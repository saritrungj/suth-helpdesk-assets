# เอกสารโดเมนสำหรับ agent

วิธีที่ agent skill (`/domain-modeling`, `/grill-with-docs`, `/improve-codebase-architecture` ฯลฯ) ควรอ่านเอกสารโดเมนของ repo นี้ก่อนเริ่มสำรวจโค้ด

## อ่านก่อนเริ่มสำรวจ

- **`CONTEXT.md`** ที่ root — **ยังไม่มี** ไฟล์นี้ในระบบตอนนี้ `/domain-modeling` (ที่เรียกผ่าน `/grill-with-docs` หรือ `/improve-codebase-architecture`) จะสร้างให้เมื่อมีเทอมที่ต้อง resolve จริง ระหว่างนี้ให้ดู `docs/explanation/domain.md` แทน — เป็นคำอธิบายกฎโดเมนหลัก (ปีงบประมาณ การคิดเงิน สิทธิ์ผู้ใช้) แต่ไม่ใช่ glossary ที่ปรับปรุงต่อเนื่องแบบ `CONTEXT.md`
- **`docs/decisions/`** — ที่เก็บ ADR ของ repo นี้ (11 ฉบับ: `0001`–`0011`) อ่าน ADR ที่เกี่ยวกับส่วนที่กำลังจะแก้ก่อนเสมอ **ไม่ใช่** `docs/adr/` — repo นี้ไม่มีโฟลเดอร์นั้น ใช้ `docs/decisions/` แทนที่เดิมทั้งหมด
- **`docs/README.md`** — ดัชนีเอกสารแบบ Diátaxis ชี้ไปยัง `explanation/`, `how-to/`, `reference/`, `decisions/`

ถ้า `CONTEXT.md` ยังไม่มี ให้ข้ามไปเงียบๆ ไม่ต้องแจ้งว่าไม่มี และไม่ต้องเสนอให้สร้างล่วงหน้า

## โครงสร้างไฟล์ (single-context)

repo นี้เป็น npm workspace (`apps/api`, `apps/web`, `apps/mcp`, `packages/domain`) แต่กฎโดเมนและ ADR รวมอยู่ที่เดียวไม่แยกตาม package — `packages/domain` มีขึ้นมาเพื่อให้กฎธุรกิจ (ปีงบ เงิน การแสดงผลไทย) มีบ้านเดียวที่ทุกแอปใช้ร่วมกัน (ดู ADR-0004) จึงถือเป็น single-context:

```text
/
├── CONTEXT.md              ← ยังไม่ถูกสร้าง จะมาโผล่ตรงนี้เมื่อถึงเวลา
├── docs/
│   ├── decisions/           ← ADR log (เทียบเท่า docs/adr/ ของ skill นี้)
│   ├── explanation/         ← เอกสารอธิบายโดเมนและสถาปัตยกรรม
│   ├── how-to/
│   └── reference/
├── apps/
│   ├── api/
│   ├── web/
│   └── mcp/
└── packages/
    └── domain/              ← กฎธุรกิจร่วม — ดู ADR-0004
```

## ใช้คำศัพท์ตาม glossary

เมื่อ `CONTEXT.md` ถูกสร้างแล้ว ให้ใช้คำตามที่นิยามไว้เป๊ะ ห้ามเบี่ยงไปใช้คำพ้องที่ glossary จงใจเลี่ยง ระหว่างที่ยังไม่มี ให้ยึดคำที่ใช้อยู่แล้วใน `docs/explanation/domain.md` และ `packages/domain` (เช่น "ปีงบประมาณ", "สตางค์") ไม่ใช้คำอื่นแทน

ถ้าเทอมที่ต้องการยังไม่ถูกบันทึกไว้ที่ไหนเลย นั่นคือสัญญาณ — อาจเป็นเพราะกำลังคิดคำที่ระบบไม่ได้ใช้ (ควรทบทวน) หรือมีช่องว่างจริงที่ต้องบันทึกให้ `/domain-modeling`
