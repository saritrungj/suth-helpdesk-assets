# ต่อผู้ช่วย AI เข้ากับระบบผ่าน MCP

ให้ถามข้อมูลทรัพย์สินและค่าใช้จ่ายเป็นภาษาพูดได้ แทนการเปิดหลายหน้าแล้วเทียบตัวเลขเอง

**เซิร์ฟเวอร์นี้อ่านอย่างเดียว** ไม่มีเครื่องมือที่แก้ไขข้อมูลได้เลย — เหตุผลอยู่ใน
[ADR-0011](../decisions/0011-read-only-mcp-server.md)

## สิ่งที่ต้องมีก่อน

1. API ทำงานอยู่และเข้าถึงได้จากเครื่องที่จะใช้ (ดู [ตั้งค่าเครื่องพัฒนา](set-up-development.md))
2. บัญชีผู้ใช้สำหรับเครื่องมือนี้โดยเฉพาะ

## 1. สร้างบัญชีสำหรับเครื่องมือ

สร้างบัญชีแยกที่ **สิทธิ์ `viewer`** จากหน้า จัดการผู้ใช้งาน — อย่าใช้บัญชีของคน

เหตุผล: ถ้ารหัสผ่านหลุด สิ่งที่ผู้ได้ไปทำได้คืออ่านข้อมูลเท่านั้น และเวลาตรวจล็อก
ย้อนหลังจะแยกออกทันทีว่าคำขอไหนมาจากคนและคำขอไหนมาจากผู้ช่วย AI

## 2. ติดตั้ง

ติดตั้งครั้งเดียวที่รากของ repository — `apps/mcp` เป็น workspace หนึ่งใน npm
workspace เดียวกัน

```bash
npm install
```

## 3. ตั้งค่าในผู้ช่วย AI

เพิ่มรายการต่อไปนี้ในไฟล์ตั้งค่า MCP ของผู้ช่วยที่ใช้อยู่ (ชื่อไฟล์ต่างกันไปตาม
โปรแกรม — Claude Desktop ใช้ `claude_desktop_config.json`)

```json
{
  "mcpServers": {
    "suth-assets": {
      "command": "node",
      "args": ["D:/suth-helpdesk-assets/apps/mcp/index.js"],
      "env": {
        "SUTH_API_URL": "http://localhost:3000/api",
        "SUTH_API_USERNAME": "mcp-reader",
        "SUTH_API_PASSWORD": "<รหัสผ่านของบัญชีนั้น>"
      }
    }
  }
}
```

| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `SUTH_API_URL` | ที่อยู่ของ API ต้องลงท้ายด้วย `/api` | `http://localhost:3000/api` |
| `SUTH_API_USERNAME` | ชื่อบัญชีสำหรับเครื่องมือ | — |
| `SUTH_API_PASSWORD` | รหัสผ่านของบัญชีนั้น | — |
| `SUTH_API_TOKEN` | token ที่ออกไว้ล่วงหน้า ใช้แทนชื่อ/รหัสผ่านได้ | — |

`SUTH_API_TOKEN` มีไว้สำหรับกรณีที่ไม่อยากให้ไฟล์ตั้งค่ามีรหัสผ่านของบัญชีจริงอยู่
ข้อแลกเปลี่ยนคือ token มีอายุ 8 ชั่วโมงและ **ไม่ต่ออายุเอง** จึงเหมาะกับการทดสอบ
มากกว่าการเปิดค้างไว้ทั้งวัน

> **ห้ามใส่รหัสผ่านลงในไฟล์ที่อยู่ใน repository** ไฟล์ตั้งค่าของผู้ช่วย AI อยู่นอก
> repository อยู่แล้ว ให้เก็บไว้ที่นั่น (ดูข้อกำหนดใน `AGENTS.md`)

## 4. ตรวจว่าใช้ได้

ปิดแล้วเปิดผู้ช่วย AI ใหม่ แล้วลองถาม

- "ปีงบนี้ใช้งบไปเท่าไหร่แล้ว"
- "ยังมีเดือนไหนที่ยังไม่ได้กรอกยอดพิมพ์"
- "แผนกไหนพิมพ์เพิ่มขึ้นมากที่สุดในไตรมาสที่แล้ว"
- "เครื่องที่ยังไม่ผูกสัญญามีกี่เครื่อง"

## เมื่อใช้ไม่ได้

เซิร์ฟเวอร์เขียนข้อความสำหรับคนลง **stderr** เท่านั้น (stdout สงวนไว้ให้โปรโตคอล)
ดูข้อความเหล่านั้นในล็อกของผู้ช่วย AI

| ข้อความ | สาเหตุและวิธีแก้ |
|---|---|
| `ต่อ API ที่ ... ไม่ได้` | API ไม่ได้ทำงานอยู่ หรือ `SUTH_API_URL` ผิด ลองเปิด `<SUTH_API_URL>/health` ในเบราว์เซอร์ |
| `ยังไม่ได้ตั้งค่าบัญชี` | ยังไม่ได้ใส่ `SUTH_API_USERNAME` / `SUTH_API_PASSWORD` |
| `เข้าสู่ระบบไม่สำเร็จ` | ชื่อบัญชีหรือรหัสผ่านผิด — ถ้าลองผิดเกิน 10 ครั้งใน 15 นาที API จะปฏิเสธชั่วคราว |
| `SUTH_API_TOKEN ... หมดอายุแล้ว` | ออก token ใหม่ หรือเปลี่ยนไปใช้ชื่อ/รหัสผ่านแทน |

## ตรวจด้วยตัวเองโดยไม่ผ่านผู้ช่วย AI

```bash
npm test --workspace @suth/mcp
```

เทสชุดนี้เชื่อมกับเซิร์ฟเวอร์ผ่านโปรโตคอล MCP จริงแล้วเรียกเครื่องมือทีละตัว —
ถ้า API ไม่ได้ทำงานอยู่ เทสจะข้ามไปพร้อมบอกเหตุผล ไม่ใช่ล้มเหลว
