# ตรวจต้นแบบสามหน้าก่อนขยายทั้งระบบ

ใช้ตรวจ human gate [#51](https://github.com/saritrungj/suth-helpdesk-assets/issues/51)
ของ [SPEC #46](https://github.com/saritrungj/suth-helpdesk-assets/issues/46)
เกณฑ์และการแบ่งสามรอบอยู่ใน SPEC; คู่มือนี้บอกวิธีลองต้นแบบ ไม่แทนคำรับรองของเจ้าของระบบ

## เปิดต้นแบบ

ใช้ [QA แยกที่เตรียมไว้](run-qa48.md) แล้วเปิดเว็บ `http://localhost:5174`
ด้วย browser profile แยก บัญชีและวิธีรับรหัสอยู่ในคู่มือ QA ห้ามนำรหัสมาใส่หลักฐาน
ใช้ข้อมูลจำลองเท่านั้น การอนุมัติรูปลักษณ์ไม่ใช่คำสั่งแก้ข้อมูลจริงของโรงพยาบาล

| หน้า | สิ่งที่ลอง | ผลที่ต้องเห็น |
|---|---|---|
| `/assets` | ค้นหา → เรียง → เปลี่ยนหน้า → แก้ไข/ย้าย → กลับรายการ | คำค้น หน้า และบริบทเดิมอยู่; ใช้ [checklist ทะเบียน](review-asset-prototype.md) |
| `/print-transactions` | เข้าแบบ staff/admin | เปิดรายเดือน รอเดือนค้างจาก API; viewer เปิดภาพรวมแบบอ่าน |
| `/print-transactions?month=2026-09` | เปิดลิงก์ที่ระบุเดือนในปีงบ 2569 | เดือนที่ระบุไม่ถูกคำตอบ coverage ที่มาช้าเขียนทับ |
| บันทึกยอด | พิมพ์ → กาง/พับความคืบหน้าปี → เปลี่ยนโหมดแล้วกดยกเลิก | draft อยู่ครบ แถวมีทั้งข้อความและสีบอกการแก้ |
| บันทึกยอด | เรียง/เปลี่ยนหน้าแล้ววางหลายค่า | preview แสดง Serial เดิม/ใหม่ก่อนยืนยัน; ค่าที่อ่านไม่ได้ไม่เลื่อน mapping |
| บันทึกยอด | ขยายตารางเต็มจอขณะมี draft | ยังเห็นเดือน ตัวกรอง และแถบบันทึกจำนวนรายการ |
| ภาพรวมยอด → กรอกยอด | วางหลายเดือน → เลิกทำ; แก้แล้วปิด/Escape | คืนค่าก่อนวางได้ และเตือนก่อนทิ้ง draft; โหลดเดิมล้มเหลวต้อง retry ก่อนกรอก |
| `/expense` | เลือกช่วง → ค้นหา → กางสัญญา/เครื่อง → Excel | หน่วยและส่วนลดเดิมครบ export ตรงบริบทตามพฤติกรรมเดิม |
| `/expense?tab=department` และ `/by-department` | กางฝ่าย/แผนก เลือกชุดกราฟ แล้วสลับตาราง | กราฟและตารางใช้ข้อมูลเดียวกัน; ช่วงเทียบแนวโน้มไม่เปลี่ยนความหมายยอดรวมทั้งปี |
| ค่าใช้จ่ายทั้งสองแท็บ | สลับแท็บ/ออกไปหน้ารายละเอียดแล้วกลับ | คำค้น ส่วนที่กาง และตำแหน่งเลื่อนยังอยู่; โหลดตัวเลขใหม่เมื่อกลับเข้า workspace |

วันที่ย้ายเครื่องใช้วันที่เซิร์ฟเวอร์ตาม API เดิม ไม่มีช่องวันที่ให้กรอก
จึงต้องรับทราบข้อจำกัดนี้ที่ gate ไม่ถือว่าเคส validation วันที่ที่ไม่มีในระบบผ่านแล้ว

## ตรวจอัตโนมัติและภาพ

จากราก repo:

```powershell
npm run verify
$env:SUTH_EVIDENCE_FULL="1"
npm run test:e2e --workspace @suth/web -- prototype.spec.js prototype-evidence.spec.js --output=../../output/finish-issue/49/final-artifacts
```

`SUTH_EVIDENCE_FULL=1` ให้ `prototype-evidence.spec.js` ถ่ายครบ 12 แบบ ไม่ตั้งจะได้แค่ไทย-สว่างกับอังกฤษ-มืดที่ 1440×900 ซึ่งเป็นชุดที่ pre-push รันทุกครั้ง

ชุด `prototype*` intercept HTTP ด้วยข้อมูลจำลองในเบราว์เซอร์ ไม่ต่อฐานข้อมูล
ตรวจพฤติกรรม UI จึงไม่พิสูจน์ว่า MySQL บันทึกจริงหรือ API บังคับสิทธิ์จริง
การทดสอบเขียนข้อมูลต้องมีอนุมัติฐาน QA ที่ระบุชื่อและคืนค่าตาม harness ก่อนแยกตรวจ
ดู [วิธีเลือก checks](verify-changes.md) และ [ขอบเขต QA](run-qa48.md)

ภาพครอบคลุมบันทึกยอดและค่าใช้จ่ายสองแท็บ ที่ 1280×720 / 1440×900 / 1920×1080
ทั้งไทย–อังกฤษและสว่าง–มืด ภาพก่อนแก้ใช้ `SUTH_EVIDENCE_PHASE=before`
ต้องเก็บก่อนเปลี่ยน source; ห้ามรัน source หลังแก้แล้วเรียกภาพนั้นว่า before
ภาพเป็นหลักฐานให้คนเปรียบเทียบ ไม่ใช่ automated pixel regression

รอบส่งมอบรวมภาพและผลจริงไว้ใน `output/finish-issue/49/`
เปิด `gallery.html` เพื่อเทียบก่อน/หลัง และอ่าน `acceptance.md` เพื่อดูผ่าน/ล้มเหลว/ยังไม่ตรวจ
ไฟล์ output ไม่ track; ผู้ส่งมอบต้องแนบลิงก์ที่ผู้ตรวจเปิดได้จริงในรายงาน ไม่ใช่ระบุเพียงชื่อโฟลเดอร์

## รับรองที่ gate

ตรวจขนาด desktop ทั้งสาม สองภาษา สองธีม; density สามระดับตรวจหน้าตัวแทน
ลอง keyboard/focus, ข้อความยาว, zoom 200%, reduced motion และ error/retry ด้วย
บันทึกแต่ละข้อเป็น ผ่าน / ต้องแก้ / ยังไม่ตรวจ พร้อมบริบทและหลักฐาน
อ่านข้อจำกัดจากผลทดสอบ โดยเฉพาะรายการที่ skip หรือยังไม่ได้ตรวจการบันทึกจริง

ผู้ใช้ยืนยันทิศทางสามหน้าและรายการข้อแก้ที่ #51 ก่อนเริ่ม #52–57
ไม่ปิด gate จากคะแนนทดสอบ ภาพหน้าจอ หรือการอนุมัติแผนล่วงหน้า
