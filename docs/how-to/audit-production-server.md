# ตรวจเซิร์ฟเวอร์จริงเทียบ checklist

ใช้เมื่อต้องการรู้ว่า [checklist เตรียมขึ้น production](prepare-for-production.md) ข้อไหนทำบนเซิร์ฟเวอร์จริงแล้ว ผู้ตรวจคือคนที่เข้าเครื่องได้ ทำครั้งแรกตาม [#306](https://github.com/saritrungj/suth-helpdesk-assets/issues/306) และทำซ้ำก่อนส่งรุ่นที่มี migration

หน้านี้บอกวิธีตรวจเท่านั้น ข้อที่ต้องทำอยู่ใน checklist ที่เดียว

## กติกา

- **อ่านอย่างเดียว** ทุกคำสั่งในหน้านี้ไม่แก้ไฟล์ ไม่แก้ข้อมูล และไม่รีสตาร์ตอะไร ถ้าพบข้อที่ขาด ให้จดไว้ อย่าแก้ระหว่างตรวจ
- **ห้ามคัดลอกค่าความลับ** ลงผลตรวจ ตอบแค่ว่า "ตั้งแล้ว" หรือ "ยังเป็นค่าตัวอย่าง" ไม่ต้องเปิดไฟล์ `.env` ให้คนอื่นดู
- **ห้ามใส่ที่อยู่ภายใน ชื่อเครื่อง ชื่อผู้ใช้ หรือข้อมูลผู้ใช้** ลงใน GitHub Issue ผลตรวจที่มีรายละเอียดเหล่านี้เก็บในระบบของหน่วยงาน
- คำสั่งเขียนแบบที่ใช้ได้ทั้ง Windows และ Linux เท่าที่ทำได้ ถ้าเครื่องจริงใช้วิธีรันที่ต่างออกไป ให้ตอบด้วยการดูจากเครื่องมือที่ใช้อยู่ และจดวิธีที่ใช้ตรวจไว้

ตอบแต่ละข้อด้วย **ทำแล้ว**, **ยังไม่ทำ** หรือ **ไม่เกี่ยว** พร้อมวิธีที่ใช้ตรวจหนึ่งบรรทัด

## ส่วนที่ 1 — เครื่องและรุ่นที่รันอยู่

ข้อมูลส่วนนี้ใช้วาดรูปการติดตั้งจริงใน [สถาปัตยกรรม](../explanation/architecture.md) และใช้วางแผนส่งรุ่น

| # | คำถาม | วิธีตรวจ |
|---|---|---|
| 1.1 | เว็บ API และ MySQL อยู่เครื่องเดียวกันหรือแยกเครื่อง | ตอบจากที่ติดตั้งจริง ระบุเป็น "เครื่องเดียว" หรือ "แยก N เครื่อง" ไม่ต้องระบุชื่อเครื่อง |
| 1.2 | ระบบปฏิบัติการของเครื่องที่รัน API | Windows Server หรือ Linux และรุ่น |
| 1.3 | API และเว็บถูกสั่งให้รันด้วยอะไร | เช่น Windows Service, pm2, systemd, Docker หรือเปิดหน้าต่างคำสั่งค้างไว้ |
| 1.4 | เครื่องรีสตาร์ตแล้วระบบกลับมาเองไหม | ดูจากการตั้งค่าของเครื่องมือในข้อ 1.3 ไม่ต้องลองรีสตาร์ต |
| 1.5 | รุ่นของโค้ดที่รันอยู่ | ในโฟลเดอร์ที่ติดตั้ง: `git rev-parse --short HEAD` และ `git status --short` (ต้องไม่มีไฟล์ที่แก้ค้าง) |
| 1.6 | อัปเดตรุ่นด้วยวิธีใด | เช่น `git pull` บนเครื่อง คัดลอกไฟล์ หรือ image ใหม่ และใครเป็นคนทำ (ตอบเป็นบทบาท) |
| 1.7 | ผู้ใช้เข้าเว็บผ่าน HTTPS หรือ HTTP | ดูจากที่อยู่ที่ผู้ใช้เปิดจริง ตอบแค่ชนิด ไม่ต้องระบุที่อยู่ |
| 1.8 | มี reverse proxy หน้า API ไหม และกี่ชั้น | เช่น IIS, nginx — ใช้เทียบกับค่า `TRUST_PROXY_HOPS` ในข้อ 3.5 |
| 1.9 | เครื่องออกอินเทอร์เน็ตได้ไหม | มีผลต่อการติดตั้ง dependency ตาม [ADR-0003](../decisions/0003-sheetjs-from-vendor-registry.md) |

## ส่วนที่ 2 — ระบบตอบและฐานตามทันโค้ด

| # | คำถาม | วิธีตรวจ |
|---|---|---|
| 2.1 | โปรเซส API ยังตอบ | บนเครื่อง API: `curl -s -o NUL -w "%{http_code}" http://localhost:<พอร์ต>/api/health/live` (Linux ใช้ `/dev/null`) ต้องได้ `200` |
| 2.2 | API ต่อฐานข้อมูลได้ | เหมือนข้อ 2.1 แต่เรียก `/api/health` ต้องได้ `200` ถ้าได้ `503` คือต่อฐานไม่ได้ |
| 2.3 | ฐานข้อมูลตามทันโค้ดรุ่นที่รัน | API รุ่นปัจจุบันไม่เปิดถ้าฐานขาด migration ดู [วิธีรัน migration](run-migrations.md) หัวข้อ "ตรวจว่าฐานข้อมูลขาดตัวไหน" — ถ้า 2.2 ผ่านบนรุ่นที่มีการตรวจนี้ ถือว่าผ่าน |

## ส่วนที่ 3 — ความลับและการตั้งค่า

ดูค่าในไฟล์ `apps/api/.env` หรือที่เก็บ environment ของเครื่องมือในข้อ 1.3 ด้วยตัวเอง แล้วตอบโดยไม่คัดลอกค่า ความหมายของแต่ละตัวอยู่ที่ [ตัวแปร environment](../reference/environment.md)

| # | ข้อของ checklist | วิธีตรวจ |
|---|---|---|
| 3.1 | `JWT_SECRET` ไม่ใช่ค่าตัวอย่างและยาวอย่างน้อย 32 ตัวอักษร | เทียบกับ `apps/api/.env.example` ด้วยตา ตอบแค่ผ่านหรือไม่ผ่าน |
| 3.2 | ผู้ใช้และรหัส MySQL ไม่ใช่ค่าตัวอย่าง และไม่ใช่ `root` ที่ไม่มีรหัส | ดู `DB_USER` และว่า `DB_PASSWORD` มีค่า |
| 3.3 | `.env` ไม่ได้ถูก commit | ในโฟลเดอร์ที่ติดตั้ง: `git ls-files apps/api/.env apps/web/.env` ต้องไม่มีผลลัพธ์ |
| 3.4 | `NODE_ENV=production` | ดูค่าที่ API ใช้จริง ถ้าไม่ตั้ง cookie session จะไม่ถูกบังคับให้ส่งผ่าน HTTPS |
| 3.5 | `TRUST_PROXY_HOPS` ตรงกับจำนวนชั้นในข้อ 1.8 | ตั้งผิดแล้วตัวจำกัดจำนวนครั้งล็อกอินทำงานผิด |
| 3.6 | `CORS_ORIGIN` เป็นที่อยู่จริงของเว็บ ไม่ใช่ `http://localhost:5173` | ตอบแค่ว่าตรงหรือไม่ตรง |
| 3.7 | `COOKIE_SAMESITE` เหมาะกับการติดตั้ง | ถ้าเว็บกับ API อยู่คนละโดเมนต้องเป็น `none` และต้องเป็น HTTPS |
| 3.8 | เว็บถูก build ด้วย `VITE_API_BASE_URL` ที่ชี้ API จริง | เปิดเว็บแล้วดูใน Network ของเบราว์เซอร์ว่าคำขอไปที่ API จริง ไม่ใช่ `localhost` |

## ส่วนที่ 4 — บัญชี

รันด้วยบัญชีฐานข้อมูลที่อ่านได้ คำสั่งนี้ไม่แสดงรหัสผ่านหรือ hash

```sql
SELECT role, COUNT(*) AS accounts FROM users GROUP BY role;
```

| # | ข้อของ checklist | วิธีตรวจ |
|---|---|---|
| 4.1 | ไม่มีบัญชีที่ไม่ได้ตั้งเอง | เทียบจำนวนบัญชีแต่ละบทบาทกับที่หน่วยงานตั้งไว้ ฐานที่สร้างก่อน #138 อาจยังมีบัญชี `user1` |
| 4.2 | รหัสของ `admin` ถูกตั้งใหม่แล้ว | ยืนยันจากผู้ที่ตั้ง ไม่ต้องลองล็อกอินด้วยรหัสเดิม |

## ส่วนที่ 5 — backup และการกู้คืน

ส่วนนี้ต้องผ่านก่อนส่งรุ่นถัดไป ดู [ส่งรุ่นและกู้คืน](release-and-recovery.md)

| # | ข้อของ checklist | วิธีตรวจ |
|---|---|---|
| 5.1 | มี backup ฐานข้อมูลอัตโนมัติรายวัน | ดูงานที่ตั้งเวลาไว้ (Task Scheduler, cron หรือเครื่องมือ backup ของหน่วยงาน) และไฟล์ล่าสุดว่าลงวันที่เมื่อใด |
| 5.2 | backup ถูกเก็บนอกเครื่องที่รันฐานข้อมูล | ตอบว่าเก็บที่เดียวกันหรือแยก ไม่ต้องระบุที่อยู่ |
| 5.3 | เคยกู้คืนจาก backup สำเร็จอย่างน้อยหนึ่งครั้ง | ถ้าไม่เคย ตอบ "ยังไม่ทำ" — backup ที่ไม่เคยลองกู้คืนถือว่ายังไม่มี |
| 5.4 | มีวิธีทดสอบ migration กับสำเนาของฐานจริง | มีเครื่องหรือฐานแยกสำหรับลองหรือไม่ |

## ส่วนที่ 6 — ข้อมูล

รันด้วยบัญชีฐานข้อมูลที่อ่านได้ ทั้งสองคำสั่งต้องได้ `0`

```sql
SELECT COUNT(*) AS months_not_ce FROM print_transactions WHERE month NOT REGEXP '^20[0-9]{2}-(0[1-9]|1[0-2])$';
SELECT COUNT(*) AS fiscal_not_ce FROM fiscal_year WHERE start_month NOT REGEXP '^20[0-9]{2}-' OR end_month NOT REGEXP '^20[0-9]{2}-';
```

| # | ข้อของ checklist | วิธีตรวจ |
|---|---|---|
| 6.1 | เดือนในฐานข้อมูลเป็น ค.ศ. ทั้งหมด | ผลของสองคำสั่งข้างบน ดู [ADR-0002](../decisions/0002-store-months-in-common-era.md) |
| 6.2 | ไฟล์นำเข้าถูกตรวจก่อนโหลด | ยืนยันจากผู้ดูแลที่นำเข้า ดู [นำเข้าไฟล์](import-files.md) |

## ส่วนที่ 7 — คนและเหตุขัดข้อง

| # | ข้อของ checklist | วิธีตรวจ |
|---|---|---|
| 7.1 | มีผู้รับเหตุเมื่อระบบล่ม และผู้ใช้รู้ช่องทางติดต่อ | ตอบเป็นบทบาท ไม่ต้องระบุชื่อใน Issue |
| 7.2 | มีที่เก็บบันทึกการส่งรุ่นและเหตุขัดข้อง | อยู่ในระบบของหน่วยงานหรือยังไม่มี |
| 7.3 | มีคนสำรองที่เข้าเครื่องได้เมื่อคนหลักไม่อยู่ | มีหรือไม่มี |

## หลังตรวจ

1. สรุปผลเป็นตารางเลขข้อกับคำตอบลงใน Issue ที่ติดตามงาน โดยไม่มีค่าความลับหรือที่อยู่ภายใน
2. ข้อที่ตอบ "ยังไม่ทำ" คือขอบเขตของงานปิด checklist โดยส่วนที่ 5 ทำก่อนข้ออื่น
3. คำตอบของส่วนที่ 1 ใช้เพิ่มรูปการติดตั้งจริงในเอกสารสถาปัตยกรรม
4. ถ้าวิธีตรวจข้อใดใช้กับเครื่องจริงไม่ได้ ให้แก้หน้านี้ในรอบเดียวกัน
