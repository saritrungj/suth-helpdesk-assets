# นำเข้าไฟล์ Excel/CSV

ใช้เมื่อได้ไฟล์ทะเบียนเครื่องหรือไฟล์ยอดมิเตอร์มาจากฝ่ายชีท

ต้องล็อกอินด้วย role `admin` ระบบรับ `.xlsx`, `.xls`, `.csv` และจำกัดขนาด 5 MB

## 1. ตรวจไฟล์ก่อนอัปโหลด

ทุกครั้ง ไม่มีข้อยกเว้น

- header ตรงกับที่ระบบอ่าน ดู [รูปแบบไฟล์นำเข้า](../reference/import-format.md)
- encoding อ่านภาษาไทยออก ไม่เป็นตัวยึกยือ
- ไม่มีข้อมูลส่วนบุคคลที่ไม่เกี่ยวข้องติดมา
- ค่าตัวเลขเป็นตัวเลขจริง ไม่ใช่ข้อความที่มีเครื่องหมายจุลภาค

## 2. เริ่มงานนำเข้า

ไปที่ **นำเข้าไฟล์จากผู้ให้เช่า** ในเมนู (`/admin/import` — แท็บนำเข้าของหน้าเพิ่มเครื่องและไอคอนนำเข้าในหน้าบันทึกยอดพิมพ์รายเดือนพามาที่เดียวกัน) แล้วอัปโหลดไฟล์ของผู้ให้เช่าได้ตรงๆ ไม่ต้องแปลงเป็นเทมเพลต รายงานมิเตอร์ให้ทั้งเครื่องและยอดในครั้งเดียว รายงานสถานะเครื่องเติมอาคารและหน่วยงาน รูปแบบที่รับอยู่ที่ [รูปแบบไฟล์นำเข้า](../reference/import-format.md)

ทุกไฟล์เป็น **งานนำเข้า** หนึ่งงาน เก็บไว้ที่เซิร์ฟเวอร์ ([ADR-0027](../decisions/0027-import-session-lifecycle.md)) — ปิดหน้า ออกจากระบบ หรือให้ผู้ดูแลคนอื่นทำต่อได้จากรายการงานที่ยังไม่เสร็จ ไม่ต้องอัปโหลดใหม่ ผู้ดูแลทุกคนเห็นทุกงาน พร้อมเจ้าของ เวลาที่สร้าง และใช้ล่าสุด ([ADR-0029](../decisions/0029-import-session-visibility.md)) งานที่ไม่มีใครแตะ 14 วันจะหมดอายุ ประวัติยังอยู่ — งานที่ยกเลิกหรือหมดอายุและไม่เคยบันทึก ลบทิ้งถาวรได้ที่ปุ่ม **ลบถาวร** ในหน้างาน ([ADR-0031](../decisions/0031-purge-unsaved-import-sessions.md))

## 3. ให้ระบบทำให้ (ค่าเริ่มต้น)

ช่อง **สร้างข้อมูลที่ขาดและบันทึกให้เลยเมื่อไม่มีอะไรต้องถาม** ใต้ช่องอัปโหลดเปิดไว้เป็นค่าเริ่มต้น ระบบจะ:

- สร้างยี่ห้อ อาคาร ฝ่าย ตามชื่อในไฟล์ (ชื่อที่ต่างกันแค่เว้นวรรคหรือคำนำหน้ารวมเป็นรายการเดียว)
- เลือกหมวดมิเตอร์ของรุ่นที่อยู่ในแคตตาล็อกรุ่น (`apps/api/src/import/model-catalog.js`)
- สร้างสัญญาจากหัวรายงานและราคาต่อหน้าในไฟล์ และสร้างปีงบที่ขาด
- บันทึกทันทีถ้าไม่เหลืออะไรต้องถาม แล้วแสดงหน้าผลลัพธ์พร้อมรายการสิ่งที่ระบบสร้างให้

ระบบหยุดให้คุณตัดสินเมื่อชื่อในไฟล์คล้ายชื่อที่มีอยู่ รุ่นไม่อยู่ในแคตตาล็อก ไฟล์จะเขียนทับยอดเดิม ตัวเลขสัญญาในระบบต่างจากไฟล์
ยอดตามใบแจ้งหนี้ไม่ตรงท้ายรายงาน หรือเลขซีเรียลคล้ายเครื่องอื่น — หน้างานบอกเหตุผลที่หยุด ทำข้อที่เหลือตามหัวข้อถัดไป
กฎทั้งหมดอยู่ใน [ADR-0030](../decisions/0030-automatic-import.md)

พบรุ่นใหม่ที่ตรวจสเปกแล้ว เพิ่มบรรทัดใน `model-catalog.js` พร้อมเทสใน `auto-resolve.test.js`

## 4. ทำตามรายการที่ต้องทำ (ปิดช่องอัตโนมัติ หรือระบบหยุดถาม)

หน้าของงานบอกทีละข้อว่ายังขาดอะไร ข้อที่ยังไม่เสร็จทำให้บันทึกไม่ได้:

1. **สัญญา** — ถ้ายังไม่มี ระบบกรอกให้จากไฟล์ (เลขที่ วันเริ่ม–สิ้นสุดจากหัวรายงานหรืองวดที่ n/36 ค่าเช่า VAT) ตรวจแล้วกด **สร้างสัญญา** ถ้าค่าเช่าหรือ VAT ในไฟล์ไม่ตรงกับสัญญาที่มีอยู่ ต้องยืนยันพร้อมเหตุผลก่อน
2. **ปีงบ** — ถ้ายอดตกในปีงบที่ยังไม่มี กดสร้างจากหน้านี้ได้
3. **ชื่อที่ไม่รู้จัก** — ยี่ห้อ อาคาร ฝ่าย → **สร้างใหม่** (แก้เป็นชื่อทางการได้) หรือ **ชื่อเรียกอื่นของ…** รายการเดิม ระบบจำไว้ ไฟล์ครั้งหน้าไม่ต้องเลือกซ้ำ และหมวดมิเตอร์ของรุ่นใหม่ ต้องสร้างสัญญาก่อน ระบบจึงรู้รุ่นที่ต้องลงราคา
4. **ยอดที่จะเขียนทับ** — ตารางค่าเดิม/ค่าใหม่ แสดง 10 แถวแรก กด **แสดงทั้งหมด** เพื่อดูครบ

ทุกการเลือกบันทึกเองทันที แล้วระบบตรวจไฟล์ใหม่ ขั้นตรวจไม่เขียนอะไรลงฐานข้อมูล

เมื่อไม่มีข้อค้าง กด **บันทึก** เครื่องและยอดทั้งไฟล์บันทึกพร้อมกันหรือไม่บันทึกเลย ([ADR-0028](../decisions/0028-import-commit-strategy.md)) ถ้ามีคนแก้ข้อมูลที่เกี่ยวข้องระหว่างนั้น ระบบไม่เขียนทับเงียบๆ แต่ให้ตรวจใหม่ก่อน

นำเข้าไฟล์เดิมซ้ำได้ เครื่องที่มีแล้วไม่ถูกสร้างซ้ำ ระบบเติมเฉพาะช่องที่ยังว่าง ไม่ย้ายเครื่อง ยอดเดิมที่ค่าเท่ากันนับเป็น "ไม่เปลี่ยน"

> ช่องที่เว้นว่างแปลว่า **ไม่เปลี่ยนข้อมูลเดิม** ส่วน `0` เป็นค่าจริงที่แปลว่าเดือนนั้นไม่มีการพิมพ์ สองอย่างนี้ไม่เหมือนกัน

> ระบบอ่านเดือนจาก **ชื่อคอลัมน์** (เช่น `meter 9/67`) ไม่ใช่จากตำแหน่งคอลัมน์ เพราะไฟล์ต้นฉบับเรียงเดือนเริ่มจากกันยายน ไม่ใช่ตุลาคมแบบปีงบ

ไฟล์ตัวอย่าง (ปุ่ม **ไฟล์ตัวอย่าง**) มีไว้สำหรับเครื่องที่ไม่มีไฟล์ของผู้ให้เช่า เทมเพลตยอดใช้หัวคอลัมน์ของสามเดือนล่าสุด ต้องเปลี่ยนเป็นเดือนที่จะนำเข้าจริง

## 5. ตรวจผลหลังนำเข้า

หน้างานที่เสร็จแล้วแสดงจำนวนเครื่องและยอดที่บันทึก การกระทบยอดกับยอดรวมท้ายรายงาน (ต่างได้ไม่เกิน 0.01 บาทต่องวด — ผู้ให้เช่าปัดเศษ VAT) ประวัติว่าใครทำอะไรเมื่อไร และลิงก์ดาวน์โหลดไฟล์ต้นฉบับ เครื่องและยอดที่มาจากงานนี้เก็บเลขงานไว้ ถ้ามีคนแก้ยอดด้วยมือภายหลัง ความเชื่อมโยงนั้นหายไป

จากนั้นเปิดหน้าค่าใช้จ่ายตรวจว่ายอดขึ้นในปีงบที่ถูกต้อง

ไฟล์จริงเก็บนอก repo (เช่น `D:\suth-data\raw\`) เพราะ repo เป็น public และไฟล์มีข้อมูลของหน่วยงาน

ถ้าแก้โค้ด importer หรือ mapping ต้อง smoke-test ครบสี่กรณี: ไฟล์ที่ผ่าน, ไฟล์ที่ถูกปฏิเสธ (ต้องไม่เขียนอะไรลงฐานเลย), การนำเข้าไฟล์เดิมซ้ำ (ต้อง update ไม่ใช่เพิ่มแถวใหม่) และการกดบันทึกหลังมีคนแก้ยอดเดือนเดียวกันไปแล้ว (ต้องให้ตรวจใหม่ ไม่ใช่เขียนทับเงียบๆ) `e2e/import-session.spec.js` ครอบคลุมทั้งหมดด้วยไฟล์สังเคราะห์ ส่วนไฟล์จริงรันด้วย spec แบบ manual ซึ่งอ่านไฟล์จากนอก repo (รันใน `apps/web` โดยมี API และเว็บชี้ไปที่ฐานข้อมูลทิ้งได้ เหมือนชุด `test:e2e:db`):

```bash
SUTH_REAL_FILES_DIR=D:/suth-data/raw npx playwright test --project=manual e2e/import-real-files.spec.js
```

ต้องรันกับฐานข้อมูลทิ้งได้เท่านั้น ห้ามรันกับฐานจริง
