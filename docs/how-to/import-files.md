# นำเข้าไฟล์ Excel/CSV

ใช้เมื่อได้ไฟล์ทะเบียนเครื่องหรือไฟล์ยอดมิเตอร์มาจากฝ่ายชีท

ต้องล็อกอินด้วย role `admin` ระบบรับ `.xlsx`, `.xls`, `.csv` และจำกัดขนาด 5 MB

## 1. ตรวจไฟล์ก่อนอัปโหลด

ทุกครั้ง ไม่มีข้อยกเว้น

- header ตรงกับที่ระบบอ่าน ดู [รูปแบบไฟล์นำเข้า](../reference/import-format.md)
- encoding อ่านภาษาไทยออก ไม่เป็นตัวยึกยือ
- ไม่มีข้อมูลส่วนบุคคลที่ไม่เกี่ยวข้องติดมา
- ค่าตัวเลขเป็นตัวเลขจริง ไม่ใช่ข้อความที่มีเครื่องหมายจุลภาค

## 2. นำเข้าทะเบียนเครื่อง

ไปที่ **ทะเบียนเครื่องพิมพ์ → เพิ่มเครื่อง → นำเข้าจากไฟล์** แล้วอัปโหลดไฟล์ของผู้ให้เช่าได้ตรงๆ ไม่ต้องแปลงเป็นเทมเพลต (รายงานสถานะเครื่องหลายแผ่น หรือรายงานมิเตอร์) รูปแบบที่รับอยู่ที่ [รูปแบบไฟล์นำเข้า](../reference/import-format.md#ทะเบียนอุปกรณ์)

1. สร้างสัญญาของไฟล์ที่หน้าสัญญาก่อน ถ้ายังไม่มี — ระบบบอกเลขที่สัญญาที่ขาด
2. กด **ตรวจไฟล์** ระบบบอกว่าจะสร้าง เติม ข้ามกี่เครื่อง และถามเฉพาะสิ่งที่เดาแทนไม่ได้:
   - ชื่อยี่ห้อ อาคาร ฝ่าย ที่ยังไม่รู้จัก → **สร้างใหม่** (แก้เป็นชื่อทางการได้) หรือ **ชื่อเรียกอื่นของ…** รายการเดิม ระบบจำไว้ ไฟล์ครั้งหน้าไม่ต้องเลือกซ้ำ
   - หมวดมิเตอร์ของรุ่นที่ยังไม่เคยลง และมีมิเตอร์สีหรือไม่
3. ทุกครั้งที่เลือก หน้าตรวจไฟล์ใหม่เอง ตรวจคำเตือน (โดยเฉพาะเลขซีเรียลที่คล้ายเครื่องที่มีอยู่) แล้วกด **บันทึก**

นำเข้าไฟล์เดิมซ้ำได้ เครื่องที่มีแล้วไม่ถูกสร้างซ้ำ ระบบเติมเฉพาะช่องที่ยังว่าง ไม่ย้ายเครื่อง — ใช้เติมอาคารและฝ่ายให้เครื่องที่ลงจากรายงานมิเตอร์ (ซึ่งไม่มีสองช่องนี้) ได้

ลำดับที่แนะนำสำหรับสัญญาใหม่: สัญญา → ทะเบียน (หรือรายงานมิเตอร์ ถ้าไม่มีไฟล์ทะเบียน) → [ยอดมิเตอร์](#3-นำเข้ายอดมิเตอร์)

## 3. นำเข้ายอดมิเตอร์

ไฟล์ยอดมิเตอร์เป็นไฟล์ต้นฉบับที่ฝ่ายชีทส่งมา ไฟล์จริงเก็บนอก repo (เช่น `D:\suth-data\raw\`) เพราะ repo เป็น public และไฟล์มีข้อมูลของหน่วยงาน

เปิดจากไอคอนนำเข้าในแถวตัวกรองของหน้า **บันทึกยอดพิมพ์รายเดือน** — ไอคอนนี้ขึ้นเฉพาะ role `admin`

ระบบจะ:

1. หาคอลัมน์ที่ชื่อขึ้นต้นด้วย `meter` ตามด้วยเดือน/ปี เช่น `meter 9/67`
2. จับคู่เครื่องด้วยเลข Serial Number
3. แปลงเดือนจาก พ.ศ. เป็น ค.ศ. ก่อนบันทึก

การนำเข้าแยกเป็นสองขั้นเสมอ — กด **ตรวจไฟล์** ก่อน ระบบยังไม่เขียนอะไรลงฐานข้อมูลในขั้นนี้ แล้วจึงกด **ยืนยันบันทึก**

หน้าตรวจบอกเดือนที่พบในไฟล์และสามจำนวน: รายการใหม่ รายการที่จะเขียนทับข้อมูลเดิม และรายการที่ค่าเดิมอยู่แล้วไม่เปลี่ยน ตารางค่าเดิม/ค่าใหม่ของรายการที่จะถูกเขียนทับแสดง 10 แถวแรก กด **แสดงทั้งหมด** เพื่อดูครบในหน้าเดียวกัน หรือดาวน์โหลดรายการทั้งหมดเป็น CSV ก่อนยืนยัน ไฟล์ตัวอย่างใช้หัวคอลัมน์ของสามเดือนล่าสุด ต้องเปลี่ยนเป็นเดือนที่จะนำเข้าจริง

ถ้าไฟล์มีข้อผิดพลาด **ทั้งไฟล์จะไม่ถูกบันทึกเลยสักแถว** ไม่ใช่ข้ามเฉพาะแถวที่ผิด รายการที่ต้องแก้ดาวน์โหลดเป็น CSV ได้จากหน้าตรวจ กฎที่ใช้ตรวจอยู่ใน [รูปแบบไฟล์นำเข้า](../reference/import-format.md)

> ช่องที่เว้นว่างแปลว่า **ไม่เปลี่ยนข้อมูลเดิม** ส่วน `0` เป็นค่าจริงที่แปลว่าเดือนนั้นไม่มีการพิมพ์ สองอย่างนี้ไม่เหมือนกัน

> ระบบอ่านเดือนจาก **ชื่อคอลัมน์** ไม่ใช่จากตำแหน่งคอลัมน์ เพราะไฟล์ต้นฉบับเรียงเดือนเริ่มจากกันยายน ไม่ใช่ตุลาคมแบบปีงบ ถ้า map ตามตำแหน่งยอดจะเลื่อนไปทั้งแถว

## 4. ตรวจผลหลังนำเข้า

ทะเบียนเครื่องรายงานเป็นรายแถว ส่วนยอดมิเตอร์เป็นทั้งไฟล์ — สำเร็จคือบันทึกครบทุกแถว ไม่มีสภาพ "สำเร็จบางส่วน"

จากนั้นเปิดหน้าค่าใช้จ่ายตรวจว่ายอดขึ้นในปีงบที่ถูกต้อง

ถ้าแก้โค้ด importer หรือ mapping ต้อง smoke-test ครบสี่กรณี: ไฟล์ที่ผ่าน, ไฟล์ที่ถูกปฏิเสธ (ต้องไม่เขียนอะไรลงฐานเลย), การนำเข้าไฟล์เดิมซ้ำ (ต้อง update ไม่ใช่เพิ่มแถวใหม่) และการกดยืนยันหลังมีคนแก้ยอดเดือนเดียวกันไปแล้ว (ต้องให้ตรวจไฟล์ใหม่ ไม่ใช่เขียนทับเงียบๆ)
