# วัดความเร็วที่ผู้ใช้จริงรู้สึก (Core Web Vitals)

เว็บ (build ที่ใช้งานจริง) วัด [Core Web Vitals](https://web.dev/articles/vitals) จากเบราว์เซอร์ของผู้ใช้ด้วยไลบรารี
[web-vitals](https://github.com/GoogleChrome/web-vitals) ของ Google แล้วส่งเข้า log ของ API — ตัวเลขนี้ต่างจากที่วัดบน
เครื่องนักพัฒนา เพราะรวมเครือข่ายและเครื่องของผู้ใช้จริงแล้ว (#171)

## ดูผล

```powershell
node scripts/web-vitals-report.cjs <ไฟล์ log ของ API>
```

ตัวอย่างบนเครื่องที่ deploy: `node scripts/web-vitals-report.cjs D:\suth-data\logs\prod\api.out.log`

ผลเรียงรายหน้า (รูปแบบ route เช่น `/assets/:id`) แต่ละค่าบอก p75, เกณฑ์, ผ่านหรือไม่, จำนวนครั้ง, สัดส่วน
ดี/พอใช้/แย่ และ **element ที่เป็นต้นเหตุบ่อยที่สุด** ของครั้งที่ไม่ดี

| ค่า | วัดอะไร | ดี (p75) |
|---|---|---|
| **LCP** | เนื้อหาหลักขึ้นเร็วแค่ไหน | ≤ 2,500 ms |
| **INP** | กดแล้วหน้าตอบสนองเร็วแค่ไหน — อาการ "เอ๋อ" | ≤ 200 ms |
| **CLS** | หน้ากระตุก/เลื่อนเองแค่ไหน | ≤ 0.1 |
| FCP | เห็นอะไรบนจอครั้งแรก | ≤ 1,800 ms |
| TTFB | เซิร์ฟเวอร์ตอบครั้งแรก | ≤ 800 ms |

p75 = 75% ของการใช้งานได้ค่านี้หรือดีกว่า ตามวิธีของ Google — ค่าเฉลี่ยซ่อนคนที่ช้าจริงไว้

## อ่านผลแล้วแก้ตรงไหน

- **INP ไม่ผ่าน** — ดู element ต้นเหตุ แล้วเปิดหน้านั้นใน Chrome DevTools แท็บ Performance กดซ้ำ ใน log มีเวลาสามช่วง:
  `inputDelay` สูง = มีงานอื่นค้างอยู่ก่อนกด, `processingDuration` สูง = โค้ดที่ทำงานตอนกดหนัก,
  `presentationDelay` สูง = วาดหน้าใหม่มาก (เช่นตารางยาว — พิจารณา virtualization)
- **LCP ไม่ผ่าน** — ดูว่า element หลักรอข้อมูลจาก API (ดู `duration_ms` ของคำขอใน log เดียวกัน) หรือรอ JS
- **CLS ไม่ผ่าน** — element ต้นเหตุมักเป็นส่วนที่ขึ้นทีหลังโดยไม่จองพื้นที่ไว้ (ใช้ skeleton ขนาดเท่าของจริง)

## เก็บอะไรบ้าง

- ชื่อค่า ค่า ระดับ (ดี/พอใช้/แย่) รูปแบบ route ของหน้า และตัวเลือก CSS ของ element ต้นเหตุ
- **ไม่เก็บ** ตัวตนผู้ใช้ URL จริง หรือ query string และไม่เขียนฐานข้อมูล
- ไม่วัดจากเบราว์เซอร์อัตโนมัติ (`navigator.webdriver`) — เทส E2E และ bot ไม่ปนกับค่าของคนจริง
- ปลายทาง `POST /api/metrics/web-vitals` ไม่ต้องล็อกอิน (หน้าเข้าสู่ระบบก็วัด) จึงรับเฉพาะรูปแบบแคบ ≤ 8 KB
  ชุดละไม่เกิน 20 ค่า และอยู่ใต้ rate limit ของ `/api` เหมือนคำขออื่น

ค่าถูกส่งตอนสลับแท็บหรือปิดหน้า (`navigator.sendBeacon`) — เปิดหน้าค้างไว้จะยังไม่เห็นใน log
