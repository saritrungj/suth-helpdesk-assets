# 0020 — หน้าภาพรวมมีตัวกรองชั้นเดียว และเป็นหน้าวิเคราะห์หน้าเดียวของระบบ

**สถานะ:** Accepted — ผู้ใช้ปฏิเสธแบบสองชั้นแล้วยืนยันแบบชั้นเดียว (#126) · ส่วน "หน้าวิเคราะห์หน้าเดียว" ถูกแก้โดย [ADR-0033](0033-overview-and-compare-pages.md) — หน้าเปรียบเทียบกลับมาเป็นมุมมองที่สองของแถวชุดเดียวกัน ตัวกรองชั้นเดียวยังใช้อยู่

## ปัญหา

หน้าวิเคราะห์ของระบบเคยมีสามหน้า — ภาพรวม (`/dashboard`), เปรียบเทียบ (`/compare`) และค่าใช้จ่ายแยกฝ่าย/แผนก (`/by-department`) — ที่แสดงตัวเลขชุดเดียวกันด้วยตัวเลือกคนละชุด ผู้ใช้ต้องจำเองว่าตัวเลขบนหน้าไหนใช้ขอบเขตใด

รอบแก้ก่อนหน้านี้ยุบสามหน้าเข้าหน้าเดียวได้ แต่ยก "ตัวเลือกของหน้าเปรียบเทียบ" มาวางบนหน้าภาพรวมทั้งชุด แล้วเพิ่มตัวกรองขอบเขตอีกชั้นหนึ่งข้างบน ผลคือ **ชื่อมิติเดียวกันโผล่สองที่ในหน้าเดียว**

- แถบบน: "ฝ่าย" = จำกัดข้อมูลที่ทั้งหน้าใช้
- พื้นที่เปรียบเทียบ: "แยกข้อมูลตาม: ฝ่าย" + "ฝ่ายที่เลือก" = เลือกเส้นในกราฟ

สองอย่างนี้ชื่อเหมือนกันแต่ผลต่างกัน และต้องมีกฎพิเศษเขียนกำกับว่า "การเลือกในกราฟต้องไม่เปลี่ยนตัวเลขบนการ์ด" ซึ่งเป็นสัญญาณว่าแบบจำลองในหัวผู้ใช้ไม่ตรงกับแบบจำลองในโค้ด ผู้ใช้ปฏิเสธรอบนี้ด้วยคำว่า "ทำไมทำให้มันรกกว่าเดิม"

## การตัดสินใจ

หน้าภาพรวมมีตัวเลือกสองชนิด และ **ชนิดที่เลือกข้อมูลมีชั้นเดียว**

| ชนิด | ตัวเลือก | หน้าที่ |
|---|---|---|
| ตัวกรอง | ปีงบ ช่วงเวลา ฝ่าย แผนก สัญญา อาคาร เครื่อง | เลือกว่าจะดูข้อมูลชุดไหน — ทุกตัวเลือกหลายค่าได้ |
| เปรียบเทียบตาม | ภาพรวม ฝ่าย แผนก สัญญา อาคาร เครื่อง ปีงบ | แบ่งข้อมูลชุดนั้นเป็นเส้น/แท่งอะไร — ไม่เพิ่มและไม่ลดข้อมูล |

ผลที่ตามมาโดยอัตโนมัติ ไม่ต้องเขียนเป็นกฎเพิ่ม

- ตัวเลขสำคัญ กราฟ ตาราง แผงรายละเอียด Excel และ CSV อ่านจากแถวชุดเดียวกันเสมอ
- "การเลือกในกราฟต้องไม่เปลี่ยนตัวเลขสำคัญ" เป็นจริงเพราะ **ไม่มีการเลือกในกราฟแล้ว**
- ปีงบเป็นตัวกรองเหมือนช่วงเวลา เลือกหลายปีเพื่อเทียบได้ โดยปีที่ใหม่ที่สุดที่เลือกคือปีงบหลักของทั้งแอป — ไม่มีปีงบสองความหมายในหน้าเดียว
- `/compare` และ `/by-department` เหลือเป็น redirect ที่แปลง query เดิมเป็นตัวกรองของหน้านี้ ไฟล์ของสองหน้านั้นถูกลบ

## ทางเลือกที่ตัดทิ้ง

**คงตัวกรองสองชั้นไว้แล้วเปลี่ยนแค่ชื่อป้าย** (เช่น "แยกข้อมูลตาม" → "เปรียบเทียบ") — ตัดทิ้งเพราะไม่แก้ต้นเหตุ ผู้ใช้ยังต้องเดาว่าตัวไหนคุมอะไร แค่เดาด้วยคำที่สวยขึ้น

**ให้กราฟแสดงทุกกลุ่มในขอบเขตเสมอ** — ตัดทิ้งเพราะมิติ "เครื่อง" มีหลักร้อยกลุ่ม ชุดสีของกราฟแยกออกได้แปดสี เส้นที่เกินนั้นอ่านไม่ได้จริง จึงวาดแปดกลุ่มที่ยอดสูงสุดแล้ว **เขียนบอกบนหน้าว่าแสดงกี่จากกี่รายการ** ส่วนตารางและไฟล์มีครบทุกกลุ่ม — ต่างจากของเดิมที่ระบบเลือก 5 รายการให้เงียบๆ

**แยกตารางของทุกมิติมาวางพร้อมกันบนหน้าเดียว** (ฝ่าย + แผนก + สัญญา + อาคาร + เครื่อง) — ตัดทิ้งเพราะกลายเป็นหน้ายาวหลายพันพิกเซลที่หาอะไรไม่เจอ ซึ่งคือปัญหาเดิมในรูปแบบใหม่ ใช้ตารางเดียวที่เปลี่ยนตาม "เปรียบเทียบตาม" แทน โดยตารางนั้นค้นหา เรียง และแบ่งหน้าได้

**เก็บเดือนที่เลือกเป็นตำแหน่งในปีงบ (P01–P12)** เพื่อให้ข้ามปีงบได้ตรงๆ — ตัดทิ้งเพราะทำให้ลิงก์ที่แชร์ออกไปเปลี่ยนความหมายตามปีงบของคนเปิด เก็บเป็นเดือนจริงของปีงบหลักเหมือนเดิม แล้วขยายไปยังปีอื่นตามตำแหน่งเดือนตอนสร้างคำขอ

## สิ่งที่ยังเป็นข้อจำกัด

- ตัวกรองทำงานฝั่งเว็บบนแถวที่ `/dashboard/monthly-kpi` ส่งมาทั้งช่วง ไม่ได้ส่งตัวกรองไปให้ SQL — พอสำหรับปริมาณข้อมูลปัจจุบัน แต่ถ้าจำนวนเครื่องหรือจำนวนปีที่ดูพร้อมกันโตขึ้นมาก ต้องย้ายการกรองลงไปที่ API
- เลือกได้ครั้งละไม่เกินสามปีงบ เพราะเกินกว่านั้นทั้งกราฟและขนาดคำขออ่านไม่ไหว
- เปอร์เซ็นต์เทียบช่วงก่อนหน้าแสดงเฉพาะตอนเลือกปีงบเดียว เพราะ "ช่วงก่อนหน้า" ของหลายปีงบพร้อมกันไม่มีคำตอบเดียว
- การเทียบส่วนต่างแบบ A/B ของหน้า `/compare` เดิม (เลือกรายการฐานแล้วดูส่วนต่างกับรายการอื่น และเทียบช่วง A กับช่วง B) **ถูกถอดออกพร้อมหน้านั้น** ยังไม่มีที่แทนบนหน้าใหม่ ถ้าต้องใช้อีกให้ออกแบบใหม่บนโครงชั้นเดียวนี้
- ตัวกรอง **ชั้น** (`?floor=` ของหน้า `/compare` เดิม) ไม่มีบนหน้าใหม่ จึงไม่ถูกแปลงตอน redirect — อาคารเป็นระดับที่หยาบที่สุดของสถานที่บนหน้านี้ ลิงก์เก่าที่ระบุชั้นจึงเปิดได้ด้วยขอบเขตระดับอาคาร ถ้าต้องการชั้นอีกให้เพิ่มเป็นตัวกรองชุดเดียวกันนี้
