# 0021 — ราคาในสัญญาใช้คิดเงินทันทีที่บันทึก ไม่มีขั้นยืนยันราคา

**สถานะ:** Accepted — ผู้ใช้ยืนยันเมื่อ 2026-09-21 หลังเห็นข้อมูลจริงของสัญญา SUTH192/2568; แทนที่ส่วน "ยืนยันราคา" และ Q27/Q29/Q30 ของ [ADR-0019](0019-effective-pricing-history.md)

## บริบท

ADR-0019 ให้ราคาของสัญญามีผลเฉพาะเมื่อผู้ดูแลกดยืนยันพร้อมเอกสาร ก่อนนั้นค่าใช้จ่ายเป็น `NULL` และแสดงว่า "ยังยืนยันราคาไม่ได้" ซึ่งบนหน้าภาพรวมย่อเป็น "รอราคา N"

ผู้ใช้งานจริงอ่านคำนี้ไม่ออก ("รอราคา 35 คือ 35 แผ่น หรือ 35 สตางค์") และอ่านว่าระบบยังทำงานไม่เสร็จ ทั้งที่ราคาต่อหน้ากำหนดในสัญญาตั้งแต่วันเซ็น กรอกมิเตอร์แล้วต้องได้ยอดเงินทันที ข้อมูลจริงยังแสดงว่าขั้นยืนยันเองเป็นแหล่งของยอดหาย: การแก้สัญญาราคา 0.40 เพื่อเปลี่ยนแค่เลขที่สัญญาทำให้สถานะยืนยันถูกล้าง เพราะโค้ดเทียบ `"0.40"` กับ `"0.4"` เป็นข้อความ

## การตัดสินใจ

- ราคาในรายการราคาของสัญญามีผลทันทีที่บันทึก ตลอดอายุสัญญา ไม่มีสถานะ "ยืนยันแล้ว/ยังไม่ยืนยัน"
- สถานะ "ไม่มีราคา" เกิดได้เฉพาะข้อมูลผิดจริง (มิเตอร์ไม่ผูกรายการราคา หรืองวดอยู่นอกอายุสัญญา) และ**กันไว้ที่ขาเข้า** — การบันทึกยอดและการนำเข้าปฏิเสธรายการที่หาราคาไม่ได้พร้อมบอกเหตุผล หน้าภาพรวมจึงไม่มีสถานะรอ
- กันราคาผิดด้วยการแสดงผลกระทบก่อนบันทึก: แก้ราคาของสัญญาที่มียอดแล้วต้องเห็น "ยอดงวด X–Y จะเปลี่ยนจาก A เป็น B บาท" แล้วกดยืนยัน
- เก็บ `device_contract_history` ไว้ตามเดิม เพราะยังตอบคำถาม "งวดนี้มิเตอร์นี้คิดเงินใต้สัญญาไหน" ที่การย้ายเครื่องและสัญญาหลายปีต้องใช้

## ทางเลือกที่ตัดทิ้ง

- **คงขั้นยืนยันแต่ซ่อนคำบนหน้าภาพรวม** — ยอดเงินจะขาดเงียบๆ ขัดกับข้อกำหนดว่าตัวเลขเงินต้องถูกทุกสตางค์
- **คงทุกอย่างแค่เปลี่ยนคำ** — ไม่แก้ต้นเหตุ ผู้ใช้ยังต้องไปกดยืนยันก่อนเห็นเงิน

## ผลที่ตามมา

การพิมพ์ราคาผิดแล้วกดยืนยันผลกระทบจะเปลี่ยนยอดย้อนหลังได้ทันที ซึ่งขั้นยืนยันเดิมมีไว้กัน — ยอมรับเพราะหน้าผลกระทบแสดงตัวเลขก่อนและหลังให้เห็นก่อนกด หน้า `/admin/contract-prices` และป้าย "รอราคา" ทุกจุดต้องถูกถอด

ด่าน "ดูผลกระทบก่อนบันทึก" อยู่ที่หน้าจัดการสัญญา — การแก้สัญญาเดิมทุกครั้งต้องกดดูผลกระทบก่อนปุ่มบันทึกจะใช้ได้ API ไม่บังคับ token ของการดูผลกระทบ เพราะผู้เรียกนอกหน้าเว็บมีเพียงสคริปต์ลงข้อมูลของผู้ดูแล และคำตอบของการบันทึกคืนผลกระทบจริงให้เสมอ ส่วนด่านที่บังคับที่ API คือการปฏิเสธการแก้ที่ทำให้ยอดเดิมหาราคาไม่ได้
