# 0038 — ออกจากระบบแล้วเพิกถอน token นั้น โดยจำไว้ในหน่วยความจำของ API

- สถานะ: Accepted
- วันที่: 2026-10-04
- Issue: #240 · ต่อจาก [ADR-0006](0006-session-cookie-instead-of-localstorage.md)

## บริบท

`POST /api/auth/logout` ลบ cookie ฝั่งเบราว์เซอร์อย่างเดียว token เดิมยังผ่าน `require-auth` ได้ทั้งทาง Cookie และ
`Authorization: Bearer` จนครบอายุ 8 ชั่วโมง token ที่ถูกคัดลอกไว้ก่อนออกจากระบบ (เครื่องที่ใช้ร่วมกัน ส่วนขยายของ
เบราว์เซอร์ log ของ proxy) จึงยังใช้ได้ ทั้งที่ผู้ใช้เข้าใจว่าออกแล้ว

ระบบตัด token ได้อยู่แล้วสองกรณี — เปลี่ยนรหัสผ่านและลบบัญชี ([current-user.js](../../apps/api/src/auth/current-user.js))
แต่ไม่มีกรณี "ผู้ใช้กดออกเอง"

## การตัดสินใจ

1. ตอน logout ถ้า token ที่ส่งมาตรวจลายเซ็นผ่าน ให้จำค่าแฮชของ token นั้นพร้อมเวลาหมดอายุ
   ([revoked-sessions.js](../../apps/api/src/auth/revoked-sessions.js)) `require-auth` ปฏิเสธ token ที่อยู่ในรายการด้วย
   401 `signed_out` ทั้งสองช่องทาง
2. **เก็บในหน่วยความจำของโปรเซส** ไม่ใช่ในฐาน รายการมีอายุเท่าอายุ token ที่เหลือและถูกเก็บกวาดเมื่อหมดอายุ
3. เพิกถอนเฉพาะ token ที่ออกจากระบบ — session อื่นของผู้ใช้คนเดียวกัน (อีกเครื่อง อีกเบราว์เซอร์) ยังใช้ได้
4. token ใหม่ทุกใบมี `jti` ไม่ซ้ำ ล็อกอินสองครั้งในวินาทีเดียวกันจึงไม่ได้ token เดียวกัน

## ทางเลือกที่ตัดทิ้ง

**เก็บเวลาที่ออกจากระบบล่าสุดต่อผู้ใช้ในตาราง `users`** — ทนต่อการเริ่ม API ใหม่ และใช้กลไกเดียวกับการเปลี่ยนรหัสผ่าน
แต่ต้องเปลี่ยน schema (migration กับทุกฐานก่อน API จะเปิดได้ ตามด่าน `schema-check.js`) และออกจากระบบหนึ่งครั้ง =
ออกทุกเครื่อง ยังไม่เลือกเพราะการเปลี่ยน schema ต้องได้รับอนุมัติแยก และความเสี่ยงที่เหลือของทางที่เลือกยอมรับได้

**ตารางรายการ token ที่ถูกเพิกถอน** — ทนต่อการเริ่มใหม่และแยก session ได้ แต่เพิ่มคำสั่งฐานข้อมูลทุกคำขอ และต้อง
เปลี่ยน schema เช่นกัน

**คงพฤติกรรมเดิม ลดอายุ token** — ไม่แก้ปัญหา แค่ลดช่วงเวลา และทำให้ผู้ใช้ถูกเด้งออกบ่อยขึ้น

## ผลที่ตามมา

- **API เริ่มใหม่แล้วรายการหาย** — token ที่ออกจากระบบไปแล้วแต่ยังไม่หมดอายุกลับมาใช้ได้จนครบ 8 ชั่วโมงของมัน
  การเริ่มใหม่เกิดตอน deploy หรือเครื่องดับ เป็นความเสี่ยงที่ยอมรับในขนาดของระบบนี้
- ใช้ได้เพราะระบบมี API โปรเซสเดียว ([ADR-0028](0028-import-commit-strategy.md) ข้อ 3) ถ้ารันหลายโปรเซส
  ต้องย้ายรายการไปเก็บในฐานหรือที่เก็บกลาง — แก้ ADR นี้ก่อน
- หน่วยความจำ: หนึ่งรายการต่อการออกจากระบบ อยู่ไม่เกิน 8 ชั่วโมง
- token ที่ออกก่อนการเปลี่ยนนี้ (ไม่มี `jti`) เพิกถอนได้เหมือนกัน เพราะรายการอ้างด้วยค่าแฮชของ token ทั้งใบ
