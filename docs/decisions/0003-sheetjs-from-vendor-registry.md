# 0003 — ติดตั้ง SheetJS จาก registry ของผู้พัฒนา ไม่ใช่ npm

**สถานะ:** Accepted

## บริบท

ระบบใช้ SheetJS (แพ็กเกจ `xlsx`) สองที่:

- **backend** — `XLSX.read()` อ่านไฟล์ Excel ที่ผู้ใช้อัปโหลดเข้ามา
- **frontend** — `XLSX.writeFile()` เขียนไฟล์ export อย่างเดียว ไม่ได้อ่านไฟล์จากภายนอก

SheetJS หยุดเผยแพร่บน npm ตั้งแต่รุ่น `0.18.5` แล้วย้ายไปแจกที่ registry ของตัวเองที่ `cdn.sheetjs.com` ผลคือรุ่นล่าสุดที่ `npm install xlsx` ให้ได้ จะค้างอยู่ที่รุ่นที่มีช่องโหว่ prototype pollution ตลอดไป และจะไม่มีวันได้รับ patch

จุดที่อันตรายจริงคือฝั่ง backend เพราะรับไฟล์จากภายนอกมา parse โดยตรง

## การตัดสินใจ

ติดตั้งจาก tarball ของ SheetJS เอง ทั้งสองแพ็กเกจ:

```
"xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"
```

API เหมือนเดิมทุกอย่าง (`XLSX.read`, `utils.aoa_to_sheet`, `writeFile`) จึงไม่ต้องแก้โค้ดเลย

## ทางเลือกที่พิจารณาแล้วไม่เลือก

**เปลี่ยนไปใช้ `exceljs`** — ดูแลอยู่บน npm ตามปกติและเป็นทางเลือกที่ดีในระยะยาว แต่ API ต่างกันมาก (async, streaming) ต้องเขียนตัวอ่านไฟล์นำเข้าใหม่ทั้งก้อน ซึ่งเป็นงานที่ควรไปอยู่กับตอนเขียนระบบใหม่ ไม่ใช่งานแก้ช่องโหว่เร่งด่วน

**อยู่ที่ `0.18.5` ต่อไป** — ระบบนี้รับไฟล์ Excel จากฝ่ายชีทเข้ามา parse โดยตรง การปล่อยตัว parser ที่มีช่องโหว่ที่รู้แล้วไว้ ไม่ใช่ทางเลือกที่ยอมรับได้

## ผลที่ตามมา

- **เครื่องที่ติดตั้งต้องออกอินเทอร์เน็ตถึง `cdn.sheetjs.com` ได้** ถ้า deploy ในเครือข่ายโรงพยาบาลที่ปิดขาออก ต้องดาวน์โหลด tarball มาเก็บไว้ในเครือข่ายเองก่อน แล้วชี้ path ไปที่ไฟล์นั้นแทน
- `npm audit` จะไม่รายงานช่องโหว่ของ `xlsx` อีก เพราะไม่ได้ดึงจาก npm registry แล้ว — แลกมาด้วยการที่ audit ก็จะไม่เตือนอะไรเกี่ยวกับแพ็กเกจนี้อีกเช่นกัน ต้องตามรุ่นใหม่จาก SheetJS เอง
- ตอนอัปรุ่นต้องแก้ URL ใน `package.json` ของทั้งสองแพ็กเกจให้ตรงกัน
