# 0005 — เลือก database engine สำหรับระบบที่เขียนใหม่

**สถานะ:** Proposed — ยังไม่ตัดสิน รอคำตอบจากฝ่าย IT โรงพยาบาล

## บริบท

ระบบปัจจุบันใช้ MariaDB 10.4 และมีแผนจะเขียนใหม่ทั้งหมด คำถามคือย้ายไป PostgreSQL หรืออยู่กับ MariaDB ต่อ

ADR ใบนี้บันทึกไว้ตอนที่ยังไม่ตัดสิน เพื่อไม่ให้เหตุผลทั้งสองฝั่งหายไประหว่างทาง

## ข้อเสนอ

ย้ายไป **PostgreSQL** ตอนเขียนใหม่ โดยมีข้อแม้ว่าฝ่าย IT โรงพยาบาลรับดูแลได้

เหตุผลที่หนักที่สุดไม่ใช่เรื่อง feature ทั่วไป แต่ตรงกับปัญหาที่ระบบนี้มีจริง:

- **`EXCLUDE` constraint** การันตีระดับฐานข้อมูลได้ว่าช่วงเวลาที่เครื่องหนึ่งสังกัดแผนกหนึ่งจะไม่ทับกัน ตอนนี้ตาราง `device_location_history` ให้ช่วงเวลาทับกันได้ และไม่มีอะไรกันเลย ซึ่งทำให้รายงานแยกตามฝ่าย/แผนกผิดย้อนหลังได้โดยไม่มีใครรู้
- `CHECK` constraint ที่ใช้งานได้เต็มรูปแบบ และ generated column สำหรับค่าที่คำนวณได้
- window function ที่ใช้กับรายงานเปรียบเทียบรายเดือนได้สะดวกกว่า

## ทางเลือก

**อยู่กับ MariaDB ต่อ** — ข้อดีคือฝ่าย IT ดูแลเป็นอยู่แล้ว มี backup routine ที่ใช้งานจริง และไม่ต้องเรียนรู้อะไรใหม่ ฐานข้อมูลที่ไม่มีคนดูแลเป็นอันตรายกว่าฐานข้อมูลที่มี feature น้อยกว่า

ข้อจำกัดที่ต้องยอมรับถ้าเลือกทางนี้: การกันช่วงเวลาทับกันต้องทำในโค้ดและเทสแทน ซึ่งอ่อนแอกว่าเพราะทางเข้าอื่น (phpMyAdmin, SQL มือ) ข้ามได้ — เป็นรูปแบบเดียวกับที่ทำให้เกิดปัญหาใน [ADR-0002](0002-store-months-in-common-era.md)

## สิ่งที่ต้องรู้ก่อนตัดสิน

1. ฝ่าย IT โรงพยาบาลมีคนดูแล PostgreSQL ได้หรือไม่ — ใครเป็นคนกู้คืนตอนตีสาม
2. มีระบบอื่นในโรงพยาบาลที่ต้องอ่านฐานข้อมูลนี้ตรงๆ หรือไม่
3. นโยบาย backup ที่มีอยู่รองรับ engine ใหม่ได้หรือไม่

## ผลที่ตามมา (ถ้าเลือก PostgreSQL)

- ต้องเขียน script ย้ายข้อมูลจาก MariaDB และรันกับข้อมูลจริงตั้งแต่เนิ่นๆ ไม่ใช่ใกล้ส่ง
- `database/*.sql` ทั้งหมดต้องเขียนใหม่ เพราะ syntax ต่างกันพอสมควร
- ต้องมีคู่มือ backup และการซ้อมกู้คืนใน `docs/` ก่อนขึ้นใช้จริง
