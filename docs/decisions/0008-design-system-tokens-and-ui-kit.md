# 0008 — สร้าง design system เป็นชั้น token + ชุด component กลาง

**สถานะ:** Accepted

## บริบท

หน้าจอทั้งหมดถูกเขียนด้วยคลาสสีของ Tailwind ตรงๆ (`bg-gray-50`, `text-blue-600`) กระจายอยู่หลายพันจุด และไม่มีที่ไหนเป็นเจ้าของ "หน้าตาของระบบ" ผลที่ตามมาคือ

- **ปุ่มเดียวกันหน้าตาไม่เหมือนกัน** ปุ่มลบเป็นสี่เหลี่ยมแดงในหน้าหนึ่ง เป็นไอคอนถังขยะในอีกหน้า ปุ่ม "เพิ่ม" เป็นวงกลมมีเครื่องหมายบวกในหน้า master data แต่เป็นปุ่มยาวในหน้าอื่น
- **โหมดมืดพังเป็นหย่อมๆ** สเกล `gray`/`blue`/`red` ถูกพลิกตามโหมดแต่ `green`/`yellow`/`purple` ไม่ถูกพลิก การ์ดที่ใช้สีเหล่านั้นจึงกลายเป็นแผ่นสีจ้าโผล่ขึ้นมากลางหน้าจอโทนมืด แต่ละหน้าจึงต้องเขียน CSS เฉพาะกิจของตัวเองแก้ทีละจุด
- **ตารางกดด้วยคีย์บอร์ดไม่ได้** หัวคอลัมน์ที่เรียงลำดับได้เป็น `<th @click>` ไม่ใช่ปุ่ม และไม่มี `aria-sort` โปรแกรมอ่านหน้าจอจึงไม่รู้ว่ากำลังเรียงตามคอลัมน์ไหน
- **หน้าต่างซ้อนและ dropdown เขียนเองทุกตัว** ไม่มีการขังโฟกัส ไม่คืนโฟกัสตอนปิด เลื่อนเลือกด้วยลูกศรไม่ได้
- **หน้า master data เจ็ดหน้าเป็นสำเนากันเกือบทั้งไฟล์** แล้วค่อยๆ เพี้ยนไปคนละทาง บางหน้าตรวจชื่อซ้ำ บางหน้าไม่ตรวจ

ทั้งหมดนี้ไม่ใช่ปัญหา "โค้ดไม่สวย" แต่เป็นต้นทุนที่ผู้ใช้จ่ายทุกวัน: ความลังเลก่อนกดปุ่ม และงานที่ทำไม่ได้เลยสำหรับคนที่ใช้คีย์บอร์ดหรือโปรแกรมอ่านหน้าจอ

## การตัดสินใจ

**แยกหน้าตาของระบบออกมาเป็นชั้นของตัวเอง แล้วบังคับให้ทุกหน้าใช้ผ่านชั้นนั้นเท่านั้น**

โครงสร้างสามชั้น อยู่ที่ `apps/web/src/`

| โฟลเดอร์ | บทบาท | กฎ |
|---|---|---|
| `design/` | token ของสี ตัวอักษร ระยะ เงา และจังหวะการเคลื่อนไหว | เป็น CSS ล้วน ไม่มี JavaScript |
| `ui/` | component พื้นฐานที่ไม่รู้จักเรื่องธุรกิจ | ห้ามมีคำว่าเครื่องพิมพ์/ปีงบ/แผนก และห้ามเรียก API |
| `app/` | เปลือกของแอป — แถบเมนู แถบบน ช่องค้นหาคำสั่ง | รู้เรื่องเส้นทางและสิทธิ์ได้ |

**ชั้น token แบ่งเป็นสามระดับ ห้ามข้ามระดับ**

1. **Primitive** — สเกลสีดิบ 50–950 ในปริภูมิ OKLCH ไม่มีความหมายทางการใช้งาน
2. **Semantic** — ตั้งชื่อตามหน้าที่ (`--surface`, `--ink-mute`, `--danger`) สลับค่าเองตามโหมดสว่าง/มืด **นี่คือชั้นเดียวที่ component เรียกใช้**
3. **Utility** — `@theme inline` ของ Tailwind v4 แปลง semantic เป็นคลาส (`bg-surface`, `text-ink-mute`)

**ตัดสินใจย่อยที่ผูกอยู่กับข้อนี้**

- **ใช้ OKLCH ไม่ใช่ hex** — ค่า L เป็นความสว่างเชิงการรับรู้จริง ทำให้ออกแบบสเกลที่ "ห่างเท่ากัน" ได้ทุกสี และคำนวณ contrast ล่วงหน้าได้ ทุกคู่สีในระบบผ่าน WCAG AA แล้วโดยการคำนวณ ไม่ใช่โดยการเดา
- **สีแบรนด์มาจากโลโก้โรงพยาบาลจริง** — teal จากตัว "TH" เป็นสีหลัก และส้มจากตัว "SU" เป็นสีเน้น แทนสีฟ้าอมเทาที่ไม่ได้อ้างอิงอะไร
- **โหมดมืดไม่ใช่การกลับสีของโหมดสว่าง** — บนพื้นมืด แผ่นที่ลอยสูงกว่าต้องสว่างขึ้น ไม่ใช่มีเงามากขึ้น semantic token จึงถูกกำหนดแยกกันทั้งสองโหมด ไม่ใช่พลิกสเกลอัตโนมัติแบบเดิม
- **รับ Reka UI เป็น dependency** สำหรับหน้าต่างซ้อน เมนู แท็บ tooltip และช่องเลือกที่พิมพ์ค้นหาได้ — เป็นสิ่งที่เขียนเองแล้วถูกครบทุกข้อได้ยากมาก
- **รับ lucide-vue-next เป็นชุดไอคอน** แทนการเก็บ path ของ SVG ไว้ในไฟล์ component

## ทางเลือกที่พิจารณาแล้วไม่เลือก

**ค่อยๆ แก้ทีละหน้าโดยไม่มีชั้นกลาง** — เป็นสิ่งที่ทำมาตลอดและเป็นสาเหตุของสภาพปัจจุบัน ทุกครั้งที่แก้หน้าหนึ่งให้ดีขึ้น ระยะห่างกับหน้าอื่นก็กว้างขึ้น

**เปลี่ยน framework เป็น Next.js หรือ Nuxt** — ปัญหาทุกข้อข้างบนไม่มีข้อไหนเกิดจาก Vue และการเปลี่ยน framework จะทิ้งกฎธุรกิจที่ผ่านการใช้งานจริงไปพร้อมกัน ซึ่งขัดกับ [ADR-0007](0007-improve-in-place-instead-of-rewriting.md) โดยตรง

**ใช้ component library สำเร็จรูปทั้งชุด (Vuetify / PrimeVue)** — ได้ component ครบเร็วก็จริง แต่หน้าตาจะกลายเป็นของ library นั้นไม่ใช่ของโรงพยาบาล และการปรับให้ตรงกับแบรนด์กับภาษาไทยมักจบด้วยการเขียน CSS ทับซึ่งเปราะกว่าการเขียนเอง — เลือกทางกลาง คือรับเฉพาะ "พฤติกรรม" (Reka UI ไม่มีสไตล์ของตัวเอง) แล้วเขียนหน้าตาเองทั้งหมด

**เก็บสเกลสีเดิมไว้แล้วเพิ่ม token ใหม่ควบคู่กัน** — ใช้เป็นทางผ่านระหว่างย้าย (ไฟล์ `legacy-bridge.css` ที่แม็ปคลาสเดิมมาที่ token ใหม่) เพื่อไม่ให้มีจังหวะไหนที่ระบบอยู่ในสภาพครึ่งๆ กลางๆ แต่ไม่เก็บไว้ถาวร เพราะการมีสองระบบสีพร้อมกันคือสภาพที่แย่กว่าทั้งสองแบบ — ไฟล์นั้นถูกลบทิ้งแล้วเมื่อย้ายครบทุกหน้า

## ผลที่ตามมา

- ทุกหน้าจอถูกเขียนใหม่ให้เรียกผ่าน `src/ui/` ทั้งหมด การเปลี่ยนหน้าตาของปุ่มทั้งระบบทำได้จากไฟล์เดียว
- หน้าข้อมูลอ้างอิงเจ็ดหน้ายุบเหลือการประกาศ schema ต่อหน้า แล้วใช้ `MasterDataPage` ร่วมกัน — พฤติกรรมทุกหน้าตรงกันโดยอัตโนมัติ
- ตาราง หน้าต่างซ้อน เมนู และช่องเลือก ใช้งานด้วยคีย์บอร์ดได้ครบ และประกาศสถานะให้โปรแกรมอ่านหน้าจอถูกต้อง
- หน้าทั้งหมดถูกเปลี่ยนเป็น lazy-load ตามเส้นทาง ทำให้ JS ก้อนแรกที่ต้องดาวน์โหลดตอนเปิดเว็บลดจาก ~260 kB เหลือ ~26 kB (gzip, วัดจาก `npm run build --workspace @suth/web`) — สำคัญกับเครื่องรุ่นเก่าในโรงพยาบาล
- เพิ่ม dependency สองตัวที่ต้องดูแลต่อ (`reka-ui`, `lucide-vue-next`) ทั้งคู่เป็น dependency ของฝั่งเว็บเท่านั้น ไม่กระทบ API
- **กฎที่ต้องรักษาต่อจากนี้:** ห้ามเขียนคลาสสีของ Tailwind ตรงๆ ในหน้าจอ (`bg-gray-50`, `text-blue-600`) ให้ใช้ชื่อเชิงหน้าที่เท่านั้น (`bg-surface`, `text-brand-ink`) ถ้าไม่มีชื่อที่ต้องการแปลว่าต้องเพิ่ม semantic token ใหม่ ไม่ใช่หยิบสีดิบมาใช้
