# 0023 — สัญญามีอายุของตัวเองและรายการราคา ยอดพิมพ์บันทึกเป็นรายมิเตอร์ต่องวด

**สถานะ:** Accepted — ผู้ใช้ยืนยันเมื่อ 2026-09-21; ผู้ใช้เพิ่มค่าเช่าและ VAT หลังเห็นใบแจ้งหนี้ SUTH 86/2567 แทนที่ `contracts.fiscal_year_id` และราคาเดียวต่อสัญญาใน [ADR-0019](0019-effective-pricing-history.md)

## บริบท

ระบบถือว่าสัญญาหนึ่งฉบับผูกปีงบเดียว มีราคาเดียว และเครื่องหนึ่งมียอดเดียวต่อเดือน สัญญาจริง SUTH192/2568 ขัดทั้งสามข้อ: มี 36 งวดครอบปีงบ 2569–2572, มีสี่ราคาตามหมวด (A4 เลเซอร์และ A4 มัลติฟังก์ชัน 0.365, A3 ขาวดำ 0.35, A3 สี 3.9) และเครื่อง A3 สีมีมิเตอร์ขาวดำกับมิเตอร์สีแยกกัน ผู้ใช้ขอ "ให้เลขที่สัญญาซ้ำได้ พ่วงปีงบ 3 ปี" เพื่อเลี่ยงข้อจำกัดข้อแรก

ไฟล์ของผู้ให้เช่าส่งมาเป็นเลขมิเตอร์ต้นงวดและสิ้นงวด งวดของ SUTH192/2568 เริ่มวันที่ 24 และจบวันที่ 23 ของเดือนถัดไป ส่วนงวดของ SUTH 86/2567 (สัญญา 3 ปี 29 ก.ย. 2567–29 ก.ย. 2570) เป็นเดือนปฏิทิน

## การตัดสินใจ

- เลขที่สัญญายังห้ามซ้ำ สัญญามีวันเริ่มและวันสิ้นสุดของตัวเอง ปีงบที่เกี่ยวข้องคำนวณจากช่วงนี้ — ถอดการผูกปีงบเดียว
- สัญญามีรายการราคาหนึ่งรายการขึ้นไป
- เครื่องมีมิเตอร์หนึ่งตัวขึ้นไป แต่ละมิเตอร์ผูกรายการราคาเดียว ยอดพิมพ์ไม่ซ้ำที่ `(มิเตอร์, เดือน)`
- เก็บเลขมิเตอร์ต้นงวดและสิ้นงวด จำนวนหน้าดิบ = สิ้นงวด − ต้นงวด ระบบเตือนเมื่อเลขต้นงวดไม่เท่าเลขสิ้นงวดของงวดก่อน
- งวดนับเป็นเดือนที่งวดสิ้นสุด ปีงบของงวดยึดวันสิ้นงวดตาม [ADR-0001](0001-thai-fiscal-year-oct-sep.md) — สัญญาที่เริ่มวันที่ 1 มีงวดแรกเป็นเดือนที่เริ่ม ส่วนสัญญาที่เริ่มกลางเดือนมีงวดแรกเป็นเดือนถัดไป (SUTH192/2568 เริ่ม 24 ก.พ. งวดแรกคือ มี.ค.; SUTH 86/2567 เริ่ม 29 ก.ย. งวดแรกคือ ต.ค.) กติกานี้ใช้ทั้งการหาราคาและเดือนที่เก็บค่าเช่า งวดสุดท้ายคือเดือนของวันสิ้นสุดสัญญา
- ตัวนำเข้าอ่านแผ่นรายงวดของผู้ให้เช่าได้ตรง ผ่าน API เดิม ไม่ต่อฐานข้อมูลตรง
- สัญญามีค่าเช่าคงที่ต่อเดือนและอัตรา VAT ได้ (ไม่บังคับ) เพราะสัญญา SUTH 86/2567 เรียกเก็บค่าเช่า 2,333.65 บาทต่อเดือนและ VAT 7% ของ (ค่าพิมพ์ + ค่าเช่า) ส่วน SUTH192/2568 ไม่มีทั้งสองอย่าง ยอดตามใบแจ้งหนี้รวม VAT ปัด VAT ครั้งเดียวที่ยอดรวมของสัญญาในงวดนั้น ส่วน "ค่าใช้จ่าย" บนหน้าภาพรวมยังเป็นค่าพิมพ์อย่างเดียว เพราะเป็นส่วนเดียวที่แบ่งตามแผนกและเครื่องได้

## ทางเลือกที่ตัดทิ้ง

- **เลขที่สัญญาซ้ำได้ หนึ่งแถวต่อปีงบ** — ต้องย้ายเครื่องข้ามแถวทุกปี ตัวนำเข้าที่จับคู่ด้วยเลขจะผูกผิดฉบับ และหน้าจอหลายจุดแสดงเลขเดียวกันจนแยกไม่ออก
- **ใช้ราคาพิเศษเฉพาะเครื่องแทนรายการราคา และสร้างมิเตอร์สีเป็นเครื่องเทียม** — เร็วกว่า แต่นับเครื่องเกินจริง และคำว่า "เครื่อง" จะมีสองความหมาย ใช้ได้เป็นทางชั่วคราวเท่านั้น
- **ให้คนแปลงไฟล์ผู้ให้เช่าเป็นเทมเพลตรายเดือน** — เป็นการคัดลอกมือเดือนละหลายร้อยแถว ซึ่งเป็นจุดที่ตัวเลขผิดง่ายที่สุด

## ผลที่ตามมา

เป็นการเปลี่ยน schema ครั้งใหญ่ (สัญญา รายการราคา มิเตอร์ ยอดพิมพ์) ต้องมี migration ที่ย้ายยอดเดิมเป็นมิเตอร์หลักของแต่ละเครื่อง และแก้ทุกจุดที่ถือว่าสัญญาเท่ากับปีงบเดียว
