# 0035 — บันทึกการตรวจย้อนหลัง (audit log) ของทุกการแก้ไขด้วยมือ และกันกรอกยอดทับกัน

- สถานะ: Accepted
- วันที่: 2026-09-24
- Issue: #214 · ที่มา: [รายงานตรวจระบบ 2026-09-24](../reports/system-audit-2026-09-24.md) F05, F06

## บริบท

ยอดพิมพ์คือฐานของทุกบาท แต่ระบบตอบไม่ได้ว่าใครแก้ยอดเดือนไหน เมื่อไร จากค่าอะไร — ตาราง `print_transactions`, `devices`,
`contracts`, `users` ไม่มี `updated_by/updated_at` มีเพียงงานนำเข้าที่มีประวัติของตัวเอง และสองคนกรอกเดือนเดียวกันพร้อมกัน
คนที่กดทีหลังทับค่าอีกคนเงียบๆ

## การตัดสินใจ

1. ตาราง `audit_log` หนึ่งตารางสำหรับทุกชนิดข้อมูล: เวลา ผู้ทำ (id + สำเนาชื่อ) การกระทำ ชนิด id/คีย์ สรุปภาษาคน ค่าก่อน/หลัง
   (**เฉพาะช่องที่เปลี่ยน**) และ request id ที่ตรงกับบรรทัดใน log ของ API
2. เขียนจากแอป (`shared/audit.js`) ไม่ใช่ trigger ของฐาน — trigger ไม่รู้ว่าใครเป็นผู้ใช้ของแอป และไม่มีสรุปภาษาคน
   เส้นทางที่ใช้ transaction อยู่แล้ว (ยอดพิมพ์ เครื่อง สัญญา งานนำเข้า) เขียนใน transaction เดียวกัน — แก้สำเร็จ = มีบันทึก
   ข้อมูลอ้างอิงและผู้ใช้ (เขียนคำสั่งเดียว) บันทึกต่อท้ายทันที
3. **ห้ามเก็บรหัสผ่านหรือ hash** — บันทึกแค่ `password_changed: true`
4. ลบบัญชีแล้วประวัติยังอยู่ (`user_id` เป็น NULL ชื่อยังอยู่)
5. อ่านได้เฉพาะผู้ดูแล: หน้า "ประวัติการแก้ไข" และการ์ดในหน้ารายละเอียดเครื่อง
6. กันกรอกทับ: คำขอบันทึกยอดส่งค่าที่ผู้ใช้เห็นก่อนแก้ (`previous`) มาด้วย ถ้าในฐานเปลี่ยนไปแล้ว ตอบ 409 `reading_changed`
   และไม่บันทึกทั้งชุด — ไม่ส่ง `previous` = ไม่ตรวจ (เครื่องมือเก่า/สคริปต์)

## ทางเลือกที่ตัดทิ้ง

**Trigger ในฐานข้อมูล** — รู้แค่ผู้ใช้ MySQL ของแอป (ทุกคนคือ `suth_app`) และเก็บทั้งแถว อ่านไม่ออกว่าเกิดอะไร

**คอลัมน์ `updated_by/updated_at` ในทุกตาราง** — บอกได้แค่คนล่าสุด ไม่รู้ค่าเดิมและไม่มีประวัติ

**ล็อกแถวระหว่างที่หน้าเปิดอยู่** — ผู้ใช้เปิดหน้าทิ้งไว้ข้ามวันได้ การเทียบค่าตอนบันทึกเรียบกว่าและไม่ค้าง
