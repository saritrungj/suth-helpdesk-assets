# 0030 — นำเข้าอัตโนมัติ: ระบบตัดสินแทนเมื่อไม่มีทางเลือกอื่น หยุดถามเมื่อการเดาอาจทำข้อมูลเสีย

- สถานะ: Accepted · ส่วน "บันทึกให้เอง" และ "สร้างสัญญา/ปีงบทันที" ถูกแทนด้วย [ADR-0034](0034-import-preview-before-write.md) — ระบบเตรียมให้ แต่บันทึกเมื่อผู้ดูแลกดยืนยันเท่านั้น
- วันที่: 2026-09-24
- Issue: #190 · ต่อจาก [ADR-0027](0027-import-session-lifecycle.md), [ADR-0028](0028-import-commit-strategy.md), [ADR-0029](0029-import-session-visibility.md)

## บริบท

หน้านำเข้า (#180) ให้ผู้ดูแลตัดสินทุกอย่างที่ระบบไม่รู้: ชื่อยี่ห้อ/อาคาร/ฝ่ายทีละชื่อ หมวดมิเตอร์ของรุ่น สร้างสัญญา สร้างปีงบ
แล้วค่อยกดบันทึก กับระบบที่ยังว่าง รายงานมิเตอร์ไฟล์เดียว (6 แผ่น 268 เครื่อง) ต้องกดราว 25 ครั้ง ทั้งที่ทุกคำถามมีคำตอบเดียว —
ระบบว่างไม่มีชื่อเดิมให้จับคู่ "สร้างใหม่" จึงเป็นทางเลือกเดียว ผู้ใช้ขอให้โยนไฟล์แล้วระบบสร้างและบันทึกให้เอง

ข้อจำกัดที่มีอยู่: ยอดพิมพ์คือฐานของทุกบาท การบันทึกต้องเป็นการกระทำของคนผ่านหน้าเว็บ (AGENTS.md, [ADR-0012](0012-remove-mcp-server.md))
และหมวดมิเตอร์กำหนดราคาต่อหน้า — เดาหมวดผิดคือคิดเงินผิด

## การตัดสินใจ

ช่อง **"สร้างข้อมูลที่ขาดและบันทึกให้เลยเมื่อไม่มีอะไรต้องถาม"** ในหน้าอัปโหลด (เปิดไว้เป็นค่าเริ่มต้น จำค่าต่อเบราว์เซอร์)
ผู้ดูแลที่เลือกช่องนี้แล้วอัปโหลดคือคนที่สั่งบันทึกผ่านหน้าเว็บ — ข้อจำกัดข้างบนยังอยู่ ระบบไม่บันทึกอะไรที่ไม่มีคนสั่ง

หลังอัปโหลด ระบบตัดสินแทนทีละชั้น ตรวจไฟล์ใหม่หลังแต่ละชั้นด้วยเส้นทางเดียวกับที่คนกดเอง (`autoProcess` ใน `session-service.js`):

| ชั้น | ระบบทำเอง | หยุดถามเมื่อ |
|---|---|---|
| ชื่อยี่ห้อ/อาคาร/ฝ่ายที่ไม่รู้จัก | สร้างใหม่ตามชื่อในไฟล์; ชื่อในไฟล์ที่ต่างกันแค่เว้นวรรค เครื่องหมาย หรือคำนำหน้า (อาคาร ฝ่าย งาน …) รวมเป็นรายการเดียว | ชื่อคล้ายชื่อหรือชื่อเรียกอื่นที่มีในระบบ — สร้างเองจะได้รายการซ้ำ |
| หมวดมิเตอร์ของรุ่นใหม่ | จาก **แคตตาล็อกรุ่นที่ตรวจสเปกแล้ว** (`model-catalog.js`) | รุ่นที่ไม่อยู่ในแคตตาล็อก — ไม่เดาจากคำอย่าง "MFP" เพราะไม่บอกขนาดกระดาษ |
| สัญญาที่ไฟล์อ้างแต่ยังไม่มี | สร้างจากหัวรายงาน (เลขที่ อายุ ค่าเช่า VAT) และราคาต่อหน้าจากคอลัมน์ Cost/Click | อ่านวันที่ไม่ได้ ไม่มีราคา รุ่นยังไม่มีหมวด หรือหมวดเดียวมีหลายราคาในไฟล์ |
| ปีงบที่ครอบเดือนในไฟล์ | สร้าง | — |
| บันทึก | บันทึกเมื่อผ่านทุกข้อ | ไฟล์จะเขียนทับยอดเดิมด้วยค่าต่างกัน · สัญญาในระบบต่างจากไฟล์ · ยอดตามใบแจ้งหนี้ไม่ตรงท้ายรายงาน · เลขซีเรียลคล้ายเครื่องอื่น · ไม่มีอะไรใหม่ |

แถวที่ข้ามและคำเตือนทั่วไปของทะเบียนไม่หยุดการบันทึก เพราะไม่ทำข้อมูลเดิมเสีย — แสดงในหน้าผลลัพธ์

ทุกอย่างที่ระบบตัดสินแทนเขียนลงประวัติของงาน (`auto_decided`, `contract_created` + `auto`, `fiscal_years_created` + `auto`,
`auto_finished` พร้อมเหตุผลที่หยุด) และหน้างานแสดงสรุป "ระบบสร้างและเลือกให้เอง" ถ้าหยุด งานยังเปิดอยู่ให้คนทำต่อจากจุดนั้น
ปุ่ม "ให้ระบบเลือกส่วนที่เหลือ" ในหน้างานใช้กฎชุดเดียวกันแต่ไม่บันทึก

การบันทึกยังเป็นไปตาม ADR-0028 ทุกข้อ (ตรวจแบบ dry-run → fingerprint → commit ในทรานแซกชันเดียว)

## ทางเลือกที่ไม่เลือก

- **บันทึกอัตโนมัติเสมอ ไม่มีช่องเลือก** — ขัดข้อจำกัดเรื่องคนสั่งบันทึก และผู้ดูแลที่อยากดูก่อนไม่มีทางปิด
- **เดาหมวดจากชื่อรุ่นหรือจากราคา** — ราคาเท่ากันไม่ได้แปลว่าหมวดเดียวกัน และชื่อรุ่นไม่บอกขนาดกระดาษ ผิดหนึ่งรุ่นคือราคาผิดทุกหน้าของรุ่นนั้น
- **จับคู่ชื่อคล้ายเข้ากับของเดิมเอง** — "อาคาร ก" กับ "อาคาร ก ใหม่" อาจเป็นคนละที่ ผิดแล้วเครื่องย้ายอาคารเงียบๆ ต้องให้คนเลือก

## ผลที่ตามมา

- ระบบว่าง + รายงานมิเตอร์ของรุ่นที่รู้จัก → อัปโหลดครั้งเดียวจบ (ไฟล์จริง 268 เครื่อง 1,415 ยอด ~22 วินาที — ตรวจซ้ำหลายรอบ)
- รุ่นใหม่ที่ยังไม่รู้จักต้องถามครั้งแรก แล้วเพิ่มเข้า `model-catalog.js` เมื่อตรวจสเปกแล้ว; รุ่นที่ลงระบบแล้วใช้หมวดของเครื่องเดิมเอง
- ชื่อที่สร้างอัตโนมัติคือชื่อตามไฟล์ แก้เป็นชื่อทางการภายหลังได้ที่หน้าข้อมูลอ้างอิง — ถ้าต้องการชื่อทางการตั้งแต่แรก ปิดช่องอัตโนมัติแล้วตั้งชื่อเอง
