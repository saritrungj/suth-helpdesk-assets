# 0019 — ใช้ราคาตามช่วงที่มีผลจริงในการคำนวณย้อนหลัง

**สถานะ:** Accepted — ผู้ใช้ยืนยัน Q25–Q30 แล้ว; โครงสร้างข้อมูล การคำนวณ และการนำเสนอเปลี่ยนตามแล้ว ทดสอบกับ MariaDB 10.4 ทั้งเส้นทางฐานใหม่และ migration แล้ว **ยังไม่ได้รันกับฐานข้อมูลจริง** และยังไม่รองรับการเปลี่ยนราคากลางเดือน (Q28 ให้แสดงว่า "ยังยืนยันราคาไม่ได้" ซึ่งเป็นพฤติกรรมปัจจุบัน)

ระบบปัจจุบันใช้ราคาจากสัญญาและราคาเฉพาะเครื่องที่เก็บเป็นค่าปัจจุบัน การเปลี่ยนค่าเหล่านั้นจึงไม่ใช่หลักฐานว่าราคาใหม่มีผลกับเดือนเก่าด้วย ผู้ใช้ยืนยันให้เก็บราคาตามช่วงที่มีผลจริง และใช้ราคาที่มีผลกับยอดในช่วงนั้น เพื่อให้รายงานย้อนหลังตรวจที่มาของเงินได้ ไม่ใช้ราคาปัจจุบันย้อนแทนราคาเดิมโดยอัตโนมัติ

กฎนี้แยกจาก [ADR-0017](0017-two-percent-page-deduction.md) ซึ่งยืนยันให้หักจำนวนหน้า 2% ย้อนหลังทุกปีงบ การเปลี่ยนสัดส่วนหน้าที่คิดเงินไม่ได้อนุญาตให้เปลี่ยนราคาต่อหน้าของช่วงเก่า

## รายละเอียดที่ยังต้องมีข้อยืนยัน

- ตำแหน่งและเนื้อหาเอกสารจริงที่ระบุราคาและวันที่มีผลของข้อมูลเดิม — ระบบมีช่อง "เอกสารอ้างอิง" ให้กรอกตอนยืนยันแล้ว แต่ยังไม่มีใครกรอกของจริง
- หลักฐานยอดที่ใช้กับแต่ละราคาเมื่อราคาเปลี่ยนกลางเดือน และรายละเอียดการคำนวณเมื่อได้หลักฐานครบ
- กรณีเปลี่ยนสัญญากลางเดือน ซึ่ง Q28 ไม่ได้กำหนดการจัดยอดระหว่างสัญญา

รูปแบบตารางและ migration เลือกแล้ว (ดูด้านล่าง) แต่ **การรัน migration กับฐานข้อมูลจริงและการแก้ข้อมูลจริงยังต้องขออนุมัติแยกต่างหาก**

## หลักฐานอ้างอิงที่ยืนยันใน Q26

ยึดเอกสารสัญญาหรือเอกสารเปลี่ยนราคาที่ตรวจสอบได้เป็นหลักฐานราคาและวันที่มีผล ผู้ใช้ยังไม่ได้ระบุไฟล์ ตำแหน่งเอกสาร หรือวันที่จริง คำตอบ “ตามคำแนะนำ” ไม่ใช่หลักฐานว่าเอกสารเหล่านั้นมีอยู่ครบ และไม่อนุญาตให้อนุมานวันมีผลจากวันที่แก้ข้อมูลในระบบ

## การแสดงผลเมื่อยังยืนยันราคาไม่ได้ — Q27

แสดงยอดพิมพ์ตามที่บันทึกจริง แต่ค่าใช้จ่ายของรายการที่ยังไม่มีหลักฐานเพียงพอให้แสดง “ยังยืนยันราคาไม่ได้” พร้อมจำนวนรายการที่รอตรวจสอบ ไม่แทนค่าใช้จ่ายที่ไม่ทราบด้วยศูนย์ หากแสดงยอดเงินรวมให้ระบุ “รวมเฉพาะรายการที่ยืนยันราคาแล้ว” และแสดงสถานะนี้ใน Excel และ PDF ด้วย เพื่อไม่ให้เข้าใจว่าเป็นค่าใช้จ่ายครบทั้งหมด

ข้อยืนยันนี้ไม่ได้กำหนดกฎแบ่งยอดเมื่อเปลี่ยนราคากลางเดือน และไม่ได้เปลี่ยนสูตรต้นทุนเฉลี่ยที่ยืนยันไว้ การแสดงต้นทุนเฉลี่ยยืนยันเพิ่มเติมใน Q29 ส่วนอันดับค่าใช้จ่ายและเปอร์เซ็นต์เพิ่ม–ลดยืนยันใน Q30 ด้านล่าง

## ราคาเปลี่ยนกลางเดือนแต่มีเพียงยอดรวมทั้งเดือน — Q28

คงยอดพิมพ์จริง และแสดงค่าใช้จ่ายว่า “ยังยืนยันราคาไม่ได้” ตาม Q27 จนมีหลักฐานเพียงพอระบุยอดที่ใช้กับแต่ละราคา ไม่เฉลี่ยยอดตามจำนวนวัน และไม่เลือกราคาใดราคาหนึ่งแทนเอง การยืนยันนี้ไม่ใช่หลักฐานว่ามีการเปลี่ยนราคากลางเดือนจริงหรือมีข้อมูลแยกยอดแล้ว และยังไม่กำหนดวิธีบันทึกยอดแยกช่วงหรือเปลี่ยนกฎการปัดเศษเดิม

## ต้นทุนเฉลี่ยเมื่อยังยืนยันราคาไม่ครบ — Q29

หากรายการที่นำมาคำนวณต้นทุนเฉลี่ยต่อเครื่องในขอบเขตที่เลือกยังยืนยันราคาไม่ครบ ให้แสดง “ยังคำนวณค่าเฉลี่ยครบไม่ได้” พร้อมจำนวนรายการรอยืนยันราคา จนรายการที่นำมาคำนวณมีราคาครบ ไม่ใช้ค่าใช้จ่ายเพียงบางส่วนหารจำนวนเครื่องทั้งหมด และไม่เปลี่ยนตัวหารให้เหลือเฉพาะเครื่องที่ยืนยันราคาแล้ว

คงสูตร Q3: ค่าใช้จ่ายสุทธิหารจำนวนเครื่องไม่ซ้ำที่มีการบันทึกยอดในช่วงที่เลือก รวมเครื่องที่บันทึกศูนย์หน้า แต่ไม่รวมเครื่องที่ยังไม่บันทึกยอด ข้อนี้เปลี่ยนการแสดงผลเมื่อราคาไม่ครบ ไม่เปลี่ยนสูตรหรือถือว่าราคาครบหมายถึงกรอกยอดครบ

## อันดับค่าใช้จ่ายและผลเปรียบเทียบเมื่อราคายังไม่ครบ — Q30

แสดงยอดเงินที่ยืนยันแล้วได้พร้อมป้ายกำกับตาม Q27 แต่เมื่อรายการในขอบเขตที่เปรียบเทียบยังยืนยันราคาไม่ครบ ต้องยังไม่สรุปอันดับค่าใช้จ่าย ผู้ใช้เงินสูงสุด หรือเปอร์เซ็นต์ต้นทุนเพิ่ม–ลด เพื่อไม่ให้ยอดเงินเพียงบางส่วนถูกตีความเป็นข้อสรุป การแสดงยอดเงินที่ยืนยันแล้วไม่ได้หมายความว่าผลเปรียบเทียบครบถ้วน

## รูปแบบข้อมูลที่เลือก

สองชิ้น โดยไม่แยกตาราง "ประวัติราคา" ออกมาต่างหาก

| ที่เก็บ | ตอบคำถามว่า |
|---|---|
| `contracts.effective_from` / `effective_to` / `price_verified_at` | สัญญาฉบับนี้ (และราคาของมัน) มีผลช่วงไหน และใครรับรองจากเอกสารอะไร |
| `device_contract_history` | เดือนนั้นเครื่องนี้ถูกคิดเงินภายใต้สัญญาไหน และมีราคาเฉพาะเครื่องเท่าไหร่ |

ทำไมไม่มีตาราง `contract_price` แยก: สัญญาหนึ่งฉบับระบุราคาเดียวตลอดอายุสัญญา ซึ่งตรงกับเอกสารจริง การเปลี่ยนราคากลางอายุสัญญาต้องมีหลักฐานว่าเกิดขึ้นจริง ซึ่ง Q26 ระบุว่ายังไม่มี — และ Q28 สั่งให้แสดงว่า "ยังยืนยันราคาไม่ได้" อยู่แล้วเมื่อราคาเปลี่ยนกลางเดือน ถ้าวันหนึ่งมีเอกสารยืนยันการเปลี่ยนราคากลางอายุสัญญา ให้เพิ่มตารางราคาทีหลังโดยไม่ต้องรื้อ `device_contract_history`

`device_contract_history` จำเป็นเพราะ `devices.contract_id` ก็เป็นค่าปัจจุบันที่ถูกใช้ตอบคำถามย้อนหลังเช่นเดียวกับราคา ถ้าไม่มีมัน การย้ายเครื่องไปสัญญาของปีงบใหม่ตาม [#81](https://github.com/saritrungj/suth-helpdesk-assets/issues/81) จะทำให้เดือนเก่าไม่มีราคาทันที เพราะสัญญาใหม่ไม่ครอบคลุมเดือนนั้น

## การหาราคาของหนึ่งเดือน

สามขั้น อยู่ใน `v_monthly_kpi` ที่เดียว ทุกหน้าที่แสดงเงินอ่านจากที่นั่น

1. หาช่วงการคิดเงินของเครื่องที่ครอบคลุมเดือนนั้น ช่วงที่เริ่มทีหลังชนะเมื่อซ้อนกัน
2. ช่วงนั้นมีราคาเฉพาะเครื่องไหม ถ้ามีใช้เลย
3. ถ้าไม่มี ใช้ราคาของสัญญาที่ช่วงนั้นระบุ **เฉพาะเมื่อสัญญาถูกยืนยันแล้วและช่วงที่มีผลครอบคลุมเดือนนั้น** ไม่งั้นคืน `NULL` = ยังยืนยันราคาไม่ได้

`NULL` ไม่ใช่ศูนย์ และไม่ถูกนับในยอดรวม ทุก endpoint ที่คืนยอดเงินจึงคืน `unpriced_readings` ควบคู่เสมอ

## สิ่งที่ migration ทำและไม่ทำ

`migration_add_effective_pricing.sql` เพิ่มคอลัมน์ ตาราง และเปลี่ยน view **ไม่เติมข้อมูลย้อนหลังให้เลยสักแถว** ตาม Q26

หลังรัน ทุกสัญญายังไม่ถูกยืนยัน รายงานทุกหน้าจึงแสดงค่าใช้จ่ายว่า "ยังยืนยันราคาไม่ได้" จนกว่าผู้ดูแลจะเปิดหน้า `/admin/contract-prices` แล้วกดยืนยันทีละฉบับ ระบบเสนอช่วง 1 ต.ค.–30 ก.ย. ของปีงบที่สัญญาผูกอยู่ให้เป็นค่าตั้งต้น (ซึ่งเอกสารสัญญาระบุไว้อยู่แล้ว) แต่ยังต้องมีคนอ่านและกดรับรอง

ตอนกดยืนยัน ระบบเปิดช่วงการคิดเงินให้เครื่องทุกเครื่องที่ผูกกับสัญญานั้น ยอดเงินย้อนหลังจึงกลับมาครบทันทีที่ยืนยันครบทุกฉบับ

## การแก้ราคาภายหลัง

แก้ `price_per_page` ของสัญญาที่ยืนยันไปแล้ว จะล้างสถานะการยืนยันทิ้ง (เก็บช่วงวันที่ไว้) ทำให้ต้องยืนยันใหม่พร้อมเอกสาร — ไม่งั้นราคาใหม่จะถูกใช้ย้อนหลังทันทีโดยยังติดป้ายว่าผ่านการตรวจแล้ว ซึ่งเป็นสิ่งที่ ADR นี้มีไว้กันตั้งแต่ต้น

## สิ่งที่ยังไม่ได้ทำ

- การเปลี่ยนราคากลางเดือนหรือกลางอายุสัญญา — ยังแสดงว่า "ยังยืนยันราคาไม่ได้" ตาม Q28
- ต้นทุนเฉลี่ยตาม Q29 ยังไม่ได้เพิ่มป้าย "ยังคำนวณค่าเฉลี่ยครบไม่ได้" ในทุกหน้าที่แสดงค่าเฉลี่ย
- การส่งออก Excel/PDF แสดงสถานะราคาแล้วบนการ์ดสรุป แต่ยังไม่ครบทุกไฟล์ส่งออก
