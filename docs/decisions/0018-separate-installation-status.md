# 0018 — แยกสถานะการติดตั้งจากสถานะการใช้งานของเครื่อง

**สถานะ:** Accepted — ผู้ใช้ยืนยันการตัดสินใจใน Q11, Q14–Q15 และ Q17–Q21; โค้ดและ schema เปลี่ยนตามแล้ว ทดสอบกับ MariaDB 10.4 ทั้งเส้นทางฐานใหม่และเส้นทาง migration แล้ว **ยังไม่ได้รันกับฐานข้อมูลจริง** — Q18 (ระบบไม่เลือกสถานะให้) ถูกผ่อนเฉพาะไฟล์ที่มีหลักฐานการติดตั้งตาม [ADR-0026](0026-raw-registry-import.md) โดย Q21 ยังมีผลเต็ม

## บริบทและการตัดสินใจ

requirement ดิบเสนอให้ใช้ “ติดตั้งแล้ว / ยังไม่ได้ติดตั้ง” แทน “ใช้งานอยู่ / ซ่อมบำรุง / ปลดระวาง” ในรอบ Q11 ผู้ใช้เลือกเพิ่มสถานะการติดตั้งแยกต่างหากและเก็บสถานะการใช้งานเดิมไว้ในทะเบียน พร้อมซ่อนตัวกรองสถานะเครื่องในหน้าบันทึกยอดพิมพ์

สองสถานะตอบคนละคำถาม: สถานะการติดตั้งบอกว่าติดตั้งแล้วหรือยัง ส่วนสถานะการใช้งานบอกว่าใช้งานอยู่ ซ่อม หรือปลดระวาง ทางเลือกที่ไม่ได้เลือกคือการแทนค่าทั้งสามเดิมด้วยค่าการติดตั้งสองค่า ซึ่งจะไม่เหลือความหมายเดิมของสถานะซ่อมและปลดระวาง

## ข้อสรุปเพิ่มเติมที่ยืนยันแล้ว

- Q14: ให้ผู้ดูแลตรวจยืนยันสถานะการติดตั้งของเครื่องเดิมรายเครื่อง ห้ามอนุมานจากสถานะใช้งานหรือการมีที่ตั้ง
- Q15: กลุ่มที่ต้องกรอกยอดและนับเป็นงานค้างคือ “ติดตั้งแล้ว + ใช้งานอยู่” ส่วนเครื่องซ่อมและปลดระวางยังดูยอดย้อนหลังได้
- Q17: นับความรับผิดชอบตามช่วงที่ติดตั้งและใช้งานจริง โดยบันทึกช่วงเวลาเริ่ม–สิ้นสุด เดือนก่อนติดตั้งไม่เป็นงานค้าง และการส่งซ่อมปัจจุบันไม่ทำให้งานค้างเดือนเก่าหายไป
- Q18: ผู้กรอกต้องเลือกสถานะการติดตั้งก่อนบันทึกเครื่องใหม่ ระบบไม่เลือกค่าให้เอง
- Q19: เครื่องเดิมที่ยังไม่ตรวจแสดง “ยังไม่ตรวจยืนยัน” พร้อมจำนวนที่เหลือ และระบุว่าความครบถ้วนของยอดยังยืนยันไม่ได้จนกว่าจะตรวจครบ ห้ามจัดเครื่องเหล่านี้เป็น “ยังไม่ได้ติดตั้ง” อัตโนมัติ
- Q20: เดือนที่มีช่วงติดตั้งแล้วและใช้งานอยู่แม้เพียงบางส่วน ต้องบันทึกยอดจริงของเดือนนั้นหนึ่งรายการ ถ้าไม่มีการพิมพ์ให้บันทึก 0 ไม่เฉลี่ยยอดตามจำนวนวัน
- Q21: ตรวจยืนยันข้อเท็จจริงปัจจุบันที่ทราบได้ก่อน ส่วนช่วงย้อนหลังที่ยังไม่ทราบเวลาเริ่ม–สิ้นสุดให้แสดงความครบถ้วนว่า “ยังยืนยันไม่ได้” ห้ามอนุมานวันติดตั้งจากวันลงทะเบียน วันกรอกยอดครั้งแรก หรือวันย้ายเครื่อง และต้องเก็บยอดดิบที่บันทึกแล้วไว้

การมีช่วงเวลาความรับผิดชอบทำให้เครื่องที่เพิ่มหรือหยุดใช้งานกลางปีไม่เปลี่ยนความครบถ้วนของเดือนก่อนหน้าไปตามสถานะปัจจุบัน ต่างจากข้อจำกัดของโค้ดเดิมที่อธิบายใน [ขอบเขต API](../reference/api.md#ข้อจำกัดที่ต้องรู้ก่อนเอา-coverage-ไปใช้ตัดสินใจ)

## ขอบเขตการนำไปใช้

การกำหนดรูปแบบข้อมูลและ migration ต้องรองรับทั้งช่วงที่ตรวจยืนยันได้และช่วงที่ยังไม่มีหลักฐาน การยืนยันกฎข้างต้นไม่ใช่การอนุมัติ mapping อัตโนมัติ การเปลี่ยนสิทธิ์ หรือการรัน migration

## รูปแบบข้อมูลที่เลือก

สามชิ้น แยกกันเพราะตอบคนละคำถาม

| ที่เก็บ | ตอบคำถามว่า |
|---|---|
| `devices.installation_status` | ตอนนี้ติดตั้งแล้วหรือยัง — `NULL` คือ "ยังไม่มีใครตรวจ" ไม่ใช่ "ยังไม่ได้ติดตั้ง" |
| `device_service_period` | เดือนไหนบ้างที่เครื่องนี้ต้องบันทึกยอด (ช่วงเริ่ม–สิ้นสุด มีได้หลายช่วง) |
| `devices.service_unverified_before` | ก่อนวันไหนที่ยังยืนยันย้อนหลังไม่ได้ — `NULL` คือยืนยันครบทุกช่วงเวลา |

ชิ้นที่สามจำเป็นเพราะ Q21: ผู้ดูแลที่เดินไปดูเครื่องตอบข้อเท็จจริงปัจจุบันได้ทันที แต่ตอบย้อนหลังได้ต่อเมื่อมีเอกสาร ถ้าเก็บแค่ช่วง เดือนก่อนหน้าที่ไม่มีช่วงครอบคลุมจะถูกนับเป็น "ไม่ต้องกรอก" ซึ่งเป็นการสรุปแทนการบอกว่าไม่รู้ — เป็นบั๊กชนิดเดียวกับที่ ADR นี้ตั้งใจกัน เพียงแต่ย้ายไปโผล่อีกที่

ผลที่ตามมาคือความครบถ้วนมีสถานะที่สามคือ `indeterminate` (ยืนยันไม่ได้) แยกจาก `complete` และ `overdue` ตราบใดที่เดือนหนึ่งยังมีเครื่องที่ยืนยันไม่ได้ ระบบจะไม่ประกาศทั้งสองคำ — ดู [ขอบเขต API](../reference/api.md)

## สิ่งที่ migration ทำและไม่ทำ

`migration_add_device_service_period.sql` เพิ่มคอลัมน์และตารางเปล่า **ไม่เติมข้อมูลย้อนหลังให้เลยสักแถว** ต่างจาก migration ของประวัติการย้ายที่ backfill ช่วงปัจจุบันให้ทุกเครื่อง เพราะ Q14 และ Q21 ห้ามอนุมานสถานะการติดตั้งจากสิ่งใดก็ตามที่มีอยู่แล้วในระบบ

เครื่องเดิมทุกเครื่องจึงเริ่มต้นที่ "ยังไม่ตรวจยืนยัน" และแดชบอร์ดจะรายงานความครบถ้วนว่ายืนยันไม่ได้พร้อมจำนวนที่เหลือ จนกว่าผู้ดูแลจะไล่ตรวจครบผ่านหน้า `/admin/installation-review`

## สิ่งที่ยังไม่ได้ทำ

ยังไม่มีเครื่องมือตรวจยืนยันทีละหลายเครื่องพร้อมกัน ถ้าจำนวนเครื่องที่ต้องไล่ตรวจมากจนการกดทีละเครื่องไม่สมเหตุสมผล ให้เพิ่มทีหลังโดยยังบังคับให้ผู้ดูแลตอบคำถามสองข้อเดิม (ติดตั้งแล้วหรือยัง และยืนยันย้อนหลังได้ไหม) ต่อกลุ่มที่เลือก ห้ามมีปุ่มที่ตั้งค่าให้ทุกเครื่องรวดเดียวโดยไม่ถาม
