# 0012 — ถอดเซิร์ฟเวอร์ MCP ออกจาก repository

**สถานะ:** Accepted

แทนที่ [ADR-0011](0011-read-only-mcp-server.md)

## บริบท

ADR-0011 เพิ่ม `apps/mcp/` เพื่อแก้ปัญหาที่ว่า "คนที่อยากรู้ตัวเลขกับคนที่ใช้ระบบเป็น
เป็นคนละคนกัน" ข้อวิเคราะห์ปัญหานั้นยังถูกอยู่ สิ่งที่เปลี่ยนคือสิ่งที่รู้เพิ่มหลังจาก
สร้างเสร็จ

**ไม่มีผู้ใช้จริงสักคน** — เซิร์ฟเวอร์นี้เป็น stdio ผู้ใช้แต่ละคนต้องติดตั้ง repository
บนเครื่องตัวเอง แก้ไฟล์ตั้งค่าของผู้ช่วย AI และมีบัญชีแยกในระบบ ผู้บริหารและหัวหน้าฝ่าย
ที่เป็นกลุ่มเป้าหมายไม่ได้ทำสามอย่างนี้ และไม่มีแผนที่จะทำ ระยะทางจากปัญหาไปถึงทางแก้
จึงยาวกว่าที่ ADR-0011 ประเมินไว้มาก

**การตรวจวันที่ 7 กันยายน 2569 พบว่าคำตอบผิดสามจุด** และทั้งสามจุดผิดแบบเงียบ คือ
ตอบเป็นตัวเลขที่ดูสมเหตุสมผลแต่ไม่ตรงกับที่ถาม

- `find_devices({unassigned: false})` กรองกลับด้าน เพราะ `String(false)` ผ่าน
  `z.coerce.boolean()` แล้วกลายเป็น `true`
- `department_usage` แบบเรียงตามค่าใช้จ่าย ไม่ได้ sort หลังรวมแผนกจากทุกฝ่าย
  แผนกที่ใช้งบสูงสุดจึงหลุดออกจาก 20 อันดับแรกได้
- `department_usage` ที่ระบุเดือน แสดงยอดรวมทั้งปีแทนยอดของเดือนที่ถาม

ความผิดพลาดแบบนี้อันตรายกว่าการไม่มีเครื่องมือเลย เพราะคำตอบมาถึงผู้บริหารในรูปประโยค
ภาษาไทยที่อ่านแล้วเชื่อได้ ไม่มีตัวกรองบนหน้าจอให้เห็นว่ากรองอะไรอยู่

**ข้อแรกไม่ได้หายไปพร้อมกับ MCP** — ต้นตอของการกรองกลับด้านคือ `z.coerce.boolean()`
ที่ `apps/api/src/devices/controller.js` ซึ่งอยู่ในชั้น API และ **ยังไม่ได้แก้** ตอนที่เขียน
ADR ฉบับนี้ `GET /devices?unassigned=false` จึงยังตอบผิดให้ทุกฝั่งที่เรียก รวมถึงหน้าเว็บ
การถอด MCP ออกลบเพียงผู้เรียกรายหนึ่ง ไม่ใช่ตัวบั๊ก — ส่วนอีกสองข้อเป็นตรรกะที่อยู่ใน
`apps/mcp/` เองและหายไปพร้อมกับโค้ดจริง

**ต้นทุนการดูแลไม่เป็นศูนย์** — เครื่องมือทั้งห้าตัวอ่านผลจาก endpoint ของแดชบอร์ด
ทุกครั้งที่รูปแบบคำตอบของ API เปลี่ยน ต้องแก้ที่นี่ด้วย และต้องมีเทสอีกชุดกันไม่ให้
ใครเผลอเพิ่มเครื่องมือที่เขียนข้อมูล

## การตัดสินใจ

**ลบ `apps/mcp/` ทั้ง workspace พร้อม `docs/how-to/connect-mcp.md` ออกจาก repository**

ไม่ใช่การปิดการใช้งานไว้ ไม่ใช่การ deprecate — ลบออกจริง โค้ดกู้คืนได้จาก git ที่
commit `61e9eb2` ถ้าวันหนึ่งมีผู้ใช้จริง

ข้อจำกัดสองข้อของ ADR-0011 ที่ยังมีผลต่อไปแม้เซิร์ฟเวอร์จะหายไป และย้ายไปอยู่ใน
`AGENTS.md` แล้ว:

- **ทุกอย่างที่แตะข้อมูลต้องผ่าน HTTP API เดิม ห้ามต่อ MySQL ตรง** — กฎสิทธิ์ทั้งหมด
  อยู่ในชั้น API ทางเข้าที่สองแปลว่าต้องเขียนกฎซ้ำแล้วรอวันที่ไม่ตรงกัน
- **ถ้าวันหลังต่อเครื่องมือ AI เข้าระบบอีก ต้องอ่านอย่างเดียว** — ข้อมูลขาเข้าของ
  เครื่องมือ AI มาจากโมเดล ไม่ใช่จากผู้ใช้ที่กดยืนยัน ยอดพิมพ์คือฐานของทุกบาทในระบบนี้

## ทางเลือกที่พิจารณาแล้วไม่เลือก

**แก้บั๊กสามข้อแล้วเก็บไว้** — แก้ได้ไม่ยาก แต่ไม่ตอบคำถามว่าใครจะใช้ ถ้ายังไม่มีผู้ใช้
การแก้ให้ถูกก็คือการดูแลโค้ดที่ไม่มีใครเรียก และบั๊กชุดต่อไปจะโผล่ตอนรูปแบบ API เปลี่ยน
โดยไม่มีใครสังเกตเห็นเหมือนเดิม

**เก็บไว้เฉยๆ ไม่ต้องแก้ ไม่ต้องลบ** — แย่ที่สุดในสามทาง เพราะเครื่องมือที่ยังต่อได้
แต่ตอบผิด อันตรายกว่าเครื่องมือที่ไม่มี และ `AGENTS.md` ยังต้องแบกกฎที่ปกป้องมันอยู่

**ทำเป็น HTTP MCP server ให้ต่อง่ายขึ้น แทนที่จะลบ** — แก้เรื่อง "ติดตั้งยาก" ได้จริง
แต่แลกกับบริการที่ต้องเปิดพอร์ต ดูแลสิทธิ์ และเฝ้าอีกตัว ซึ่งเป็นการลงทุนก้อนใหญ่กว่าเดิม
สำหรับความต้องการที่ยังไม่มีใครยืนยัน — ถ้าจะทำ ต้องมีผู้ใช้ที่ขอมาก่อน

## ผลที่ตามมา

- npm workspace เหลือ `apps/api`, `apps/web`, `packages/domain` — `@modelcontextprotocol/sdk`
  หลุดออกจาก dependency tree
- ความต้องการ "ถามข้อมูลเป็นภาษาพูด" **กลับไปเป็นปัญหาที่ยังไม่มีทางแก้** ตามที่
  ADR-0011 อธิบายไว้ ไม่ใช่ปัญหาที่ถูกตัดสินว่าไม่สำคัญ — ถ้ากลับมาทำอีกครั้ง ให้เริ่ม
  จากการหาผู้ใช้ที่ยืนยันว่าจะใช้ ก่อนเขียนเครื่องมือตัวแรก
- ตัวเลขจากระบบนี้กลับมามีทางออกทางเดียวคือหน้าเว็บ ซึ่งเห็นตัวกรองที่ใช้อยู่เสมอ
