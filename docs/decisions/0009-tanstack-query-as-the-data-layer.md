# 0009 — ใช้ TanStack Query เป็นชั้นดึงข้อมูลของฝั่งเว็บ

**สถานะ:** Accepted

## บริบท

ทุกหน้าดึงข้อมูลเองด้วย axios ตรงๆ ใน `onMounted` แล้วเก็บลง `ref` พร้อมตัวแปร
`loading` และ `error` ของตัวเอง รูปแบบนี้ทำงานได้ แต่พอมีสิบกว่าหน้าก็เริ่มเห็นผล

- **ยิงซ้ำโดยไม่จำเป็น** — รายชื่ออาคาร ชั้น ฝ่าย แผนก ยี่ห้อ ถูกดึงใหม่ทุกครั้งที่
  เปลี่ยนหน้า ทั้งที่แทบไม่เคยเปลี่ยน หน้าเดียวอย่างทะเบียนทรัพย์สินยิงหกคำขอ
  ตอนเปิด แล้วหน้าถัดไปยิงชุดเดิมซ้ำอีก
- **หน้าเดียวยิงซ้ำในตัวเอง** — บนแดชบอร์ด กราฟแนวโน้ม เส้นแนวโน้มจิ๋วบนการ์ด KPI
  และรายชื่อเดือนของตัวเลือกช่วงเวลา ต้องการข้อมูลก้อนเดียวกัน แต่ต่างคนต่างยิง
- **โค้ดจัดการสถานะซ้ำกันทุกไฟล์** — `loading` / `error` / `try-catch` ชุดเดียวกัน
  ถูกคัดลอกไปกว่าสิบที่ แล้วค่อยๆ เขียนไม่เหมือนกัน
- **ไม่มีการรีเฟรชเบื้องหลัง** — เปิดหน้าทิ้งไว้ทั้งวันแล้วตัวเลขไม่เคยอัปเดต
  จนกว่าจะกด F5 เอง ซึ่งเป็นเรื่องจริงในห้องที่เปิดแดชบอร์ดค้างไว้บนจอติดผนัง
- **กระพริบทุกครั้งที่เปลี่ยนตัวกรอง** — กราฟถูกแทนที่ด้วยโครงร่างแล้วค่อยกลับมา
  ทำให้เลย์เอาต์กระโดดและอ่านต่อไม่ได้

## การตัดสินใจ

**ใช้ TanStack Query (`@tanstack/vue-query`) เป็นชั้นดึงข้อมูลกลาง** โดยรวม query
ทั้งหมดไว้ที่ `apps/web/src/api/queries.js` ที่เดียว

ขอบเขตที่ตั้งใจจำกัดไว้

| ใช้ TanStack Query | ยังยิง axios ตรงๆ |
|---|---|
| ข้อมูลที่ **อ่านซ้ำ** ข้ามหน้าและข้าม component (ข้อมูลอ้างอิง, ทะเบียนเครื่อง, ยอดรายเดือน) | การ **เขียน** ทั้งหมด (POST/PUT/DELETE) |
| | ข้อมูลที่หน้าเดียวใช้และไม่มีใครใช้ซ้ำ |

ไม่ย้ายทุกอย่างในคราวเดียวโดยตั้งใจ — การเขียนข้อมูลในระบบนี้ตามด้วยการโหลดใหม่
ทันทีอยู่แล้ว และการห่อด้วย mutation ไม่ได้เพิ่มอะไรนอกจากชั้นที่ต้องอ่านเพิ่ม

ค่าอายุของ cache แบ่งเป็นสองระดับตามความถี่ที่ข้อมูลเปลี่ยนจริง

- **ข้อมูลอ้างอิง** (อาคาร ชั้น ฝ่าย แผนก ยี่ห้อ สัญญา) — 30 นาที
  อาคารกับแผนกเปลี่ยนปีละไม่กี่ครั้ง การถือไว้ครึ่งชั่วโมงจึงไม่มีทางแสดงผลผิด
  ส่วนหน้า Admin ที่ *แก้* ข้อมูลเหล่านี้ยังยิงตรงเอง จึงเห็นผลทันทีเสมอ
- **ข้อมูลปฏิบัติการ** (ทะเบียนเครื่อง ยอดรายเดือน) — 2 นาที
  ยังตัดการยิงซ้ำตอนสลับหน้าได้ แต่ไม่ค้างจนตัวเลขเก่าเกินไป

`refetchOnWindowFocus` ถูกปิด — คนที่นี่สลับไปโปรแกรมอื่นแล้วกลับมาตลอดเวลา
การยิงใหม่ทุกครั้งที่กลับมาที่แท็บทำให้ตัวเลขขยับเองระหว่างที่กำลังอ่านอยู่

## ทางเลือกที่พิจารณาแล้วไม่เลือก

**เขียน cache เองใน store** — ทำได้และไม่ต้องเพิ่ม dependency แต่สิ่งที่ต้องเขียนเอง
ไม่ได้มีแค่ Map: การยุบคำขอที่ซ้อนกัน การจัดการ race condition เมื่อตัวกรองเปลี่ยน
เร็วกว่าที่ API ตอบ การหมดอายุ การเก็บกวาดหน่วยความจำ และการคงข้อมูลเดิมไว้
ระหว่างโหลดชุดใหม่ ทั้งหมดนี้คือสิ่งที่ไลบรารีนี้ถูกสร้างมาเพื่อแก้ และเป็นจุดที่
การเขียนเองผิดแบบเงียบๆ ได้ง่ายมาก

**Pinia + action ที่จำผลลัพธ์ไว้** — แก้เรื่องยิงซ้ำได้ แต่ไม่ได้เรื่องอายุของข้อมูล
การรีเฟรชเบื้องหลัง หรือการคงภาพเดิมไว้ระหว่างโหลด และสุดท้ายก็ต้องเขียนกลไก
เดียวกันขึ้นมาเองอยู่ดี — เท่ากับเลือก "เขียนเอง" โดยเรียกชื่ออื่น

**ปล่อยไว้แบบเดิม** — ต้นทุนไม่ได้อยู่ที่ความสวยของโค้ด แต่อยู่ที่จำนวนคำขอที่
เครื่องรุ่นเก่าในโรงพยาบาลต้องรอจริงทุกครั้งที่เปลี่ยนหน้า

## ผลที่ตามมา

- เปิดหน้าที่สองที่ใช้ข้อมูลอ้างอิงชุดเดิม **ไม่ยิงคำขอเลย** ได้จาก cache ทันที
- บนแดชบอร์ด กราฟใหญ่กับเส้นแนวโน้มจิ๋วบนการ์ด KPI ใช้คำขอเดียวกัน จากเดิมสองคำขอ
- เปลี่ยนตัวกรองแล้วกราฟเดิมค้างไว้แบบจางจนของใหม่มาถึง (`placeholderData`)
  ไม่มีการกระพริบเป็นโครงร่างและเลย์เอาต์ไม่กระโดด
- เพิ่ม dependency หนึ่งตัวที่ต้องดูแลต่อ เป็นของฝั่งเว็บเท่านั้น ไม่กระทบ API
- **ข้อควรระวังที่ต้องรู้:** ถ้าเพิ่มหน้าที่แก้ข้อมูลอ้างอิงในอนาคต ต้องสั่ง
  `queryClient.invalidateQueries` ของ key นั้นหลังบันทึก ไม่งั้นหน้าอื่นจะเห็น
  ข้อมูลเก่าได้นานถึง 30 นาที — key ทั้งหมดรวมอยู่ที่ `keys` ใน `api/queries.js`
