# 0031 — ลบงานนำเข้าที่ไม่เคยบันทึกทิ้งถาวรได้ และงานนำเข้าเป็นทางเดียวของการนำเข้า

- สถานะ: Accepted
- วันที่: 2026-09-24
- Issue: #192 · แก้ส่วน "เก็บประวัติเสมอ" ของ [ADR-0027](0027-import-session-lifecycle.md)

## บริบท

ADR-0027 ให้งานที่หมดอายุหรือถูกยกเลิกเก็บไว้เสมอ "และลบทิ้งภายหลังได้" แต่ยังไม่มีทางลบ ผู้ดูแลที่ลองอัปโหลดไฟล์แล้วยกเลิก
เห็นงานค้างในรายการตลอดไป ส่วนงานที่ไม่เคยบันทึก ประวัติของมันไม่ได้ตอบคำถาม "ข้อมูลนี้มาจากไหน" เพราะไม่มีข้อมูลในระบบมาจากงานนั้น

อีกเรื่อง: API ยังมีเส้นทางนำเข้าเดิม `POST /devices/import` และ `POST /print-transactions/import` ที่หน้าเว็บเลิกใช้ตั้งแต่ #180
สองเส้นทางนี้เขียนเครื่องและยอดโดยไม่มีเลขงาน ไม่มีประวัติ และไม่ผ่านกฎของ ADR-0028 — ทางที่สองที่เขียนข้อมูลคิดเงินได้โดยไม่เหลือร่องรอย

## การตัดสินใจ

1. **ลบถาวรได้เฉพาะงานที่ `expired` และไม่เคยบันทึก** (`completed_at` ว่าง และไม่มีเครื่องหรือยอดอ้างถึง — ตรวจใน transaction เดียวกับการลบ
   ด้วย `FOR UPDATE`) ลบทั้งแถว ประวัติ และไฟล์ แถวหายจากฐาน จึงเขียนหนึ่งบรรทัดลง log ของเซิร์ฟเวอร์: เลขงาน ชื่อไฟล์ sha256 เจ้าของ ผู้ลบ
   `DELETE /api/import-sessions/:id` ตอบ 204 หรือ 409 `import_session_not_purgeable`
2. **งานที่บันทึกแล้วลบไม่ได้** — เป็นที่มาของเครื่องและยอด ถ้าต้องการเอาข้อมูลที่นำเข้าผิดออก ต้องเป็นความสามารถ "ย้อนการนำเข้า" แยกต่างหาก
3. **ถอดเส้นทางนำเข้าเดิม** พร้อม `scripts/load-vendor-workbooks.cjs` ที่ใช้มัน — งานนำเข้า (โหมดอัตโนมัติของ [ADR-0030](0030-automatic-import.md))
   ทำสิ่งที่สคริปต์ทำได้ครบผ่านหน้าเว็บ

## ผลที่ตามมา

- มีทางเดียวที่ไฟล์เข้าระบบได้ ทุกเครื่องและยอดที่นำเข้ามีเลขงานและประวัติ
- สคริปต์หรือเครื่องมือภายนอกที่เคยเรียกเส้นทางเดิมต้องเปลี่ยนไปใช้ `/api/import-sessions`
- การลบไม่มีทางกู้จากในระบบ — กู้ได้จาก backup รายวันเท่านั้น (งานเหล่านี้ไม่มีข้อมูลธุรกิจ)
