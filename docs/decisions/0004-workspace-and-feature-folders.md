# 0004 — จัด repository เป็น workspace และแบ่งโค้ดตามความสามารถ

**สถานะ:** Accepted

## บริบท

โครงสร้างเดิมมีสองโปรเจกต์แยกกันที่ราก คือ `backend/` และ `frontend/` แต่ละตัวมี `package.json` ของตัวเอง ไม่มีอะไรผูกไว้ ผลที่ตามมา:

- **แชร์โค้ดกันไม่ได้เลย** ตรรกะปีงบจึงถูกเขียนสองรอบ ครั้งหนึ่งใน `backend/utils/fiscalYear.js` อีกครั้งใน `frontend/src/store/fiscalYear.js` แล้วเพี้ยนคนละทาง — ฝั่ง backend ใช้ ต.ค.–ก.ย. ถูก ส่วนฝั่ง frontend เดาเป็น ม.ค.–ธ.ค. ผิด นี่คือต้นเหตุของ [ADR-0001](0001-thai-fiscal-year-oct-sep.md)
- ต้อง `npm install` แยกสองรอบ และไม่มีคำสั่งเดียวที่รันเทสหรือ build ทั้ง repo ได้

ภายใน `backend/` โค้ดถูกแบ่งตามชนิดของไฟล์ (`routes/`, `controllers/`, `middlewares/`, `utils/`) การแก้ฟีเจอร์เดียวจึงต้องเปิดสามถึงสี่โฟลเดอร์ และชื่อโฟลเดอร์ไม่บอกเลยว่าระบบนี้ทำอะไร

## การตัดสินใจ

**หนึ่ง — ยุบเป็น npm workspace เดียว** แยกสองระดับตามธรรมเนียมที่ใช้กันทั่วไป

```
apps/         สิ่งที่ deploy ได้จริง มี entry point ของตัวเอง
  api/        Express API (ย้ายมาจาก backend/)
  web/        Vue SPA (ย้ายมาจาก frontend/)
packages/     โค้ดที่ apps ใช้ร่วมกัน ไม่ deploy เดี่ยว
  domain/     ปีงบ เดือน และกฎธุรกิจ พร้อมเทส
```

`packages/domain` เป็น CommonJS เพื่อให้ `apps/api` require ได้ตรงๆ ส่วน Vite ฝั่ง `apps/web` pre-bundle CommonJS ให้อยู่แล้ว

**สอง — ภายใน `apps/api` แบ่งโค้ดตามความสามารถ ไม่ใช่ตามชนิดไฟล์**

```
src/
  devices/        ทะเบียนเครื่อง
  print-usage/    ยอดพิมพ์และการนำเข้ามิเตอร์
  expense/        ค่าใช้จ่ายตามสัญญา
  dashboard/      รายงานรวม
  master-data/    ข้อมูลอ้างอิงและสัญญา
  auth/           ล็อกอินและสิทธิ์
  users/          จัดการผู้ใช้
  shared/         db และของที่ใช้ร่วมจริงๆ
```

## ทางเลือกที่พิจารณาแล้วไม่เลือก

**คงสองโปรเจกต์แยก แล้ว copy ตรรกะที่ใช้ร่วม** — เป็นสิ่งที่ทำอยู่เดิม และเป็นสาเหตุที่ปีงบเพี้ยนคนละทางสองฝั่ง

**แยกเป็นสอง repository** — ทำให้การเปลี่ยนที่กระทบทั้งสองฝั่งต้องเปิดสอง PR ที่ต้อง merge พร้อมกัน สำหรับทีมสองคนนี่คือต้นทุนล้วนๆ

**ใช้ Nx หรือ Turborepo** — ให้ cache และ task graph ที่ดี แต่เพิ่มเครื่องมือที่ต้องเรียนรู้และดูแล ขนาดโปรเจกต์ตอนนี้ npm workspaces พอแล้ว ค่อยเพิ่มเมื่อเวลา build เริ่มเป็นปัญหาจริง

## ผลที่ตามมา

- `npm install` ครั้งเดียวที่รากติดตั้งให้ทุก workspace และ hoist dependency ที่ใช้ร่วมกัน
- กฎธุรกิจใหม่ที่ทั้งสองฝั่งต้องเห็นตรงกัน ต้องไปอยู่ใน `packages/domain` ห้ามเขียนซ้ำ
- path ใน script, Dockerfile และเอกสารที่อ้าง `backend/` หรือ `frontend/` ต้องแก้ทั้งหมด
- โค้ดที่ย้ายในการ refactor นี้ **ไม่มีการเปลี่ยนพฤติกรรม** commit ที่ย้ายไฟล์แยกจาก commit ที่แก้ตรรกะเสมอ เพื่อให้ review และ bisect ได้จริง
