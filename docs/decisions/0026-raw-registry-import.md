# 0026 — นำเข้าทะเบียนเครื่องจากไฟล์ดิบ: ตรวจก่อน ให้คนตัดสินชื่อ และเติมเฉพาะช่องที่ว่าง

**สถานะ:** Accepted — ผู้ใช้อนุมัติให้เริ่มเมื่อ 2026-09-22 (#132)

## บริบท

ตัวนำเข้าทะเบียนรับได้เฉพาะเทมเพลตของระบบ ไฟล์ที่หน่วยงานมีจริงคือรายงานสถานะเครื่องของผู้ให้เช่า
(หลายแผ่น หัวรายงานก่อนหัวตาราง คอลัมน์สะกดหลายแบบ ไม่มีคอลัมน์ยี่ห้อ) และรายงานมิเตอร์ ซึ่งเป็น
แหล่งเดียวของเครื่องสัญญา SUTH192/2568 การแปลงไฟล์มือทุกครั้งคือเหตุผลที่ผู้ใช้บอกว่าระบบ "ใช้ไม่ได้จริง"

ตัวนำเข้าเดิมยังบันทึกแถวที่ผ่านทันที ไม่มีขั้นตรวจ ชื่อที่ไม่ตรงทุกตัวอักษรทำให้แถวถูกข้าม และ
เครื่องที่มีอยู่แล้วชน UNIQUE ทั้งไฟล์

## การตัดสินใจ

- **ตรวจก่อน บันทึกทีหลัง** (`mode=preview` / `commit`) เหมือนหน้ายอดมิเตอร์ แต่ไม่มี token ระหว่างสองขั้น —
  commit วางแผนใหม่จากไฟล์และข้อมูลปัจจุบันทุกครั้ง และบันทึกทั้งก้อนใน transaction เดียว
- **ไม่เดาชื่อ** ยี่ห้อ อาคาร ฝ่าย ที่จับคู่ไม่ได้ต้องมีคนเลือก "สร้างใหม่ (ชื่อทางการ)" หรือ "ชื่อเรียกอื่นของ…"
  สิ่งที่เลือกถูกบันทึกเป็นชื่อเรียกอื่น (ADR-0025) ไฟล์ครั้งถัดไปจึงไม่ถามซ้ำ ชั้นและแผนกสร้างใต้รายการแม่ได้เลย
- **หมวดมิเตอร์เลือกต่อรุ่น** ไม่ใช่ต่อเครื่อง และรุ่นที่มีในระบบแล้วใช้หมวดของเครื่องเดิม เครื่องที่มีสัญญา
  ต้องมีหมวดที่สัญญามีราคา ไม่งั้นยอดแรกจะหาราคาไม่ได้ (ADR-0021)
- **สถานะการติดตั้งจากหลักฐานในไฟล์** ผ่อน Q18 ของ ADR-0018 เฉพาะไฟล์ที่มีหลักฐาน: รายงานสถานะเครื่อง
  (หรือสถานะ "completed") และยอดในรายงานมิเตอร์ = ติดตั้งแล้ว, "รอจุดติดตั้ง" ในช่องใดก็ตาม = ยังไม่ติดตั้ง
  เทมเพลต ค่าสถานะที่ไม่รู้จัก และเครื่องที่ไม่มียอดสักงวด คงเป็น NULL ให้ผ่านหน้าตรวจยืนยัน (Q19)
- **Q21 ยังมีผลเต็ม — ยืนยันย้อนหลังเฉพาะเมื่อไฟล์ระบุวันติดตั้ง** ไม่มีวัน = เริ่มรับผิดชอบยอดตั้งแต่วันแรกที่มี
  หลักฐาน (วันนี้ หรือวันเริ่มงวดแรกที่มียอดในรายงานมิเตอร์) และก่อนหน้านั้น "ยืนยันไม่ได้" ไม่อนุมานจากวันเริ่มสัญญา
  วันติดตั้งที่อยู่ก่อนเดือนเริ่มสัญญาเลื่อนเป็นวันเริ่มสัญญา เพราะเดือนก่อนสัญญาไม่มีราคา
- **ช่วงประวัติที่ตั้งแรกเริ่มที่วันเริ่มสัญญา** ไม่ใช่วันนำเข้า — ยอดย้อนหลังในไฟล์ต้องอยู่กับหน่วยงานนั้นแม้เครื่อง
  ย้ายทีหลัง (ADR-0014) วันที่ในไฟล์อ่านจากเซลล์ดิบ (เลขลำดับวันของ Excel) ผ่าน `@suth/domain`
- **เครื่องที่มีอยู่แล้ว: เติมเฉพาะช่องที่ว่าง** ช่องที่ตั้งเติมที่ช่วงประวัติปัจจุบันเพราะเป็นข้อมูลที่ขาด
  ไม่ใช่การย้าย ช่องที่มีค่าต่างจากไฟล์ขึ้นเป็นคำเตือน ไม่ย้ายเครื่องและไม่เปลี่ยนสัญญาให้ ชั้นเติมได้เฉพาะเมื่ออาคาร
  ตรงกัน แผนกเฉพาะเมื่อฝ่ายตรงกัน และไม่เติมที่ตั้งของเครื่องที่เคยย้ายแล้วเลย เพราะไม่รู้ว่าไฟล์หมายถึงช่วงไหน
- **commit วางแผนใหม่ใน transaction เดียวกับการเขียน** และการเติมใช้ `COALESCE` — ค่าที่คนอื่นเติมระหว่างตรวจชนะ
- **เลขซีเรียลที่น่าจะพิมพ์ผิด** (สลับตัวอักษร ตัวที่หน้าตาคล้าย ขีด/ช่องว่าง) เป็นคำเตือน ไม่รวมเครื่องเอง
  เพราะระบบบอกไม่ได้ว่าเลขในไฟล์ไหนถูก ตัวนำเข้ายอดมิเตอร์บอกเลขที่คล้ายในทะเบียนด้วย
- **ไม่อ่านข้อมูลส่วนบุคคล** (ชื่อ ตำแหน่งงาน เบอร์โทรผู้รับการติดตั้ง) และ IP/MAC

## ทางเลือกที่ไม่เลือก

- **จับคู่ชื่อใกล้เคียงอัตโนมัติ** — ดู ADR-0025 ค่าใช้จ่ายลงผิดอาคารโดยไม่มีใครรู้
- **เขียนทับข้อมูลเดิมตามไฟล์** — ไฟล์ของผู้ให้เช่าแต่ละรอบเขียนไม่เหมือนกัน การนำเข้าซ้ำจะย้ายเครื่องไปมา
  และเขียนประวัติการย้ายที่ไม่เคยเกิดขึ้น
- **รวมเครื่องที่ SN คล้ายกันให้เอง** — `WB1B…` กับ `BW1B…` อาจเป็นเครื่องเดียวกันหรือสองเครื่องก็ได้

## ผลที่ตามมา

- API ตอบรูปแบบใหม่ (`summary`, `unresolved`, `models`, `rows`, `choices`) หน้าเว็บเดิมที่อ่าน `inserted`/`skipped` ถูกแทนทั้งหมด
- `import/row-rules.js` ถูกรวมเข้าตัววางแผน (`import/registry-plan.js`) — กฎความยาวคอลัมน์ของ #85 ยังอยู่พร้อมเทส
- กฎสร้างชื่อหลักและชื่อเรียกอื่นย้ายไป `master-data/lookup-writes.js` ใช้ทั้งหน้าข้อมูลอ้างอิงและตัวนำเข้า
- ยังไม่มีทางแก้เลขซีเรียลที่พิมพ์ผิดจากหน้าตรวจ ต้องแก้ที่หน้าทะเบียนเครื่อง
