# 0034 — นำเข้าไฟล์: แสดงสิ่งที่จะเกิดก่อน สัญญาและปีงบเป็นแผนจนกว่าจะกดยืนยัน

- สถานะ: Accepted
- วันที่: 2026-09-24
- Issue: #207 · แทนส่วน "บันทึกให้เอง" ของ [ADR-0030](0030-automatic-import.md) · ต่อจาก [ADR-0028](0028-import-commit-strategy.md)

## บริบท

ADR-0030 ให้ช่อง "สร้างข้อมูลที่ขาดและบันทึกให้เลย" เปิดเป็นค่าเริ่มต้น เลือกไฟล์แล้วระบบบันทึกทันที ผู้ใช้เห็นข้อมูลหลังจากที่มัน
เข้าระบบไปแล้ว และขอให้ "แสดงข้อมูลก่อน แล้วค่อยกดยืนยันอีกครั้ง"

ตรวจโค้ดแล้วพบปัญหาที่หนักกว่านั้น: แม้ในโหมดที่ไม่บันทึก ระบบก็ **สร้างสัญญาและปีงบจริงทันที** (ปุ่ม "สร้างสัญญา" ในหน้างานก็เช่นกัน)
ยกเลิกงานแล้วสัญญาและปีงบจากไฟล์นั้นยังค้างในระบบ การเพิ่มแค่หน้าต่างยืนยันหลังอัปโหลดจึงไม่พอ

## การตัดสินใจ

1. **สัญญาและปีงบที่มาจากงานนำเข้าเป็นแผน** — เก็บใน `decisions.planned` ของ session (`contracts` ตามคีย์เลขสัญญา, `fiscal_years`)
   ทั้งจากปุ่มในหน้างานและจากระบบเตรียมให้ `PUT /decisions` ไม่แตะแผน แก้ได้ทาง endpoint ของมันเท่านั้น
2. **`analyse()` เขียนแผนก่อนวางแผนเครื่องและยอด ใน transaction เดียวกัน** — ตรวจ = ลองเขียนแล้วย้อน ผลตรวจจึงเห็นเครื่องผูกสัญญาใหม่
   และยอดหาราคาได้จริง ยืนยัน = แผน ชื่อ เครื่อง และยอดเข้าไปพร้อมกันหรือไม่เข้าเลย (ADR-0028) สัญญาที่มีคนสร้างเลขเดียวกันไว้
   ระหว่างนั้นไม่เขียนซ้ำ ใช้ของในระบบแล้วเทียบกับไฟล์ตามปกติ
3. **ระบบเตรียมให้ แต่ไม่บันทึก** — `auto` ทุกค่าไม่เรียก commit อีก (`auto=commit` ของเว็บรุ่นเก่ามีผลเท่า `resolve`) การบันทึกมีทางเดียว
   คือ `POST /commit` ที่ผู้ดูแลกด ตรงกับกฎ "การบันทึกต้องเป็นการกระทำของคน" (AGENTS.md, ADR-0012)
4. **ผลตรวจมี `preview`** — สัญญาใหม่ (อายุ ค่าเช่า VAT ราคา) ปีงบ ชื่อและชื่อเรียกอื่นใหม่ ชั้น แผนก เครื่องที่จะสร้าง/เติม ยอดใหม่
   ยอดที่จะแทนที่ เลขซีเรียลที่คล้ายของเดิม ยอดตามใบแจ้งหนี้หลังบันทึก และ `writes` = จำนวนรายการที่จะเขียน ปุ่มยืนยันบอกจำนวนนี้
5. **ลายนิ้วมือไม่ขึ้นกับ id ชั่วคราว** — id ของสัญญาในแผนเปลี่ยนทุกครั้งที่ลองเขียน (InnoDB ไม่คืนเลขที่ย้อน) จึงแทนด้วยคีย์ของแผน
   ข้อมูลในระบบเปลี่ยนระหว่างดูสรุปกับกดยืนยัน = ไม่บันทึก แล้วให้ดูผลใหม่ (กลไกเดิมของ ADR-0028)

## ผลที่ตามมา

- ยกเลิกงาน = ไม่มีสัญญา ปีงบ ชื่อ หรือเครื่องจากไฟล์นั้นค้างในระบบ
- ประวัติของงานใหม่มี `contract_planned` / `fiscal_years_planned` แทน `contract_created` / `fiscal_years_created`
  ผลบันทึกบอก `contracts_created` และ `fiscal_years_created`
- ผู้ใช้กดเพิ่มหนึ่งครั้ง (ยืนยัน) เทียบกับ ADR-0030 — ตั้งใจ เพราะผู้ใช้ขอขั้นนี้เอง

## ทางเลือกที่ตัดทิ้ง

**เพิ่มหน้าต่างยืนยันหลังอัปโหลด แต่คงการสร้างสัญญา/ปีงบทันที** — ตัดทิ้งเพราะยกเลิกแล้วยังมีของค้าง ซึ่งคือปัญหาหลัก

**สร้างสัญญาแบบ "ร่าง" ในตาราง contracts แล้วลบเมื่อยกเลิก** — ตัดทิ้งเพราะทุกรายงานต้องรู้จักสถานะร่าง และงานที่หมดอายุโดยไม่มีใครยกเลิก
จะทิ้งร่างไว้ในระบบ
