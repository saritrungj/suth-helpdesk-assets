# 0007 — ปรับปรุงระบบเดิมต่อ ไม่เขียนใหม่

**สถานะ:** Accepted

## บริบท

เคยมีข้อเสนอให้เขียนระบบใหม่ทั้งหมดด้วย stack ใหม่ (Nuxt + TypeScript + PostgreSQL + Docker) เหตุผลตอนนั้นคือระบบเดิมมีปัญหาสะสมหลายข้อพร้อมกัน

- ตรรกะปีงบคำนวณผิดและถูกเขียนซ้ำสองฝั่ง แล้วเพี้ยนคนละทาง
- เดือนถูกเก็บปนกันทั้ง พ.ศ. และ ค.ศ. ทำให้รายงานว่างเปล่าทั้งที่มีข้อมูล
- ค่าใช้จ่ายคำนวณด้วยทศนิยมลอยตัว ยอดรวมคลาดจากการคำนวณมือ
- ไลบรารีอ่านไฟล์ Excel ค้างอยู่ที่รุ่นที่มีช่องโหว่
- token ของ session เก็บใน `localStorage` ซึ่ง JavaScript ทุกตัวอ่านได้
- ที่อยู่ API และ CORS เป็นค่าคงที่ในโค้ด ทำให้ deploy จริงไม่ได้
- ไม่มี automated test และไม่มีข้อตกลงการทำงานที่เขียนไว้

## การตัดสินใจ

**ไม่เขียนใหม่ ปรับปรุงระบบเดิมต่อไป**

เหตุผลคือปัญหาทุกข้อที่ผลักดันให้อยากเขียนใหม่ ถูกแก้ไปแล้วโดยไม่ต้องเขียนใหม่

| ปัญหาเดิม | แก้ด้วย |
|---|---|
| ปีงบผิด เขียนซ้ำสองฝั่ง | [ADR-0001](0001-thai-fiscal-year-oct-sep.md) และ `packages/domain` ตาม [ADR-0004](0004-workspace-and-feature-folders.md) |
| เดือน พ.ศ./ค.ศ. ปนกัน | [ADR-0002](0002-store-months-in-common-era.md) พร้อม `CHECK` constraint |
| คิดเงินด้วย float | `packages/domain/money.cjs` คิดเป็นจำนวนเต็มสตางค์ |
| ช่องโหว่ SheetJS | [ADR-0003](0003-sheetjs-from-vendor-registry.md) |
| token ใน localStorage | [ADR-0006](0006-session-cookie-instead-of-localstorage.md) |
| config hardcode | `VITE_API_BASE_URL` และ `CORS_ORIGIN` |
| ไม่มีเทส | 54 เคสใน 3 workspace |

## ทางเลือกที่พิจารณาแล้วไม่เลือก

**เขียนใหม่ทั้งหมด** — สิ่งที่ได้กลับมาจริงเหลือแค่สองอย่าง คือ TypeScript ทั้งระบบ กับ `EXCLUDE` constraint ของ PostgreSQL ที่กันช่วงเวลาสังกัดแผนกทับกัน ทั้งคู่ทำแบบค่อยเป็นค่อยไปได้ TypeScript ใส่ทีละไฟล์ได้ ส่วนการย้ายฐานข้อมูลเป็น migration ไม่ใช่ rewrite — ระบบเดิมรันต่อได้ระหว่างย้าย

ต้นทุนที่ต้องจ่ายคือทิ้งกฎธุรกิจราว 18,000 บรรทัดที่ผ่านการใช้งานจริงมาแล้ว แล้วค่อยๆ ค้นพบใหม่ทีละข้อผ่านบั๊กที่เกิดกับผู้ใช้จริงในโรงพยาบาล บั๊กปีงบที่ต้องแก้ถึงสองรอบเป็นตัวอย่างว่ากฎเหล่านี้ละเอียดแค่ไหน

**รอไว้ก่อนแล้วค่อยตัดสินทีหลัง** — ไม่เลือกเพราะการปล่อยให้คำถามค้างไว้ทำให้ทุกงานถูกเลื่อนด้วยเหตุผลว่า "เดี๋ยวก็เขียนใหม่อยู่แล้ว" ซึ่งเป็นสาเหตุที่หนี้ทางเทคนิคสะสมตั้งแต่แรก

## ผลที่ตามมา

- งานปรับปรุงต่อจากนี้ทำกับ `apps/api` และ `apps/web` ที่มีอยู่ ไม่ต้องรอ stack ใหม่
- ลำดับที่แนะนำถ้าจะเดินต่อ: ใส่ TypeScript เริ่มจาก `packages/domain` (810 บรรทัด มีเทสครบแล้ว เสี่ยงต่ำสุด) แล้วค่อยขยายออก
- [ADR-0005](0005-database-engine.md) ที่เลือก PostgreSQL ตั้งอยู่บนสมมติฐานว่าจะเขียนใหม่ จึงถูกเลื่อนออกไป ถ้าจะย้ายฐานข้อมูลจริงต้องตัดสินใหม่เป็นเรื่องของตัวเอง
- เงื่อนไขที่จะทำให้กลับมาพิจารณาเขียนใหม่อีกครั้ง คือ **ความต้องการทางธุรกิจเปลี่ยนจนของเดิมตอบไม่ได้** ไม่ใช่เพราะโค้ดไม่สวยหรือ stack ไม่ทันสมัย
