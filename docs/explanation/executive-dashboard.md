# หน้าภาพรวมการพิมพ์

หน้าภาพรวม (`/dashboard`) เป็นหน้าวิเคราะห์หน้าเดียวของระบบ และเป็นศูนย์กลางตัดสินใจสำหรับหัวหน้าหน่วยงาน ตอบว่าช่วงที่เลือกใช้เงินและพิมพ์เท่าไร หน่วยงาน สัญญา สถานที่ หรือเครื่องใดใช้มาก/น้อย และตัวเลขนั้นมาจากรายการใด โดยแสดงข้อมูลปัจจุบันกับย้อนหลังเท่านั้น ไม่คาดการณ์อนาคต

## การนำเสนอ

- ใช้โครงหน้าและธีมกลางเดียวกับทะเบียนและรายงานค่าใช้จ่าย: `UiPageHeader`, `UiCard`, `UiStat` รวมถึงสีพื้น ขอบ มุมโค้ง เงา และขนาดตัวอักษร ไม่ติดธีมเฉพาะ Dashboard ที่เปลือกแอป
- **มีตัวเลือกสองชนิด และชนิดที่เลือกข้อมูลมีชั้นเดียว** ([ADR-0020](../decisions/0020-single-scope-dashboard.md)) — "ตัวกรอง" (ปีงบ ช่วงเวลา ฝ่าย แผนก สัญญา อาคาร เครื่อง) บอกว่าจะดูข้อมูลชุดไหน ส่วน "เปรียบเทียบตาม" บอกว่าจะแบ่งชุดนั้นเป็นเส้นอะไร ทุกช่องของตัวกรองเลือกหลายรายการได้ และเลือกแผนกข้ามฝ่ายได้โดยไม่ต้องเลือกฝ่ายก่อน
- ตัวเลขสำคัญ กราฟ ตาราง แผงรายละเอียด Excel และ CSV อ่านจากแถวชุดเดียวกันเสมอ การเปลี่ยน "เปรียบเทียบตาม" จึงไม่ทำให้ยอดบนการ์ดขยับ เพราะมันไม่ได้เลือกข้อมูล — ไม่ใช่เพราะมีกฎพิเศษกันไว้ บรรทัดเหนือการ์ดบอกขอบเขตที่ใช้อยู่เสมอ
- ปีงบเป็นตัวกรองเหมือนช่วงเวลา เลือกหลายปีเพื่อเทียบได้ (ไม่เกินสามปี) โดยปีที่ใหม่ที่สุดที่เลือกคือปีงบหลักของทั้งแอป ตรงกับที่แถบบนสุดแสดงเสมอ เดือนที่เลือกไว้เป็นเดือนของปีงบหลัก แล้วขยายไปยังปีอื่นตามตำแหน่งเดือนในปีงบ ([ADR-0001](../decisions/0001-thai-fiscal-year-oct-sep.md))
- กราฟวาดได้ไม่เกินแปดกลุ่มตามจำนวนสีที่แยกกันออก เกินกว่านั้นวาดกลุ่มที่ยอดสูงสุดแล้ว **เขียนบนหน้าว่าแสดงกี่จากกี่รายการ** ส่วนตารางและไฟล์ที่ส่งออกมีครบทุกกลุ่ม — ไม่เลือกอันดับให้แทนผู้ใช้โดยไม่บอก
- เปอร์เซ็นต์เทียบช่วงก่อนหน้าใช้เดือนที่ API กำหนด (ยาวเท่ากันและอยู่ในปีงบเดียวกัน) แต่คิดยอดจากรายการชุดเดียวกับช่วงที่ดู ถ้าช่วงใดยังยืนยันราคาไม่ครบหรือไม่มียอดของขอบเขตนั้น จะบอกเหตุผลแทนการแสดงเปอร์เซ็นต์
- การ์ดที่สามนับเครื่องที่มียอดในขอบเขต จำนวนเครื่องในทะเบียนวันนี้และความครบถ้วนทั้งองค์กรเป็นข้อมูลอ้างอิงประกอบ ไม่ใช่ตัวหารของขอบเขตที่เลือก
- ตารางแสดงทุกกลุ่มในขอบเขต ค้นหา เรียงมาก–น้อย/น้อย–มาก แบ่งหน้า และเปิดรายละเอียดถึงเครื่องกับเดือนได้ ส่วน `/compare` และรายงานตามฝ่าย/แผนกเดิมพาเข้าหน้านี้พร้อมแปลงตัวเลือกที่รองรับเป็นตัวกรองของหน้านี้
- ช่วงที่มีตั้งแต่สองเดือนใช้กราฟเส้นหนึ่งเส้นต่อกลุ่ม เดือนเดียวใช้กราฟแท่งแนวนอน เพราะเส้นที่มีจุดเดียวไม่บอกอะไร ทุกมุมมองมีตารางตัวเลขชุดเดียวกับกราฟ
- แสดงเฉพาะเดือนที่มีรายการ เดือนที่บันทึกศูนย์ยังอยู่ ส่วนราคาที่ไม่ยืนยันแสดงขีดแทนศูนย์
- “ยอดพิมพ์” หมายถึงยอดพิมพ์จริงที่บันทึก และแสดงยอดสุทธิหลังหัก 2% ประกอบ ค่าใช้จ่ายยังคำนวณจากยอดสุทธิตามกฎโดเมน
- อันดับมีไว้ชี้จุดที่ควรตรวจสอบ ไม่ใช่ตัดสินความสิ้นเปลือง เพราะยอดรวมขึ้นกับจำนวนเครื่องและลักษณะงานของแต่ละกลุ่ม ไฟล์ส่งออกจึงแสดงจำนวนเครื่องและสถานะข้อมูลประกอบอันดับเสมอ
- ตัวกรองและตัวเลือกทั้งหมดอยู่ใน URL และมีจุดเดียวในโค้ดที่เขียนกลับ (`dashboard-view.js` + watcher เดียวใน `ExecutiveDashboard.vue`) เปิดรายละเอียดแล้วกดย้อนกลับจึงได้มุมมองเดิม และไม่มีตัวกรองตัวไหนถูกตัวอื่นเขียนทับหาย
- การแตะตัวกรองเปลี่ยนแค่ `?query` ของหน้าเดิม ไม่เปลี่ยนเส้นทางและ **ไม่ดึงจอขึ้นบนสุด** — `scrollBehavior` ของ router ยกเว้นการนำทางที่ path เดิม
- งานที่ต้องติดตามอยู่ในลิ้นชักแจ้งเตือนของ Sidebar **ที่เดียว** ไม่มีสำเนาบนหน้านี้ (#83); ข้อจำกัดของตัวเลขแต่ละตัว เช่น "ยังยืนยันราคาไม่ได้ N รายการ" ติดอยู่กับตัวเลขนั้นเอง ส่วนความครบถ้วนของข้อมูลเป็นบริบทของรายงานตาม [ADR-0018](../decisions/0018-separate-installation-status.md)

## การเจาะข้อมูลและส่งออก

กดการ์ดตัวเลขสำคัญเพื่อดูข้อมูลรายเครื่องทั้งหมดตามตัวกรองบนหน้า หรือกดรายการในตารางเพื่อเจาะเฉพาะกลุ่มนั้น แผงรายละเอียดแยกกลุ่มตามแผนก สัญญา เครื่อง หรือเดือนได้ การค้นหาจะกรองทั้งตารางและยอดสรุปในแผง โดยมีช่วงรายงานและสถานะราคากำกับ

บนหน้าจอมีปุ่มส่งออกปุ่มเดียวชื่อ **“ส่งออก”** แล้วเลือกรูปแบบในเมนู ทั้งสองแบบใช้ตัวกรองชุดเดียวกับที่เห็นบนจอเสมอ และต่างกันที่หน้าที่ ไม่ใช่ต่างกันที่นามสกุลไฟล์

| รูปแบบ | เนื้อใน |
|---|---|
| Excel | รายงานหลายแผ่น — “สรุป” “รายเดือน” “เปรียบเทียบ” “อันดับ” (เมื่อใช้ได้) “ข้อมูลรายละเอียด” “คุณภาพข้อมูล” “เงื่อนไขรายงาน” พร้อมกราฟในไฟล์ |
| CSV | ตารางแบนแผ่นเดียวของแถวรายเครื่องรายเดือน สำหรับเอาไปคำนวณต่อ พร้อมป้องกันค่าที่โปรแกรมตารางอาจตีความเป็นสูตร |

เดิมมีสามทางออกในสองปุ่ม (“ส่งออก Excel”, เมนู “ข้อมูลดิบอย่างเดียว” ซึ่งก็เป็น .xlsx และปุ่ม “ส่งออก CSV” อีกปุ่ม) โดยสองในสามมีเนื้อในเหมือนกัน — ตอนนี้เหลือสองอย่างที่ต่างกันจริง

แผ่น “เปรียบเทียบ” มีทุกกลุ่มในขอบเขต ส่วนกราฟในแผ่นนั้นวาดกลุ่มชุดเดียวกับกราฟบนจอ และ “เงื่อนไขรายงาน” เขียนตัวกรองที่ใช้อยู่ออกมาเป็นภาษาคน เพื่อให้ไฟล์เดินทางต่อได้เองโดยไม่ต้องมีหน้าจอกำกับ

แผ่น “อันดับ” มีทุกรายการของมิติที่ดูอยู่เรียงมาก→น้อยตามตัวชี้วัดบนจอ (#115) เกินสิบรายการได้กราฟสองใบคือ 10 อันดับแรกและ 10 อันดับท้าย ไม่เกินสิบได้ใบเดียวที่มีครบทุกรายการ ส่วนแผ่นข้อมูลรายละเอียดเก็บทุกแถวตามตัวกรองบนหน้า เพื่อให้ตรวจย้อนกลับและวิเคราะห์ต่อได้โดยไม่ตกหล่นเพราะเลือกเส้นในกราฟไว้เพียงบางรายการ

ยอดเงินรับจาก HTTP API เดิม รวมผ่านหน่วยสตางค์ใน `packages/domain` โดยไม่หาราคาหรือคำนวณส่วนลดใหม่ การจัดกลุ่มใช้ชื่อและรหัสประวัติที่ API ส่งมา ไม่ย้อนใช้สถานที่ปัจจุบัน ขอบเขตความถูกต้องของราคาขึ้นกับ API ตาม [ADR-0019](../decisions/0019-effective-pricing-history.md): เมื่อราคาไม่ครบ แสดงจำนวนรายการที่ไม่ยืนยันคู่กับยอดเงิน และงดข้อสรุปอันดับกับส่วนต่างค่าใช้จ่าย หากค่าฐานเป็นศูนย์จะแสดงส่วนต่างจริงแต่ไม่คำนวณเปอร์เซ็นต์

## แนวทางอ้างอิง

- [Ramp — Travel admin dashboard and reporting](https://support.ramp.com/travel-admin-dashboard-and-reporting/): เริ่มจากคำถามด้านค่าใช้จ่าย ให้การ์ดและกราฟเปิดรายละเอียดที่แยกกลุ่มและส่งออกได้
- [Tableau — Actions and Dashboards](https://help.tableau.com/current/pro/desktop/en-us/actions_dashboards.htm): ใช้การเลือกข้อมูลในภาพรวมเป็นทางเข้าสู่ขอบเขตรายละเอียด

อ้างอิงพฤติกรรมการวิเคราะห์จากเอกสารของผู้ผลิต ไม่ใช่นำรูปภาพหรือสินทรัพย์จากผลิตภัณฑ์เหล่านั้นมาใช้ในแอป
