# รูปแบบไฟล์นำเข้า

ข้อกำหนดของไฟล์ที่ระบบรับได้ วิธีนำเข้าอยู่ที่ [นำเข้าไฟล์](../how-to/import-files.md)

## ข้อจำกัดร่วม

| หัวข้อ | ค่า |
|---|---|
| นามสกุลที่รับ | `.xlsx`, `.xls`, `.csv` |
| ขนาดสูงสุด | 5 MB |
| ชื่อ form field | `file` |
| สิทธิ์ที่ต้องมี | role `admin` |

## ทะเบียนอุปกรณ์

`POST /api/devices/import` — ตรวจก่อนแล้วค่อยบันทึก ([ADR-0026](../decisions/0026-raw-registry-import.md))

| form field | ค่า |
|---|---|
| `file` | ไฟล์ทะเบียน |
| `mode` | `preview` (ค่าเริ่มต้น) = ตรวจอย่างเดียว · `commit` = บันทึก |
| `decisions` | JSON สิ่งที่ผู้ดูแลเลือกในหน้าตรวจ (ดูด้านล่าง) — ส่งชุดเดียวกันทั้งตอนตรวจและตอนบันทึก |

`commit` วางแผนใหม่จากไฟล์และข้อมูลปัจจุบันทุกครั้ง แล้วบันทึกทั้งก้อนใน transaction เดียว แผนที่ยังไม่ครบถูกปฏิเสธด้วย `import_needs_decisions`

### ไฟล์ที่รับ

| รูปแบบ | ลักษณะ | ระบบอ่านอย่างไร |
|---|---|---|
| เทมเพลตของระบบ | หัวตารางแถวแรก คอลัมน์ตามด้านล่าง | ตรงตัว สถานะการติดตั้งยังไม่รู้ → รอตรวจยืนยันการติดตั้ง |
| รายงานสถานะเครื่องของผู้ให้เช่า | หลายแผ่น (OKI / HP / HP A3) หัวรายงานก่อนหัวตาราง | หาแถวหัวตารางใน 15 แถวแรก อ่านทุกแผ่น เลขที่สัญญาจากหัวรายงาน ทุกแถว = ติดตั้งแล้ว (ยกเว้นสถานะที่ไม่รู้จัก) |
| รายงานมิเตอร์รายงวด ([ADR-0023](../decisions/0023-contract-term-price-lines-and-meters.md)) | หลายแผ่น แผ่นละงวด | หนึ่งเครื่องต่อ SN ที่ตั้งจากแผ่นล่าสุด สองแถวต่อ SN = มีมิเตอร์สี มียอด = ติดตั้งแล้วตั้งแต่งวดแรกที่มียอด ไม่มียอดเลย = รอตรวจยืนยัน |

ชื่อหัวคอลัมน์ที่รับ (ไม่สนตัวพิมพ์และช่องว่าง):

| ช่อง | หัวคอลัมน์ |
|---|---|
| เลขซีเรียล (จำเป็น) | `serial_number`, `Serial Number`, `Serial No.`, `SN.`, `SN`, `S/N`, `เลขซีเรียล`, `หมายเลขเครื่อง` |
| ยี่ห้อ | `brand`, `ยี่ห้อ` — ไม่มีคอลัมน์นี้ = แยกจากชื่อรุ่น (`OKI ES5112` → OKI + ES5112) |
| รุ่น | `model`, `รุ่น` |
| อาคาร / ชั้น | `building`, `อาคาร` / `floor`, `Floor.`, `Fool.`, `ชั้น` |
| ฝ่าย / แผนก | `division`, `ฝ่าย` / `department`, `แผนก`, `Depatment` — คอลัมน์ฝ่ายที่ไม่มีหัวแต่ค่าส่วนใหญ่ขึ้นต้นด้วย "ฝ่าย" ถูกเดาและแจ้งในหน้าตรวจ |
| ตำแหน่ง | `location`, `ตำแหน่งที่ตั้ง`, `Printer Name` — ไม่รับ `ตำแหน่ง` เดี่ยวๆ เพราะในไฟล์ของผู้ให้เช่าคือตำแหน่งงานของผู้รับการติดตั้ง |
| อื่นๆ | `contract_no`, `status`, `Date` (วันติดตั้ง วว/ดด/ปปปป), `meter_category`, `price_override` |

**ไม่อ่าน** ชื่อผู้รับการติดตั้ง ตำแหน่งงาน เบอร์โทร IP และ MAC

ข้อความ "ยังไม่มีจุดติดตั้ง" / "รอจุดติดตั้ง" ในช่องอาคาร ตำแหน่ง หรือสถานะ = เครื่องยังไม่ติดตั้ง ไม่ใช่ชื่ออาคาร

วันติดตั้ง (`Date`) ที่ไฟล์ระบุ = ยืนยันสถานะย้อนหลังได้ตั้งแต่วันนั้น ไม่มีวัน = เริ่มนับตั้งแต่วันแรกที่มีหลักฐาน และก่อนหน้านั้นยืนยันไม่ได้ ([ADR-0018](../decisions/0018-separate-installation-status.md) Q21) เซลล์วันที่ของ Excel อ่านได้ตรง ข้อความต้องเป็น วัน/เดือน/ปี 4 หลัก อ่านไม่ได้ = คำเตือน

### สิ่งที่ผู้ดูแลต้องตัดสินก่อนบันทึก

| สิ่งที่ต้องตัดสิน | ตัวเลือก |
|---|---|
| ยี่ห้อ อาคาร ฝ่าย ที่ไม่ตรงชื่อหลักหรือชื่อเรียกอื่นในระบบ ([ADR-0025](../decisions/0025-master-data-aliases.md)) | สร้างใหม่ (ตั้งชื่อทางการได้ ชื่อในไฟล์กลายเป็นชื่อเรียกอื่น) · เป็นชื่อเรียกอื่นของรายการในระบบ · เป็นชื่อเรียกอื่นของชื่อที่กำลังสร้างในไฟล์เดียวกัน |
| หมวดมิเตอร์ของรุ่นที่มีสัญญา แต่ยังไม่เคยลงในระบบ | เลือกหมวดครั้งเดียวต่อรุ่น และมีมิเตอร์สีหรือไม่ — รุ่นที่เคยลงแล้วใช้หมวดของเครื่องเดิม |
| สัญญาที่ไฟล์ระบุแต่ยังไม่มีในระบบ | สร้างสัญญาที่หน้าสัญญาก่อน |

ชั้นและแผนกที่ยังไม่มี ถูกสร้างใต้อาคาร/ฝ่ายของแถวนั้นเองโดยไม่ต้องถาม ("5" กับ "ชั้น 5" คือชั้นเดียวกัน)

```json
{
  "names": {
    "building": {
      "ศูนย์ความเป็นเลิศทางการแพทย์ (EMC)": { "action": "create", "as": "อาคารศูนย์ความเป็นเลิศทางการแพทย์" },
      "ศูนย์ความเป็นเลิศ": { "action": "alias", "target_new": "ศูนย์ความเป็นเลิศทางการแพทย์ (EMC)" },
      "รัตนเวชพัฒน์ (RVP)": { "action": "alias", "target_id": 2 }
    }
  },
  "models": { "oki|es5112": { "meter_category_id": 2, "has_color_meter": false } }
}
```

### ผลต่อแถว

| ผล | เมื่อไร |
|---|---|
| สร้างใหม่ | SN ยังไม่มีในระบบ — ลงด้วยขั้นตอนเดียวกับฟอร์มเพิ่มเครื่อง (ประวัติที่ตั้ง สถานะการติดตั้ง ช่วงการคิดเงินจากวันเริ่มสัญญา มิเตอร์) |
| เติมช่องที่ว่าง | SN มีแล้ว และบางช่องในระบบยังว่าง — เติมเฉพาะช่องนั้น ช่องที่ตั้งเติมที่ช่วงประวัติปัจจุบัน ไม่ใช่การย้าย ชั้นเติมเฉพาะเมื่ออาคารตรงกัน แผนกเฉพาะเมื่อฝ่ายตรงกัน เครื่องที่เคยย้ายแล้วไม่เติมที่ตั้ง |
| ไม่เปลี่ยน | SN มีแล้ว และไม่มีช่องว่างให้เติม — อาคาร/ชั้น/ฝ่าย/แผนกที่ต่างจากระบบขึ้นเป็นคำเตือน ไม่ย้ายเครื่องให้ ถ้าย้ายจริงให้ย้ายที่หน้าทะเบียน |
| ข้าม | ข้อมูลในแถวใช้ไม่ได้ (ตารางถัดไป) แถวอื่นยังบันทึกได้ |

| กรณีที่ข้ามแถว | เหตุผล |
|---|---|
| เลขซีเรียล / รุ่น / ตำแหน่ง / ชื่อยี่ห้อ อาคาร ชั้น ฝ่าย แผนก ยาวเกินคอลัมน์ | บอกความยาวจริง — ไม่ตัดให้สั้นลงเอง เพราะเลขที่ถูกตัดจะไม่ตรงกับไฟล์ต้นทางอีกต่อไป |
| หมวดที่สัญญาไม่มีราคา หรือมีมิเตอร์สีแต่สัญญาไม่มีราคาสี | ยอดพิมพ์ของเครื่องนั้นจะหาราคาไม่ได้ (ADR-0021) |
| `price_override` ไม่ใช่ตัวเลข | |

คำเตือน (บันทึกได้ แต่ควรตรวจ): SN เดียวกันอยู่หลายแผ่น (ใช้แถวแรก) · SN คล้ายเครื่องที่มีอยู่ ต่างกันแค่สลับตัวอักษร (`WB…` / `BW…`) ตัวที่หน้าตาคล้าย (O/0, I/1) หรือขีดและช่องว่าง · สัญญาหรือที่ตั้งต่างจากในระบบ

| ไฟล์ทั้งไฟล์ | ผล |
|---|---|
| เปิดเป็นตารางไม่ได้ (เช่น HTML ที่เปลี่ยนนามสกุลเป็น `.xlsx`) | `unreadable_file` |
| ไม่มีแผ่นไหนมีคอลัมน์เลขซีเรียลกับรุ่นหรืออาคาร | `registry_not_found` |
| เกิน 60 แผ่น 50,000 แถว หรือ 200 คอลัมน์ | `import_too_large` |

เพดานความยาวอ่านจาก `MAX_LENGTH` ใน `packages/domain/constraints.cjs` ที่เดียว ไม่เขียนตัวเลขซ้ำในโค้ด

ต้นฉบับของเทมเพลตอยู่ที่ตัวแปร `TEMPLATE_CSV` ใน `apps/web/src/components/DeviceImportPanel.vue` และดาวน์โหลดได้จากหน้านำเข้าข้อมูลในระบบ — ที่นั่นคือแหล่งเดียว ไม่มีไฟล์ตัวอย่างเก็บซ้ำใน repository

## ยอดมิเตอร์

`POST /api/print-transactions/import`

ไฟล์ต้นฉบับจากฝ่ายชีท — ไฟล์จริงเก็บนอก repo (เช่น `D:\suth-data\raw\`) เพราะ repo เป็น public และไฟล์มีข้อมูลของหน่วยงาน

| หัวข้อ | รายละเอียด |
|---|---|
| หัวตาราง | อยู่แถวที่ 2 ของชีต แถวแรกเป็นหัวข้อรวมแบบ merge cell |
| คอลัมน์จับคู่เครื่อง | `SN.` |
| คอลัมน์เดือน | ชื่อขึ้นต้นด้วย `meter` ตามด้วยเดือน/ปี พ.ศ. สองหลัก เช่น `meter 9/67`, `meter10/67` |

ระบบหาคอลัมน์เดือนจาก **ชื่อคอลัมน์** ไม่ใช่ตำแหน่ง เพราะไฟล์ต้นฉบับเรียงเดือนเริ่มจากกันยายน ไม่ใช่ตุลาคมตามปีงบ ถ้า map ตามตำแหน่งยอดจะเลื่อนไปทั้งแถว

เดือนที่อ่านได้จะถูกแปลงจาก พ.ศ. เป็น ค.ศ. ก่อนบันทึกเสมอ — ดู [ADR-0002](../decisions/0002-store-months-in-common-era.md)

### กฎการตรวจก่อนบันทึก

ไฟล์ถูกตรวจทั้งไฟล์ก่อน แล้วจึงบันทึกครั้งเดียว — **ไฟล์ที่มีข้อผิดพลาดแม้จุดเดียวจะไม่ถูกบันทึกเลยสักแถว** เพราะไฟล์หนึ่งชุดคือยอดของงวดเดียวกันทั้งชุด ถ้าบันทึกครึ่งไฟล์แล้วค้าง จะไม่มีใครบอกได้ว่ายอดที่เห็นอยู่ครบหรือยัง

| กรณี | ผล |
|---|---|
| `SN.` ที่ไม่มีในทะเบียน | ปฏิเสธทั้งไฟล์ พร้อมเลขแถวและ Serial ที่หาไม่เจอ |
| ยอดไม่ใช่จำนวนเต็ม ติดลบ หรือเกินค่าสูงสุดต่อเดือน | ปฏิเสธทั้งไฟล์ |
| Serial เดียวกันซ้ำในเดือนเดียวกันภายในไฟล์ | ปฏิเสธทั้งไฟล์ — ระบบไม่เลือกให้เองว่าจะเชื่อแถวไหน |
| ช่องว่าง | **ไม่เปลี่ยนข้อมูลเดิม** ไม่ใช่การลบและไม่ใช่การเขียนทับด้วยศูนย์ |
| `0` | เป็นค่าจริง แปลว่าเดือนนั้นไม่มีการพิมพ์ |
| เดือนที่มียอดอยู่แล้ว | ขึ้นเป็นรายการ "จะเขียนทับ" พร้อมค่าเดิมและค่าใหม่ ให้ผู้ใช้เห็นก่อนยืนยัน |

ค่าสูงสุดต่อเดือนอ่านจาก `MAX_PAGES_PER_MONTH` ใน `packages/domain/constraints.cjs` ที่เดียว ไม่เขียนตัวเลขซ้ำไว้ในเอกสาร

### สองขั้น — ตรวจก่อน แล้วจึงยืนยัน

`POST /api/print-transactions/import` รับ `mode` สองค่า

| `mode` | ทำอะไร |
|---|---|
| `preview` (ค่าเริ่มต้น) | ตรวจไฟล์ เทียบกับยอดที่มีอยู่ คืนรายการใหม่ / จะเขียนทับ / ไม่เปลี่ยน พร้อม `preview_token` — **ไม่เขียนฐานข้อมูล** |
| `commit` | บันทึกจริงในทรานแซกชันเดียว ต้องแนบ `preview_token` ที่ได้จากขั้น `preview` |

`preview_token` ผูกกับทั้งตัวไฟล์และยอดเดิมที่มีอยู่ ณ ตอนตรวจ ถ้ามีคนแก้ยอดของเดือนเดียวกันระหว่างที่ผู้ใช้ยังดูหน้าตรวจค้างอยู่ token จะไม่ตรงและระบบจะให้ตรวจใหม่ แทนที่จะเขียนทับค่าที่ผู้ใช้ไม่เคยเห็น

### ไฟล์รายงวดของผู้ให้เช่า

endpoint เดียวกันตรวจรูปแบบไฟล์ผู้ให้เช่าอัตโนมัติจากหัวตารางที่มี Serial และเลขมิเตอร์ต้นงวด/สิ้นงวด (คอลัมน์ราคา `Cost/Click` ไม่บังคับ) ไฟล์มีหลายแผ่นได้ หัวแผ่นต้องมีวันที่สิ้นงวด (พ.ศ. หรือ ค.ศ.) ระบบใช้เดือนของวันที่สิ้นงวดเป็น `month` ถ้าหัวแผ่นมีเลขที่สัญญา ต้องตรงกับสัญญาที่คิดเงินเครื่องนั้นในงวดนั้น

- Serial ต้องมีในทะเบียนแล้ว — หน้านำเข้าไม่สร้างเครื่อง ไม่เลือกหมวด และไม่ย้ายเครื่อง
- แถวแรกของ Serial คือมิเตอร์หลัก (ขาวดำ) แถวที่สองคือมิเตอร์สี เครื่องที่มีสองแถวต้องมีราคาในคอลัมน์ `Cost/Click` ทั้งสองแถว ไม่งั้นถูกปฏิเสธ เพราะลำดับแถวอย่างเดียวบอกไม่ได้ว่าแถวไหนเป็นสี
- ราคาในไฟล์ต้องตรงกับราคาที่ระบบหาได้ของมิเตอร์นั้น — ไม่ตรงแปลว่าหมวดมิเตอร์ของเครื่องหรือรายการราคาในสัญญาผิด
- แถวที่ไม่มีเลขสิ้นงวด (เครื่องสำรอง รอติดตั้ง) ข้ามไป เครื่องที่เปลี่ยนในช่องเดิมมี Serial ใหม่ จึงเป็นอีกเครื่องหนึ่งในทะเบียน
- การลงทะเบียนครั้งแรกจากไฟล์ผู้ให้เช่า (หมวดจากรุ่น เครื่องที่ยังไม่ติดตั้ง ที่ตั้งจากแผ่นล่าสุด) ทำด้วย `scripts/load-vendor-workbooks.cjs` ซึ่งเรียก API ชุดเดียวกันแล้วส่งยอดผ่าน endpoint นี้
- `errors` มี `sheet`, `row`, `serial_number`, `month`, `reason` และบล็อกการบันทึก
- `warnings` ใช้แจ้งเลขต้นงวดไม่ต่อกับเลขสิ้นงวดก่อนหน้า แต่ไม่บล็อกเมื่อผู้ใช้ตรวจแล้ว
- `sheets` สรุปชื่อแผ่น ช่วงวันที่ เดือน และเลขที่สัญญา; `invoice` สรุปเดือน/สัญญา/หมวด/ราคา/หน้าดิบ/หน้าสุทธิ/ยอดเงิน เพื่อเทียบใบแจ้งหนี้ก่อนยืนยัน
