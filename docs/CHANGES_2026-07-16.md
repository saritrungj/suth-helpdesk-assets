## สิ่งที่ต้องทำหลัง pull (สำคัญมาก)

1. `cd backend && npm install` (มีการใช้ bcrypt ซึ่งบางเครื่องยังไม่ได้ลง)
2. **รหัสผ่านใน DB ต้องเป็น bcrypt hash แล้ว** — ถ้า DB เดิมมี user รหัส plaintext อยู่ ให้รัน:
   ```
   cd backend
   node scripts/hash-passwords.js
   ```
   (รันซ้ำได้ ปลอดภัย — รหัสที่เป็น hash แล้วจะถูกข้าม)
   ถ้าสร้าง DB ใหม่จาก `database/schema_normalized.sql` ไม่ต้องทำอะไร seed เป็น hash ให้แล้ว
   - login ทดสอบ: `admin / admin123`, `user1 / user123` (เหมือนเดิม)
3. ไฟล์ที่ถูก **ลบ** (โค้ดตาย ไม่ถูก mount): `backend/server.js`, `backend/routes/master.js`,
   `backend/routes/import.js`, `frontend/src/views/admin/Department.vue`
   → ถ้ามี branch ที่แก้ไฟล์พวกนี้อยู่ให้ย้ายมาที่ `index.js` / `master-data.js` / `importRoutes.js` / `Division.vue`

## Backend — API ที่เปลี่ยน/เพิ่ม

### เปลี่ยนพฤติกรรม (ระวังกระทบ)
| Endpoint | เปลี่ยนอะไร |
|---|---|
| `POST /api/auth/login` | ตรวจรหัสด้วย bcrypt เท่านั้น (เดิมพังกับ seed plaintext), error ตอบ 401 ข้อความกลางๆ กัน username enumeration |
| `POST /api/devices/import` | **ต้อง login + เป็น admin แล้ว** (เดิมเปิดโล่ง), แก้บั๊ก query ตาราง `brands/buildings` → `brand/building`, serial ซ้ำ = อัปเดตแทน error, รองรับคอลัมน์เพิ่ม: floor/ชั้น, division/ฝ่าย, department/แผนก, contract_no/เลขสัญญา (ไฟล์ CSV เดิมยังใช้ได้) และ response มี `skipped[]` บอกแถวที่ข้ามพร้อมเหตุผล |
| `GET /api/devices/:id` | แก้บั๊ก `JOIN floors` → `floor` (เดิม 500 ทุกครั้ง) |
| `GET /api/devices` | เพิ่ม field `status` ใน response |
| `POST/PUT /api/devices` | รับ field `status` (`active`/`repair`/`retired`) เพิ่ม — ไม่ส่งก็ได้ default `active` |
| `DELETE /api/devices/:id` | ลบเครื่องที่มียอดพิมพ์ → ตอบ 409 พร้อมข้อความไทย (เดิม 500) |
| `POST/PUT /api/floors` | รับ `building_id` แล้ว (เดิมบั๊ก — ไม่เคยบันทึก), GET มี `building_name` + filter `?building_id=` |
| `POST/PUT /api/departments` | รับ `division_id` แล้ว (เดิมบั๊กเดียวกัน), GET มี `division_name` + filter `?division_id=` |
| `DELETE` lookup ทุกตัว | ลบแถวที่ถูกอ้างอิง → 409 ข้อความไทย (เดิม 500) |

### เพิ่มใหม่ (ของเดิมไม่กระทบ)
- `PUT /api/fiscal-years/:id`, `DELETE /api/fiscal-years/:id`
- `GET /api/dashboard/monthly-summary` — ยอดรวมรายเดือน (ขับ Dashboard)
- `GET /api/dashboard/top-devices?limit=5` — เครื่องค่าใช้จ่ายสะสมสูงสุด (ขับตาราง Top 5)
- `GET /api/expenses/tree` — โครงสร้าง ปีงบ → สัญญา → เครื่อง → รายเดือน (ขับหน้า Expense)
- `backend/scripts/hash-passwords.js` — สคริปต์แปลงรหัสเก่าเป็น hash
- `backend/scripts/seed-demo-data.js` — seed ข้อมูลเดโม (4 อาคาร, 4 ฝ่าย, 20 เครื่อง,
  ยอดพิมพ์ 6 เดือน ต.ค. 2568 – มี.ค. 2569) รันซ้ำได้ ไม่สร้างข้อมูลซ้ำ ตัวเลข deterministic

## Frontend — โครงสร้างที่เปลี่ยน

- **Router เป็น nested layout แล้ว**: ทุกหน้า (ยกเว้น `/login`) เป็น children ของ `MainLayout`
  → หน้า login ไม่มี sidebar ครอบแล้ว และเมนู admin ขึ้นทันทีหลัง login ไม่ต้อง refresh
  → ถ้าจะเพิ่ม route ใหม่ ให้เพิ่มใน `children` ของ `/` ใน `router/index.js`
- Route ใหม่: `/edit-asset/:id`, `/admin/buildings`, `/admin/divisions`, `/admin/fiscal-years`, `/admin/contracts`
- Guard: `/admin/*`, `/add-asset`, `/edit-asset`, `/import-devices` เข้าได้เฉพาะ admin
