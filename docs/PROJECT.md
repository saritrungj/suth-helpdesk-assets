# ภาพรวมระบบ

เอกสารนี้อธิบายขอบเขต สถาปัตยกรรม และกฎธุรกิจของ SUTH Helpdesk Assets สำหรับนักพัฒนาและ AI agent รายละเอียดการติดตั้งและดูแลระบบอยู่ใน [OPERATIONS.md](OPERATIONS.md)

## เป้าหมาย

ระบบรวมข้อมูลเครื่องพิมพ์และเครื่องถ่ายเอกสารของโรงพยาบาลไว้ในแหล่งเดียว ตั้งแต่ทะเบียนอุปกรณ์ สถานที่ตั้ง หน่วยงาน สัญญา ราคาต่อหน้า และยอดพิมพ์รายเดือน ไปจนถึงรายงานการใช้งานและค่าใช้จ่าย

## บทบาทผู้ใช้

| บทบาท | สิทธิ์หลัก |
|---|---|
| `admin` | ดูข้อมูลและจัดการอุปกรณ์ Master Data สัญญา ผู้ใช้ และการนำเข้า |
| `staff` | ดูข้อมูลและบันทึกยอดพิมพ์รายเดือน |
| `viewer` | ดู Dashboard ทะเบียน และรายงานโดยไม่แก้ข้อมูล |

Backend middleware เป็นขอบเขตความปลอดภัยที่เชื่อถือได้ ส่วนการซ่อนเมนูใน Frontend เป็นเพียงส่วนติดต่อผู้ใช้

## ความสามารถของระบบ

- Dashboard และ KPI ตามเดือน อาคาร ฝ่าย และแผนก
- ทะเบียนอุปกรณ์พร้อมสถานะ `active`, `repair`, `retired`
- ประวัติการย้ายอาคาร ชั้น ตำแหน่ง ฝ่าย และแผนก
- Master Data สำหรับยี่ห้อ อาคาร ชั้น ฝ่าย แผนก และปีงบ
- สัญญาและราคาต่อหน้า รวมถึงราคาที่กำหนดเฉพาะเครื่อง
- การบันทึกยอดพิมพ์ทีละรายการ หลายรายการ หรือครบทั้งปีงบ
- รายงานค่าใช้จ่าย การเปรียบเทียบ และยอดพิมพ์รายเครื่อง
- การนำเข้าทะเบียนอุปกรณ์และยอดมิเตอร์จาก CSV/Excel

## สถาปัตยกรรม

```text
Vue SPA (:5173)
    │ Axios + Bearer JWT
    ▼
Express API (:3000)
    │ mysql2 connection pool
    ▼
MySQL
```

- Frontend route และ navigation อยู่ใน `apps/web/src/router/`
- HTTP client กลางอยู่ใน `apps/web/src/services/api.js`
- Backend entry point อยู่ที่ `apps/api/index.js`
- Route รับ request และ controller ดูแล logic ที่ซับซ้อนกว่า
- `database/schema.sql` เป็น source of truth ของฐานข้อมูลใหม่

## โมเดลข้อมูลหลัก

| กลุ่ม | ตาราง | หน้าที่ |
|---|---|---|
| ผู้ใช้ | `users` | บัญชี รหัสผ่านแบบ bcrypt hash และ role |
| Master Data | `brand`, `building`, `floor`, `division`, `department` | ข้อมูลอ้างอิงของอุปกรณ์และรายงาน |
| ปีงบและสัญญา | `fiscal_year`, `contracts` | ช่วงปีงบและราคาต่อหน้า |
| ทรัพย์สิน | `devices` | ข้อมูลประจำเครื่อง ตำแหน่งปัจจุบัน สัญญา และสถานะ |
| ประวัติ | `device_location_history` | ช่วงเวลาที่เครื่องอยู่แต่ละสถานที่และหน่วยงาน |
| การใช้งาน | `print_transactions` | ยอดพิมพ์หนึ่งรายการต่อเครื่องต่อเดือน |

## กฎธุรกิจสำคัญ

### ปีงบประมาณและเดือน

- ปีงบราชการไทยเริ่มเดือนตุลาคมและสิ้นสุดเดือนกันยายน
- `fiscal_year.year` แสดงเป็น พ.ศ. แต่ `start_month`, `end_month` และ `print_transactions.month` เก็บเป็น ค.ศ. รูปแบบ `YYYY-MM`
- ระบบรับค่าเดือนทั้ง พ.ศ. และ ค.ศ. ที่ขาเข้า แล้ว normalize เป็น ค.ศ. ผ่าน `packages/domain/month.js`
- การแปลงปีงบเป็นช่วงเดือนมี source of truth ที่ `packages/domain/fiscal-year.js`

### ยอดพิมพ์และค่าใช้จ่าย

- `(device_id, month)` ต้องไม่ซ้ำ การบันทึกเดือนเดิมเป็นการ update ยอดเดิม
- จำนวนหน้าสุทธิเท่ากับ `pages × 0.8`
- ราคาที่ใช้คำนวณเรียงลำดับจาก `devices.price_override`, `contracts.price_per_page` และ `0`
- ค่าใช้จ่ายเท่ากับจำนวนหน้าสุทธิคูณราคาที่มีผล

### ประวัติการย้าย

- `devices` เก็บสถานที่และหน่วยงานปัจจุบัน
- `device_location_history` เก็บช่วงย้อนหลัง โดย `effective_to = NULL` หมายถึงช่วงปัจจุบัน
- รายงานย้อนหลังต้องจัดยอดของแต่ละเดือนให้สถานที่และหน่วยงานที่มีผลในเดือนนั้น ไม่ใช้ค่าปัจจุบันย้อนทับอดีต

## ขอบเขต API

| Prefix | หน้าที่ |
|---|---|
| `/api/auth` | Login และออก JWT |
| `/api/devices` | ทะเบียนอุปกรณ์ การย้าย และประวัติ |
| `/api/contracts` | สัญญาและราคา |
| `/api/print-transactions` | ยอดพิมพ์และสรุปตามปีงบ |
| `/api/dashboard` | KPI รายงาน และการเปรียบเทียบ |
| `/api/expense` | ค่าใช้จ่ายตามปีงบและอุปกรณ์ที่ไม่มีสัญญา |
| `/api/users` | จัดการผู้ใช้สำหรับ admin |
| `/api/devices/import`, `/api/print-transactions/import` | นำเข้าอุปกรณ์และยอดมิเตอร์สำหรับ admin |

Master Data ได้แก่ `/api/brands`, `/api/buildings`, `/api/floors`, `/api/divisions`, `/api/departments` และ `/api/fiscal-years` รายละเอียด endpoint และ payload ให้ตรวจ route/controller โดยตรง เพื่อไม่ให้เอกสารกลายเป็นสำเนาของโค้ด
