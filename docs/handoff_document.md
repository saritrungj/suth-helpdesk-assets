# 📢 Handoff Document: สรุปงานและโครงสร้างระบบล่าสุด (อัปเดตวันนี้)

เอกสารนี้จัดทำขึ้นเพื่อส่งมอบงาน (Handoff) ให้กับทีมงาน (โดยเฉพาะฝั่ง Backend และ Frontend) เพื่อให้ทุกคนเห็นภาพตรงกันว่า วันนี้เราได้ปรับปรุงโครงสร้างระบบและวางแผนการทำงานร่วมกันไว้อย่างไรบ้าง

---

## 1. 🔐 ระบบ Login (สำหรับงาน Prototype)
เพื่อความรวดเร็วในการนำเสนอ Prototype เราได้ทำระบบ Login แบบง่าย (Plaintext) ไว้ให้พร้อมใช้งานแล้ว:
- **Database:** สร้างตาราง `users` ให้แล้ว พร้อมข้อมูลแอดมินสำหรับเทส (`admin` / `admin123`)
- **API:** สร้าง API เส้น `POST /api/auth/login` ไว้แล้ว (อยู่ที่ `backend/routes/auth.js`)
- **Next Step (Frontend):** สามารถยิง API เส้นนี้เพื่อรับ Token และจำลองการล็อกอินเข้าใช้งาน Dashboard ได้ทันที

---

## 2. 🗄️ การปรับโครงสร้างฐานข้อมูล (Schema v3 Normalized)
เราได้ปรับปรุงไฟล์ `database/schema_v3_normalized.sql` เพื่อให้โครงสร้างข้อมูลเป็นระบบมาตรฐาน (ป้องกันปัญหาชื่อตึก/แผนกสะกดเพี้ยน) และรองรับฟีเจอร์ Compare ของผู้บริหาร:

- **เพิ่มปุ่ม เปิด/ปิด (Status):** ตาราง Master Data ทั้งหมด (เช่น `building`, `department`, `brand`) ถูกเพิ่มคอลัมน์ `status ENUM('active', 'inactive')` เพื่อให้ซ่อน/แสดงข้อมูลได้โดยไม่ต้องลบทิ้ง
- **Soft Delete สำหรับเครื่องปริ้น:** ตาราง `devices` เพิ่มคอลัมน์ `status` (active, repair, retired) เพื่อใช้ "แทงจำหน่าย" เครื่องพัง โดยที่ประวัติค่าใช้จ่ายในอดีตยังอยู่ครบถ้วน
- **ผูกความสัมพันธ์กันให้เป๊ะขึ้น:**
  - `floor` (ชั้น) ถูกบังคับให้ผูกกับ `building_id` (ตึก)
  - `department` (แผนก) ถูกบังคับให้ผูกกับ `division_id` (ฝ่าย)
- **อัปเดตสูตร Views:** ตัว Dashboard Views ถูกแก้ไขให้ดึงราคาจากตาราง `contracts` หรือ `price_override` มาคูณยอดกระดาษแบบสดๆ (Real-time) 

---

## 3. 🧪 ข้อมูลจำลองสำหรับทดสอบ (Dummy Data)
เพื่อให้ Frontend สามารถสร้าง Dashboard กราฟสวยๆ ไปนำเสนอได้ทันทีโดยไม่ต้องรอข้อมูลจริง เราได้สร้างไฟล์ **`database/seed_dummy_data.sql`** ไว้ให้แล้ว
- **วิธีใช้:** รันไฟล์นี้หลังจากรัน Schema หลัก ระบบจะสร้างตึก แผนกจำลอง และเครื่องปริ้นให้ 5 เครื่อง พร้อมยอดปริ้น 3 เดือนย้อนหลังให้ทันที

---

## 4. 📥 ข้อตกลงเรื่องการนำเข้าข้อมูล (ETL & Excel Import)
**ฝากถึงเอ็มเจและทีม Backend:**
เราตกลงกันแล้วว่า **"เราจะไม่แก้ไฟล์ Excel เดิม และจะไม่ Import CSV ผ่าน phpMyAdmin ตรงๆ"** เพราะจะทำให้เกิด Error (Foreign Key Fails) เนื่องจาก Database เราแยก ID ไว้หมดแล้ว

**Workflow การทำงานที่ตกลงกันไว้:**
1. ฝ่ายชีทส่งไฟล์ Excel (ภาษาไทย) มาเหมือนเดิม
2. เราได้เตรียมไฟล์ตัวอย่างจิ๋วไว้ให้เทสโค้ดชื่อ **`docs/mock_import_devices.csv`**
3. **Task ของ Backend:** ต้องเขียนโค้ด (Node.js) เพื่ออ่านไฟล์ CSV ตัวนี้ ➡️ ค้นหาว่าชื่อตึก/แผนกภาษาไทยตรงกับ ID เลขอะไรใน DB ➡️ แล้วค่อยรันคำสั่ง `INSERT INTO devices`

---

> **สิ่งที่ทุกคนต้องทำก่อนเริ่มงาน:**
> ฝั่ง Backend และคนทำ Database ให้รันคำสั่ง `git pull` เพื่อดึงโค้ดล่าสุดเข้าเครื่อง 
> จากนั้นเอ็กซ์พอร์ตไฟล์ `schema_v3_normalized.sql` และ `seed_dummy_data.sql` ไปรันในฐานข้อมูลเพื่ออัปเดตให้ตรงกันครับ!
